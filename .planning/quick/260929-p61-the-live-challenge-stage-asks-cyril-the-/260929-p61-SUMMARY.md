## Decisions Made

- Per-question prompting (every question printed first, verbatim and numbered, then one prompt per question in order) rather than one editor-style block — the binding of answer *n* to question *n* is structural: nothing to parse, nothing to mis-align.
- No-TTY is the primary path, not the edge case — the no-TTY transport had to genuinely work (write a sheet, log its path, poll for the answer), not merely fail politely, since the developer runs this gate backgrounded.
- An empty answer is a failure rather than a delegation, on purpose — a developer who genuinely wants to delegate a decision can *type* that delegation, and typing it makes it his answer; a blank line is the absence of one.
- A malformed handoff file keeps the transport polling; only the deadline fails, carrying the LAST parse defect seen — the developer is editing the file by hand while the run waits, and a half-saved file must not kill it.
- The arm guard is structural in two independent ways (`assertLiveArm`'s runtime argv refusal, plus a source scan proving the two I/O-performing offline arms hold zero call sites) rather than either alone — a comment promising the boundary is not the boundary.
- The wholly-generic-fallback gate was added even though the live arm can no longer reach `ANSWER_BANK` at all under this closure — it is a deliberate tripwire on the exact regression this closure prevents, which only fires if a future edit reconnects the two.
