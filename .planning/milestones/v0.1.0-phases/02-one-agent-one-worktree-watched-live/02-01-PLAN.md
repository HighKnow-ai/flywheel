<assumption_delta_decision>
The assumption-delta detector fired on a `pluralization` signal in this phase's scope: success
criterion 4 introduces a **second** session against the same worktree, where Phase 1's model had at
most one of anything per task.

- **Primary noun: `worktree`.** The worktree is promoted to the entity that owns the branch, the
  base ref and the on-disk path. A session is demoted to a detail of one run against that worktree.
- **Decision: `promote`.** The `worktrees` row is created once per task and reused by every
  subsequent run (`worktrees.task_id` is UNIQUE). Session identity is a *column* on `agent_runs`
  (`external_session_id`), not a peer table: D-30 makes every session exactly one `AgentRun`
  because native resume is deliberately unimplemented, so a separate `sessions` table would
  duplicate `agent_runs` row for row (RESEARCH.md Open Question 2; UI-SPEC Discretion #1 already
  renders them together as one run row). Adding a `sessions` table later, if `resumeSession` is
  ever implemented and one run can span several sessions, is purely additive — a new table with an
  `agent_run_id` FK, no rewrite of what exists.
- **Rationale:** the product thesis is "worktrees are durable, agent contexts are disposable".
  Modelling the worktree as the primary, session-independent noun is that thesis expressed in the
  schema rather than merely asserted in prose.
- **Invariant test (companion, built in Task 3):** `packages/core/tests/worktree_lifecycle.rs`
  asserts *a worktree survives the death of every session that ever ran against it* — it goes red
  the instant a future phase reintroduces the singular assumption by tying worktree lifetime to a
  run.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → Rust core | Untrusted-shaped input (task ids, permission mode strings) crosses the Tauri IPC seam; the renderer may never claim an actor. |
| Rust core → Node sidecar | The core hands the sidecar an absolute worktree path and a resolved credential environment over stdio; the sidecar is a driver with no authority of its own. |
| Node sidecar → `claude` process | The sidecar spawns a separate OS process whose file access is scoped to the worktree directory. |
| `claude` process → the worktree filesystem | Agent-written bytes land inside a throwaway branch in an isolated directory, never inside the main checkout. |
