    - `render_prompt(&packet, instruction)` appends the operator's free-text instruction under its own heading when the instruction is non-empty, and omits that heading entirely when it is empty or whitespace.
    - `render_prompt` for the same packet and instruction returns byte-identical output across calls.

  <action>
Create `packages/core/src/context_packet.rs` and register it in `packages/core/src/lib.rs`.

Define `ContextPacket` as a serializable struct with optional epic fields, the task fields, a
`Vec<CriterionEntry>` (text plus verification hint), and a `WorktreeFacts` struct carrying branch,
base ref and absolute path. Every field is data — no rendered sentence is stored on the struct, in
keeping with this crate's "derive at read time, never store" rule.

`assemble_context_packet(conn, task_id) -> anyhow::Result<ContextPacket>` reads through literal SQL
statements bound with named parameters, exactly as `query/events.rs` does — never assembled by
string interpolation. Order criteria by their existing rank column, then id, so the ordering is
total and reproducible. Resolve the worktree facts by calling `worktree_for_task` first and falling
back to the derivation functions only when no row exists; the packet must describe the worktree the
run will actually use.

This function makes **no model call and no network call of any kind**. It is a pure query over the
board, and that is the property Phase 4's determinism suite will be written against.

`render_prompt(packet, instruction) -> String` produces the initial prompt text with stable
headings and stable ordering. Omit a heading entirely rather than printing an empty section: no epic
means no epic heading, no criteria means no criteria heading, an empty instruction means no
instruction heading. Never emit a placeholder such as a bare dash for a missing field — an omitted
section is the honest representation and a placeholder would drift into the packet Phase 4 diffs.

Write `packages/core/tests/context_packet.rs` covering every case in `<behavior>`. The determinism
case is the load-bearing one: build a seeded project, call the function twice, and assert the two
packets are equal *and* that their rendered prompts are byte-identical. Add a third call after a
criterion reorder asserting the output changed, so the test proves determinism rather than merely
proving the function is constant.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → Rust core | The operator's free-text instruction and the chosen permission mode cross the IPC seam and end up in a spawned process's argument list. |
| board data → agent prompt | Task and epic text the user authored becomes the initial prompt of a process with filesystem access to a worktree. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-19 | Spoofing | renderer-supplied `permission_mode` reaching the backend verbatim | high | mitigate | `agent_run_start` validates the value against exactly four accepted strings before any sidecar request is sent, and persists the accepted value on the run row; an unrecognised mode is rejected with an error naming it. |
| T-02-20 | Denial of Service | an unbounded free-text instruction | medium | mitigate | The instruction is trimmed and rejected above 4000 characters with a message naming the limit and the actual length, matching the bound-checking shape `task_create` already uses for titles. |
| T-02-21 | Tampering | the sheet rendering a briefing that differs from the prompt actually sent | high | mitigate | The prompt is rendered once, in Rust, by `render_prompt`, and the preview DTO carries that exact string; a test asserts the previewed prompt equals the prompt recorded for the started run. The renderer never composes its own prompt. |
| T-02-22 | Information Disclosure | the packet surfacing content from another project's task | medium | mitigate | `assemble_context_packet` reads by task id and follows only that task's own project and epic foreign keys; every statement is a bound literal, so no interpolated identifier can widen the read. |
| T-02-23 | Elevation of Privilege | a run silently launched in a permissive mode the operator did not pick | high | mitigate | The default selection is `Accept Edits` (D-36), the four labels map one-to-one to adapter values with no relabeling, and the launched mode is persisted on the run row so the board can show what it actually ran with. |
</threat_model>
