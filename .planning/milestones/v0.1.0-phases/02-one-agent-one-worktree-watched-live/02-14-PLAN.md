<objective>
Close gap 4 of 4 (`02-VERIFICATION.md`, CR-02 in `02-REVIEW.md`): `main.rs`'s `RunEvent::Exit` handler
calls only `SidecarHandle::kill()`, which signals the sidecar's single process via
`tauri-plugin-shell`'s `CommandChild::kill()`. Every `claude` session is spawned `detached: true` in
`claude-code-adapter.ts` precisely so it becomes its own process-group leader, independent of the
sidecar's group — so killing the sidecar reaches none of them. Quitting Flywheel mid-run leaves a live
`claude` writing to the developer's worktree and spending API credit, with no supervisor left to
interrupt it. This contradicts the hard architectural constraint named in `.claude/CLAUDE.md`: killing
orphans "at the OS-process-tree level". `kill()`'s own doc comment asserts the opposite of the truth.

`As a … I want to … so that …` user-story format, so the MVP user-story enrichment is deliberately
NOT invented here. Run `/gsd mvp-phase 02` if the story framing is wanted on the roadmap entry.

Purpose: the orphan-on-quit failure mode is the one that costs the user real money while being
completely invisible. It is also the one constraint `CLAUDE.md` names by hand.
Output: a shutdown instruction the Rust core sends before it kills the sidecar, a sidecar that tears
down every live session's process group on that instruction and on two independent fallback signals, a
real multi-process test that proves a grandchild is gone, and a source-order gate on the exit handler.
