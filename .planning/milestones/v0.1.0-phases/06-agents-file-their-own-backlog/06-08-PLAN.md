<objective>
**As a** developer, **I want to** reach the proposal queue from the board and see proposals appear
while a run is still working, **so that** triage is one keystroke from where I already am and I am not
surprised by a queue that filled up while I was watching the wrong screen.

Everything the triage surface needs exists after plan 06-07; this plan makes it reachable. It also
answers the one remaining `06-CONTEXT.md` discretion item about the in-flight signal, which
`06-RESEARCH.md` Pitfall 6 already reduced to a one-line mount condition with a known blast radius.

Purpose: wire the surface into the application and give an execution run the same live tray an
authoring run already has.
Output: the `uiStore` trigger, the App-level mount, the lane's route, and the broadened tray
condition.
</objective>
