<objective>
**As a** developer who has just cloned Flywheel, **I want to** run one documented build command
and get a `Flywheel.app` that actually works, **so that** the application I install is the
application the repository describes.

This is the phase's tracer: the thinnest path through every layer the distribution work touches —
sidecar source → compiled `dist/` → a staged Node runtime → the `externalBin` launcher → the Tauri
bundle → a sidecar that answers from outside the source tree.

It exists because the current `externalBin` file is not a binary at all. It is a 3.8 kB bash dev
stub (`packages/desktop/src-tauri/binaries/flywheel-sidecar-aarch64-apple-darwin`, plan 02-01
deviation) that walks *up* the filesystem looking for `packages/sidecar/dist/index.js` and `exec
node`s it. An installed `.app` has no source tree above it, no guaranteed `node` on `PATH`, and no
`flywheel-shim` beside its executable — so today a shipped bundle cannot start a single agent run,
and criterion 3 ("builds a working desktop application") is false in the one way that matters.

Purpose: prove the packaging architecture end-to-end on one path before any CI, updater, signing or
register work is built on top of it.
Output: a generated launcher, a staged runtime, a packaged-sidecar test, and two bundle artifacts.
</objective>

<discretion_decisions>
CONTEXT.md § "Claude's Discretion" grants: "whether the sidecar's self-contained binary comes from
`pkg` or `nexe`". **Answer: neither — a staged Node runtime plus the compiled `dist/`, which is
STACK.md's own "Node.js (bundled sidecar runtime)" row.** Grounds, all read from the code:

- `packages/sidecar/src/claude-code-adapter.ts:272,278,288,300` write Claude Code hook commands as
  `${process.execPath} <absolute path to dist/*-hook.js>`. Under `pkg`/`nexe`/Node-SEA,
  `process.execPath` is the packaged binary (not a Node interpreter) and the hook `.js` files do
  not exist on the real filesystem a hook command is run through. The destructive gate, the scope
  gate and the stage gate all fail closed, which bricks every session.
- `claude-code-adapter.ts:96` and `:113-135` resolve five sibling modules via `import.meta.url`
  (`mcp-permission-server.js`, `pretooluse-hook.js`, `stage-gate-hook.js`, `scope-hook.js`,
  `sessionstart-hook.js`). A single-file binary has no siblings.
- The sidecar is ESM (`"type": "module"`, `module: NodeNext`) and `@modelcontextprotocol/sdk` is
  ESM-only; `pkg` (archived upstream) and `nexe` both want CJS.

D-192's substance is honoured exactly: the binary leaves the repository, enters `.gitignore`, and
the documented build produces the `<name>-<target-triple>` artifact `externalBin` expects.
**Reversibility: reversible** — the packaging step is one script; switching to a single-file
runtime later costs nothing already built.
</discretion_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| nodejs.org → build machine | A third-party runtime binary is fetched and then ships inside a signed application bundle. |
| bundle → OS process table | `Contents/MacOS/flywheel-sidecar` is an `exec`ing shell script resolving an interpreter and an entrypoint by relative path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Tampering | `stage-runtime.mjs` Node download | high | mitigate | Pinned `NODE_VERSION`; `SHASUMS256.txt` verification before extraction; refuse on mismatch, never fall through to an unverified tarball. |
| T-11-02 | Elevation of Privilege | `launcher.sh` path resolution | medium | mitigate | Packaged branch requires both `$SCRIPT_DIR/flywheel-node` executable AND `../Resources/sidecar/dist/index.js` readable before `exec`; no `PATH` lookup for the interpreter in the packaged branch; loud `exit 127` rather than a fallthrough. |
| T-11-03 | Information Disclosure | staged `resources/sidecar/` tree | low | mitigate | Staged via `npm ci --omit=dev` into a clean prefix, so no dev dependency, `.env`, cache or local config is copied into a public bundle. |
| T-11-SC | Tampering | npm/cargo installs | high | accept | This plan adds **no** package-manager dependency: the Node runtime is a checksum-verified first-party download and the shim is an existing workspace member. The package-legitimacy gate applies to plan 11-05 (`tauri-plugin-updater`), which carries the blocking checkpoint. |
</threat_model>
