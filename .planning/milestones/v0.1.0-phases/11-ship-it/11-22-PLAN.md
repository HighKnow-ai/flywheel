<objective>
Two findings from plan 11-17's finish review that the owner decided on 2026-10-13 should not wait for
plan 11-21's redemption pass, because neither is a matter of taste.

**three-3** is an accessibility defect with a remedy already written down. `review.css` says in its
own comment that a change is carried by "the row tint and the +/- gutter", and no sign is drawn - so
added and removed rows differ by colour alone. That fails WCAG 1.4.1. Plan 11-21's protocol
automates what is automatable and surfaces the rest to the owner; sending an accessibility bug
there risks ratifying it instead of fixing it.

**four-1** is the Core Value failing in the one place a user would look for it. `SessionSurface.tsx`
is handed a `taskId` and nothing else - no read returns a task by id, so the header says `Session`
and never names the board item the run belongs to. The remedy is a new core read, which is work
rather than a decision.

The other seven high-severity findings from the same review remain routed to D-196 filing at plan
11-21, where an owner looking at a running build is the right judge. This plan does not touch them.

Purpose: close three-3 and four-1.
Output: a sign column in the diff gutter, and a session header that names its task.
</objective>

    `capabilities/default.json`, and add the typed wrapper to `adapters/tauri.ts`. The adapter seam

    `invoke` directly, so a future web surface can swap transport in one file.

      to `Session`. A missing read must not blank the header or throw - a live run still needs its
      surface.

    key and title for a seeded task and `None` for an unknown id. The surface test asserts all three
    cases above, including the deleted-task fallback.

    Do not widen `list_tasks_for_epic` or reuse a board list read to do this. Pulling a project's
    rows to name one task is the thing the finish-review row calls out.
