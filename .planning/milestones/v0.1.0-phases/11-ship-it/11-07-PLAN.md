  <name>Task 1: The Apple Developer account, the certificate, and the six secrets</name>
  <action>Enrol in the Apple Developer Program, create a Developer ID Application certificate and an App Store Connect API key, and store six repository secrets. Every step here is one only you can perform; nothing else in the phase is blocked by it.</action>
  <instructions>
Everything in this task is something only you can do. Nothing in this plan can be verified until it
is done, and nothing else in the phase is blocked by it.

1. **Enrol in the Apple Developer Program** ($99/yr, `developer.apple.com/programs`). A free Apple
   account cannot notarize — that is the whole reason this is a purchase and not a configuration.
   Enrolment is not instant; it can take a day or more for identity verification.
2. **Create a Developer ID Application certificate** (Certificates, Identifiers & Profiles →
   Certificates → `+` → Developer ID Application). Download it, add it to your login keychain, then
   export it **with its private key** as a `.p12` with a password.
   Confirm with `security find-identity -v -p codesigning` — it must now list one
   `Developer ID Application: … (TEAMID)` identity. Record the identity string exactly as printed,
   including the team id in parentheses; Task 2 writes it into the build config.
3. **Create an App Store Connect API key** for notarization (App Store Connect → Users and Access →
   Integrations → App Store Connect API → Team Keys → `+`, with the Developer role). Download the
   `.p8` **once** — Apple does not let you download it again. Record the Key ID and the Issuer ID.
4. **Store five repository secrets** with `gh secret set`:
   - `APPLE_CERTIFICATE` — the `.p12`, base64-encoded (`base64 -i cert.p12 | pbcopy`)
   - `APPLE_CERTIFICATE_PASSWORD` — the `.p12` export password
   - `APPLE_SIGNING_IDENTITY` — the identity string from step 2
   - `APPLE_API_ISSUER` — the Issuer ID (a UUID)
   - `APPLE_API_KEY` — the Key ID, **and** `APPLE_API_KEY_PATH` content: store the `.p8` body
     base64-encoded as `APPLE_API_KEY_P8` so the workflow can write it to a temp file at build time.

Then answer with: the signing identity string, the team id, and confirmation that all six secrets
are set. Back up the `.p12` and the `.p8` off this machine — like the updater key, these are
one-download artifacts.

Never paste a certificate, a password, a `.p8` body or the base64 of any of them into a plan, a
SUMMARY, a commit message or a CI log.
  </instructions>
  <verification>`security find-identity -v -p codesigning` lists a `Developer ID Application` identity; `gh secret list` shows all six `APPLE_*` names; a tag-triggered release then produces a bundle whose `codesign -dv` Authority line names that identity.</verification>
  <resume-signal>Reply with the signing identity string, the team id, and "secrets set" once all six exist. If enrolment is still pending, reply "pending" — this plan waits and the rest of the phase does not.</resume-signal>

<task type="auto">
  <name>Task 3: Prove Gatekeeper is silent, against the downloaded artifact</name>
  <files>scripts/release/verify-gatekeeper.sh</files>
  <read_first>
    - .github/workflows/release.yml (Task 2 — the artifact names the script fetches)
    - packages/desktop/src-tauri/tauri.conf.json (`bundle.externalBin`'s three entries — each is a nested Mach-O the hardened runtime checks independently)

  </read_first>
  <action>
Write `scripts/release/verify-gatekeeper.sh`, taking a tag as `$1`. It must operate on the
**downloaded release artifact**, never on a local build — a locally built bundle is signed by the
local keychain and proves nothing about what users get.

Steps:
1. `gh release download "$1" --pattern '*.dmg' --dir "$tmp"`.
2. `spctl --assess --type open --context context:primary-signature -vvv` on the `.dmg`. The expected
   output contains `accepted` and `source=Notarized Developer ID`. Anything else fails.
3. `hdiutil attach` the `.dmg`, then on the mounted `Flywheel.app`:
   - `codesign --verify --deep --strict --verbose=2` (no output and exit 0 is the pass).
   - `codesign -dv --verbose=4` and require an Authority line containing
     `Developer ID Application`.
   - `spctl --assess --type execute -vvv` and require `accepted`.
   - `xcrun stapler validate` and require a stapled ticket — notarization that is not stapled means
     a first launch without network access shows the warning criterion 1 forbids.
4. Assert each of the three nested executables under `Contents/MacOS/` (`flywheel-sidecar`,
   `flywheel-node`, `flywheel-shim`) passes `codesign --verify`, and run the packaged-sidecar `ping`
   probe from plan 11-01 against the **mounted, signed** bundle copied to a temp directory. The
   hardened runtime is the most likely thing to break a shell-script `externalBin` that `exec`s a
   sibling binary, and that failure would otherwise surface as "agents do not start" on a user's
   machine.
5. `hdiutil detach` and clean up, including on failure (`trap`).

Print one line per check with its verdict and exit non-zero on the first failure. Then run it
against the real release produced by plan 11-08 and record the full output in that plan's evidence
file; if the account from Task 1 is not yet active, this task's verification is the one thing in the
phase allowed to wait.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → Apple code-signing identity | A CI job holds the private key that vouches for every Flywheel binary. |
| hardened runtime → nested executables | Three `externalBin` Mach-O files and a staged JS tree must survive signing and run under the runtime's restrictions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-20 | Spoofing | Developer ID certificate in CI | critical | mitigate | Secrets only, scoped to the tag-triggered workflow; `ci.yml` and pull-request runs reference no `APPLE_` variable, so a fork PR can never request a signature; no `set -x` and no step echoing the decoded `.p8`. |
| T-11-21 | Tampering | unsigned release passing as signed | high | mitigate | The job fails unless `codesign -dv` reports a `Developer ID Application` Authority, and `verify-gatekeeper.sh` re-asserts it plus a stapled ticket against the *downloaded* artifact, not the build directory. |
| T-11-22 | Denial of Service | hardened runtime breaking the sidecar launcher | high | mitigate | Task 3 reruns plan 11-01's packaged `ping` probe against the signed, mounted bundle, so a signature that breaks `exec` of a sibling binary is found in CI rather than by a user whose agents silently never start. |
| T-11-23 | Information Disclosure | `APPLE_SIGNING_IDENTITY` team id in a public config | low | mitigate | The identity comes from the environment rather than being written into the public `tauri.conf.json`. |
</threat_model>
