- `rm -rf packages/relay-client`
- Remove the member from the workspace: a `sed` deleting the line matching `packages/relay-client`
  from the root `Cargo.toml` `members` list, followed by an assertion that the line is gone and that
  `Cargo.toml` still parses (`cargo metadata --no-deps --format-version 1` must exit 0). Note that
  `packages/sidecar` is **not** a Cargo member, so this edit must leave the sidecar steps untouched.

Then add the structural half the deletion alone does not catch — a grep gate that fails the job if
any non-planning source file references the crate: search `packages/`, `src-tauri/`, `scripts/` and
the root manifests for `relay_client` or `relay-client`, excluding `packages/relay-client/` itself,
`.planning/`, `target/`, `node_modules/` and this workflow file. Zero matches is the pass condition,
and the grep must exclude comment-only lines from its count so a comment explaining the gate cannot
invalidate it.

This is the same move as Phase 6's canonical-writer gate and Phase 12's install-at-every-mutation
invariant: prove a boundary with a check that fails the build, not with a convention. Its value is
not that it passes today — `packages/relay-client/Cargo.toml` has no dependencies and nothing
depends on it — but that it keeps passing as features land.

Do not use a Cargo feature flag or an `optional = true` dependency to simulate absence: a
feature-gated member is still in the tree, and DIST-04's wording is "with the relay entirely
absent".

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party GitHub Actions → CI runner with repository write scope | Each `uses:` step runs arbitrary code with the workflow's token. |
| future feature code → the open-core seam | A dependency added to `packages/relay-client` would silently couple the OSS app to the commercial layer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-07 | Tampering | `uses:` actions in both workflows | medium | mitigate | Only first-party (`actions/*`) and two widely-audited Rust actions (`dtolnay/rust-toolchain`, `Swatinem/rust-cache`); no `permissions: write-all`; these workflows declare no secrets at all, so a compromised action cannot exfiltrate signing material (that lives only in 11-04/11-07's release workflow). |
| T-11-08 | Tampering | open-core boundary | high | mitigate | `open-core.yml` deletes the crate and runs the full suite, plus a non-comment grep gate for `relay_client` references outside the crate. Fails the build rather than warning. |
| T-11-09 | Denial of Service | `build:dist` network fetch in CI | low | accept | A nodejs.org outage fails CI; the runtime cache and the pinned version limit the window, and a red CI on an upstream outage is the correct, visible outcome. |
</threat_model>
