<objective>
Make the rack answer instantly on a real project: free-text search across titles and bodies, filters
on every dimension the row anatomy shows, and a bounded indexed window that keeps the interaction
imperceptible at 1,000 items and beyond.

Purpose: `BOARD-08` is named in the ROADMAP as a design constraint on the first board build, not a
later optimisation — and `BOARD-06` and `BOARD-08` only compose if the query is indexed and the
renderer holds nothing but the current window. The trust property underneath both is D-03: there is
exactly one definition of a result set, and it lives in the core.

Output: search and filter that run as SQL, a virtualized window that does not care how many rows
exist, and a latency assertion that fails when either regresses.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-typed search term → FTS5 match expression | The highest-risk untrusted string in the phase: it reaches a query parser, not only a value slot |
| renderer filter set → SQL WHERE clause | A structured filter chosen in the UI becomes SQL |
| result window size → renderer memory | How much the core is willing to return in one call |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | the FTS5 match expression in `query/search.rs` | high | mitigate | The term is a bound parameter and is wrapped so FTS5 treats it as a literal phrase rather than query syntax; a grep gate fails the build if any query in `packages/core/src/query` is assembled by string formatting; the punctuation cases are asserted in `search_filter.rs` |
| T-01-23 | Tampering | `BoardFilter` translation in `query/filter.rs` | high | mitigate | The filter is a typed struct whose variants map to fixed parameterised fragments; no renderer-supplied string ever becomes a column name, an operator or an ORDER BY clause |
| T-01-24 | Denial of Service | unbounded result window | medium | mitigate | The core caps the window at its default limit and the command layer caps the requested limit before calling the core, so no single call can be made to return the whole board |
| T-01-14 | Tampering | FTS5 index drift | medium | mitigate | The three sync triggers from migration 0002 are the only mechanism; `title_edit_updates_what_search_matches` asserts they fire, and the module doc comment records that any future bulk write path must rebuild the index |
| T-01-02 | Elevation of Privilege | `capabilities/default.json` | high | mitigate | `board_search` is named explicitly; no blanket grant |
</threat_model>
