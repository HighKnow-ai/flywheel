<objective>
Turn the event log into two things a user and a future relay can each read: a chronological,
actor-attributed activity trail on every item, and an ordered stream any consumer can resume from a
cursor without a gap and without a duplicate.

Purpose: `BOARD-09` and `DATA-05` are the same table read two ways, which is exactly why D-19 refuses
a second denormalised history — one source cannot disagree with itself. The consequence D-19 names is
that event payloads had to be human-renderable from day one, and this plan is where that decision
either pays off or is exposed.

Output: a trail that reads like a person wrote it, and the cursor contract Phase 2's relay seam and
the phase's replay criterion both rest on.
</objective>

    Write `packages/core/src/query/events.rs` exposing `EventCursor { project_id, origin, sequence }`,
    `activity_trail(conn, parent_kind, parent_id, limit, offset)` and

    `activity_trail` is one indexed query against the denormalised `task_id` or `epic_id` column,
    ordered ascending by `id` — the id is a ULID and is therefore chronological by construction, so no
    separate timestamp sort is needed. Criterion events already carry their parent's id in that
    column, so a task's trail includes its criteria changes without a second query or a union.

    `events_since_cursor` runs `WHERE project_id = ?1 AND origin = ?2 AND sequence > ?3 ORDER BY

    row at all, and it can never deliver a row twice provided the consumer stores the batch's maximum
    sequence as its next cursor. That is the whole of `DATA-05`, and it is also the entire integration
    surface a relay would need later: no new table, no change-data-capture tooling, no schema change.

    per-origin keying is for. To present a merged timeline across origins, sort the fetched rows by

| Boundary | Description |

## Flagged assumption

**DATA-05 — unclassified edge.** The deterministic edge probe could not derive an edge category from
"readable as an ordered, resumable stream from any point via a cursor", so the row stays `unresolved`
and is surfaced here rather than auto-resolved. This plan's reading, which the executor should confirm
rather than assume: *resumable* is exact per `(project, origin)` — a consumer storing each batch's
maximum sequence can never gap or double-read — while *ordered across origins* is approximate, using
the ULID's embedded clock rather than a causal scheme such as vector clocks or Lamport timestamps.
`01-RESEARCH.md` records this as assumption A2 at medium risk: it is sufficient for a human-facing
activity trail, and if the relay milestone later needs strict causal ordering across concurrent edits
on two machines, that is a change to the merge step and not to this schema. Nothing in this phase
produces a second origin, so the property is proved by a test that writes one rather than by
observation.
