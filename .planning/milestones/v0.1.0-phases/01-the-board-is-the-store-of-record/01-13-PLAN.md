<objective>
Give `useGlobalBindings` the layer awareness the Escape ladder already has, so a global shortcut can
never open a surface the user cannot then type into.

Purpose: G-01-FOCUS diagnosed a single root cause behind five separate misfocus symptoms —
`useGlobalBindings` is a bare `window` keydown listener with no idea which layer is on top. The board
list already stands down correctly and `nextEscapeLayer` already models the stack, but that model is
consulted only for Escape. Radix's `FocusScope trapped` on the detail panel can trap Tab movement but
cannot stop a window listener from opening a surface outside the scope, so a shortcut opens something
and Radix immediately yanks focus back. The fix is one central guard, not five per-consumer guards —
which is also what `state/keyboard.ts`'s own module doc already demands ("no other component
hand-rolls its own key check").

Output: the full layer stack in one store, a pure layer model beside the Escape ladder that both the
window listener and the board-list container read, and regression tests that hold every instance the
UAT named.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| window keydown → global action | any keydown reaching `window`, real or synthesized by `dispatchAction`, can request a global action |
| trapped overlay → surfaces outside it | a focus-trapped layer must not be able to have a surface opened behind or beside it that it then steals focus from |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-GC-07 | Elevation of Privilege | a global keystroke acting on a surface behind a trapped layer | medium | mitigate | `bindingAllowedInLayer` drops every binding not owned by the topmost layer, decided in one place inside `useGlobalBindings`; the board-list container reads the same function, so no consumer can opt itself back in by forgetting a guard |
| T-01-GC-08 | Tampering | a project switch under an open detail panel | medium | mitigate | ⌘1-⌘9 is refused outside the board and quick-add layers, so the panel can no longer be left rendering `detailItemId` against another project's item window; the palette's "Go to Project" closes the panel first through `returnToBoardLayer` |
| T-01-GC-09 | Elevation of Privilege | the native folder dialog opened from behind a trapped scope (⌘⇧O) | medium | mitigate | Refused outside the board and quick-add layers; the menu-bar route returns the app to the board layer before dispatching, so the dialog is never raised behind a trap |
| T-01-GC-10 | Tampering | a synthetic keydown dispatched by page script reaching a global action | low | accept | `dispatchAction` is renderer-internal and the window loads only bundled first-party code — a synthesized keydown carries exactly the authority a real one does, and every action it reaches is already reachable from the user's keyboard. Revisit if agent-authored content is ever rendered inside this window |
| T-01-GC-11 | Denial of Service | the user stranded by a layer that refuses every shortcut | medium | mitigate | `open-palette` is exempt from the layer gate in every layer except "picker" and "palette", so ⌘K always reaches the discoverable command surface BOARD-07 rests on, and Escape's existing ladder still closes exactly one layer per press |
| T-01-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no package — no line is added to `package.json` or any `Cargo.toml`, so the package-legitimacy gate has nothing to audit |
</threat_model>
