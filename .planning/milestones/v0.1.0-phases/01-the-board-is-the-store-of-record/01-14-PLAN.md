<objective>
Make a task's epic assignable from the running board: one keystroke on a selected task opens a picker
of the project's epics, and choosing one puts the task under it — visible immediately in the row's
epic pill, reversible from the same picker, and reachable from the command palette under a printed
label.

Purpose: plan 01-12 built the reparenting command; nothing calls it yet. G-01-EPIC-ASSIGN's third
cause is that no affordance exists at all, and it named the obstacle precisely — `s`, `p`, `e` and `a`
are already taken by status, priority, estimate and assignee, so the epic picker needs a deliberate
binding rather than a reflexive first letter. This plan makes that choice, records it in the Keyboard
Map so the contract stops lying, and builds the picker as a generic one that plan 01-15 reuses for
issue parents instead of duplicating.

Output: a reusable `ParentPicker`, the `m` binding and its `open-epic-picker` action, the two query
hooks, and the tests that hold them.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| picker option list → command argument | the epic id sent to `task_set_epic` originates from a rendered option list, not from a validated source |
| renderer → Tauri command surface | `task_set_epic` is callable with any `taskId`/`epicId` pair regardless of what the picker offered |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-GC-12 | Tampering | an epic id from another project reaching `task_set_epic` | high | mitigate | The picker derives its options from the current project's loaded board window only, but the authority is plan 01-12's server-side `assert_parent_in_project`, which rejects a cross-project parent inside the transaction — the picker is a convenience, never the boundary |
| T-01-GC-13 | Tampering | an epic being parented under another epic | medium | mitigate | The keystroke is refused on an epic row, the palette command is disabled there, and the option list excludes the picked row itself; the command surface has no epic-parent field at all, so the three-level hierarchy is unrepresentable rather than merely unoffered |
| T-01-GC-14 | Information Disclosure | option labels in the picker | low | accept | Each label is the epic's own key and title, already rendered on the board row beside it |
| T-01-GC-15 | Elevation of Privilege | the new picker as an unmodelled focus layer | medium | mitigate | `PickerKind` gains a member rather than the picker getting its own state, so `topLayer`'s `pickerOpen` derivation covers it with no change and plan 01-13's global-binding guard applies to it on the first render |
| T-01-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no package — no line is added to `package.json` or any `Cargo.toml`, so the package-legitimacy gate has nothing to audit |
</threat_model>
