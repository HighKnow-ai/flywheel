<objective>
**As a** developer watching a session close, **I want to** see the agent's own summary land on the
board within the same second it says it wrote one, **so that** the next briefing is built from what the
agent actually said rather than from what the core could infer.

Plan 04-03 built the agent-facing write surface; plan 04-02 built the fallback. This plan closes the
loop: the `summary_reported` event travels the existing sidecar reader loop, a database-only domain
function writes the row in one transaction with its event, and the prompt the next session receives
tells it — by the exact tool name — to record its own closing summary and to echo back the decision ids
it is working under.

Purpose: make the agent-authored path the common case and `auto_generated` the exception, which is what
D-66 says has to be true before discard-mid-task is worth measuring the thesis against.

Output: `apply_summary_reported`, the reader-loop branch, and two new `render_prompt` sections.

**Architectural constraint carried forward.** `assemble_context_packet` stays a pure query. Both new
render sections are computed from data already in the packet — the accumulated decision list is derived
from the summaries the packet already holds, and the closing instruction is a constant string. No git
call, no network call and no write enters this file, and its header contract stays literally true.
</objective>
