<objective>
**As a** developer whose agent has gone down a wrong path, **I want to** throw away its whole context in
one action and land on a fresh session against the same worktree, **so that** `/clear` costs me nothing.

This is the phase's flagship action and the sentence the product thesis rests on. D-66 fixes the shape:
ask for the summary first, wait a bounded time, then fall through to D-35's interrupt-then-force exactly
as Stop already does — so the agent-authored summary lands in the common case and `auto_generated` stays
the exception. Taking the weakest summary on the path the thesis is being falsified against would be
measuring the wrong thing. D-67 fixes where it lands: D-27's launch sheet, pre-filled with the freshly
assembled packet — summaries, compaction boundary, diff-so-far, any drift warnings — with Enter to start.

Purpose: CTX-08, and the user-visible half of everything the previous twelve plans built.

**Planner call, resolving what "ask for the summary first" can actually mean here.** The backend runs
headless (`claude -p`), so there is no channel to inject an extra user turn into a live session — the
"ask" therefore lives where it already is: every briefing's Closing Requirement section (plan 04-06)
tells the agent, by exact tool name, to record its summary as its final turn. Discard's contribution is
the **bounded wait**: it gives that turn time to land before the interrupt. This is the honest reading of
D-66 against the adapter this product actually has; do not implement an injected turn, and do not claim
one in the code comments.

**Planner call, resolving D-66's open timing item.** `DISCARD_SUMMARY_WAIT_MS` is **8000** — longer than
`STOP_GRACE_MS` (5000, the SIGINT-to-SIGTERM window in `claude-code-adapter.ts`), because this window is
waiting for a model to finish a tool call rather than for a process to notice a signal, and shorter than
twice it, because discard has to keep feeling like one action. The two windows are sequential, so the
worst case before the force step is 13 seconds. Declare the constant beside the command with that
arithmetic written down.
</objective>

Add `agent_run_discard` to `packages/desktop/src-tauri/src/commands/agent_run.rs` as a thin wrapper

Declare `pub const DISCARD_SUMMARY_WAIT_MS: u64 = 8_000;` beside the command, with a doc comment
recording the arithmetic from this plan's objective: longer than the sidecar's `STOP_GRACE_MS` because
this window waits for a model to finish a tool call rather than for a process to notice a signal;
shorter than twice it because discard has to keep feeling like one action; the two windows are
sequential, so the worst case before the force step is thirteen seconds.

`agent_run_discard(state, app, agent_run_id) -> Result<AgentRunStopDto, String>`:

1. Poll for a summary: check `latest_summary_for_run` at a modest interval (200ms is fine) until it
   returns `Some`, until the run's status reads terminal, or until `DISCARD_SUMMARY_WAIT_MS` elapses —
   whichever comes first. **Take and release the database lock per poll**; never hold it across the
   whole wait. `agent_run_stop`'s own CR-01 comment states the reason in this exact file: holding the
   one `Mutex<Connection>` across a multi-second wait freezes every other board read in the app. The
   same reasoning applies here with more force, because this window is longer.
2. Then perform exactly what `agent_run_stop` performs, by calling the same helper it calls rather than
   by restating its body: resolve the interrupt outcome before taking the lock, then
   `stop_agent_run_recording_first`, then the `board:changed` emit. If the two commands cannot share a
   body without a signature change, factor the shared tail into a private function and have both call
   it — one termination path, two entry points, the shape this phase has used for every other shared
   write.
3. Return the same DTO `agent_run_stop` returns, so the renderer's existing handling applies unchanged.

The wait must never be the reason a discard fails: a poll error is logged and treated as "no summary
yet", and the fall-through happens regardless. A hung agent must never sit between the developer and a
fresh session — that is the friction D-46 reserves for money burning.

Create `packages/core/tests/discard_lifecycle.rs` covering the six behaviours above at the level the

already-terminal case. Where a behaviour needs a live sidecar, assert the database-visible half and note

| a hung agent → the developer's next action | An unresponsive model must not be able to hold the developer's workflow open indefinitely. |
