<objective>
**As a** developer sharpening a criterion three hours into a run, **I want to** type the edit and have it
land, **so that** the board stays honest — while the agent that is already working keeps being judged
against what it was actually told.

Plan 04-04 built the revision write path. This plan gives it surfaces and closes the non-repudiation
half. D-79 puts superseded wording behind a quiet expand affordance visible to the developer and to
nobody else — because the whole point of criteria being structured and immutable is that no session ever
reads a version that is no longer true. D-78 pins the revision set each run's packet carried onto the
`agent_runs` row, so a completed run's briefing stays reproducible and an agent is never marked as
having missed a criterion it was never given.

Purpose: finish BOARD-03 end to end, and supply the third drift detector's input (plan 04-11 compares a
run's pin against the current revision set).

Output: two Tauri commands, the revised marker, and the run-level pin with its tests.
</objective>
