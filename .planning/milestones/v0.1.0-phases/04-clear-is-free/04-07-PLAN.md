<objective>
**As a** developer who discards a context mid-edit, **I want to** have the next session handed the real
state of the working tree, **so that** it does not rediscover or clobber changes it cannot see.

D-70 is a deliberate departure from `ARCHITECTURE.md` section 3, which specifies only the committed
range. That is insufficient here: D-35 guarantees a dirty, uncommitted tree after every interrupt, and
D-66/D-67 make discard-mid-edit the flagship path — so a committed-only packet hands the new session a
tree full of changes it cannot see. D-71 fixes what travels: the stat block and the changed-path list,
never hunk bodies, plus one line telling the agent to read what it needs. The agent is standing in the
worktree; a file list and an invitation is strictly more information per token than a wall of hunks,
and the packet's size then depends only on how many files changed — bounded, deterministic, and
diffable across five cycles.

Purpose: make the packet's claim to be ground truth actually true, without breaking the purity contract
`context_packet.rs`'s own header states.

**The seam, resolved deliberately rather than by accident (04-RESEARCH.md Pitfall 2, assumption A3).**
`assemble_context_packet` keeps its stated contract literally — no git call, no write of any kind. The
git read happens in the **command layer** (`agent_run_preview` / `agent_run_start`), which then calls a
thin `assemble_context_packet_with_extras` wrapper to attach it. The obvious-looking edit — adding a
`git_at` call inside the assembler — would couple a fast board-only preview to a subprocess spawn and
break a property that already has tests. Do not make it.

**What this means for CTX-04.** Determinism is a property of board state: `assemble_context_packet`
returns byte-identical packets for an unchanged database, and `assemble_context_packet_with_extras`
returns byte-identical packets for the same database *and* the same extras. A worktree edited between
two calls legitimately changes the diff section — that is the diff being ground truth, not a
determinism failure. State this in the wrapper's doc comment so a later reader does not mistake one for
the other.
</objective>
