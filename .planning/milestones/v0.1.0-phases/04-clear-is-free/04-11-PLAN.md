<objective>
**As a** developer whose agent just told me something the board contradicts, **I want to** be told now,
**so that** I do not discover it later in the diff.

D-72 fixes what a detector may be: three fact-based comparisons, no model judgement anywhere. D-73 adds
the fourth — the decision-id read-back that gives criterion 4's *stated understanding* something real to
check, while staying pure id matching and never semantics. D-75 fixes where the result lives: the warning
line is re-derived on every assembly and never stored, because a stored verdict goes stale the moment the
range it was computed against changes.

Purpose: build the detectors and put their output in front of the agent. The board-visible signal, the
activity-trail event and the project-rail count are plan 04-12.

**The test that decides whether an implementation belongs to this decision:** if it needs a model to
decide whether two sentences disagree, it has left D-73. Every comparison here is over identifiers, file
paths or refs.

**Planner call, resolving CONTEXT.md's open item on renamed files.** The real changed-path list is read
**without rename detection**, so a moved file appears as both its old and its new path. An agent that
honestly claims either side then matches, and the detector does not cry wolf on a legitimate move — which
matters because a detector guarding the product's central claim has to be one that cannot be argued with.
The alternative, teaching the detector about renames, would make it a heuristic rather than a fact.
</objective>

Detector rules, precisely:
- **Claimed files** compares the *latest* summary's `changed_files` against `real_changed_paths`.
  `None` means there is no worktree to compare against, and nothing fires. A claimed path absent from

  every run that touched a lockfile.
- **Staleness** fires when the latest summary's `diff_ref` is `Some` and differs from `head_ref`, or

  exactly what makes that summary's claims incomplete rather than wrong.
- **Criteria revision** returns immediately when `pinned_criterion_ids` is `None`. Otherwise it compares

  that entered or left.

  because compaction is lossless for decisions), then compares it against the latest summary's
  `acknowledged_decisions`. An on-record id never echoed fires `UnacknowledgedDecision`; an echoed id
  matching no record fires `FabricatedDecisionEcho`. Both are id matching, never text comparison.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent's claimed file list → board fact | A model-authored claim is compared against git's own answer; the comparison must be the authority, not the claim. |
| agent's echoed decision ids → board record | Ids a model emits are checked against ids the board holds; a fabricated id must be visible rather than absorbed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-02 | Tampering | an agent's claimed changed-file list | high | mitigate | The claimed-files detector compares the claim against git's own path list and surfaces every unmatched claim; the claim is never trusted on its own. |
| T-04-28 | Tampering | fabricated decision echoes | high | mitigate | An echoed id matching no recorded decision fires its own warning kind, so a session cannot manufacture the appearance of having acknowledged something. |
| T-04-29 | Repudiation | stale drift verdicts | medium | mitigate | Nothing is stored; a workspace-wide migration gate fails the build if a drift verdict is ever given a column, so a warning cannot outlive the fact behind it. |
| T-04-30 | Denial of service | a detector that cries wolf | medium | mitigate | Under-reporting does not fire, a null pin never fires, and the real path list is read without rename detection so a legitimate move does not fire — each of these has a named non-fire test. |
| T-04-31 | Elevation of privilege | drift as a blocking gate | low | accept | Drift blocks nothing, by D-46 and D-74. The risk accepted is that a developer ignores a warning; the mitigation is the board-visible signal plan 04-12 adds, not a modal. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable — this plan installs no package. Any newly surfaced dependency need routes back through the legitimacy gate. |
</threat_model>
