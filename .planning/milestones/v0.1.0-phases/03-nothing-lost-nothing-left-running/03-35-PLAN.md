<objective>
Close the round-eight destructive-gate bypass: `env` and `command` wrapper-token recognition is
exact-token-equality at every site that feeds a security decision, so any word-formation mechanism
that produces the token without producing the literal string — brace expansion (`{env,}`), a path
prefix (`/usr/bin/env`) — walks straight past it, and the hook returns "no opinion" for a payload
whose unobfuscated twin denies.

**MVP user story (from ROADMAP Phase 3's `**Goal:**` line and Success Criterion 5):** **As** a
developer running an agent in auto-accept permission mode, **I want to** still be stopped and asked
before a force-push, a branch deletion or a recursive delete, **so that** I can leave the loop
unattended without wondering whether it quietly destroyed something.

Purpose: `03-VERIFICATION.md` (round eight, `gaps_found`, 4/5) leaves exactly one truth open, and
its first `missing:` item is the defect itself — "a fix giving `env` and `command` the same raw-text,
character-level, word-boundary substring-scan companion `git`/`rm` and the six `KEYWORD_TRIGGERS`
already have." Its second `missing:` item is that fix's documentation precondition, which the
trust-boundary document's own rule for round six puts FIRST. This plan carries both, one shape at a
time, and each shape is proven through the real compiled hook rather than the classifier alone.

Output: a `C6` clause in the trust boundary that states exactly what wrapper-token recognition now
proves and what it still cannot see; `raw_text_names_path_defeating_wrapper` in the shim, promoted
from C5's token equality to word-boundary containment and widened to `command`; and a Rust test per
shape, each asserted against its own unobfuscated control so a regression reads as a divergence from
the control rather than as an absolute nobody can check.
</objective>

### Assumption-delta decision

<assumption_delta_decision>
**Detector result assessed, not accepted.** The three `pluralization` signals the detector fired on
(`second` in "sixty-second answer", `also` as an adverb, `multiple` in "multiple git versions") are
lexical hits on ordinary prose. None is a singular→plural transition in this phase's identity model.
Were those the only signals, the correct answer would be `no-change`.

**The real transition, found by inspection rather than by the detector:** the noun that is now plural
is **the wrapper-token recognition mechanism**. Two mechanisms coexist in `main.rs` today —
exact-token-equality (three call sites: `resolve_segment_program_index`,
`text_can_shadow_path_resolution`'s own `env`/`command` token walk, and C5's
`raw_text_names_opaque_env_reparse`) and character-level word-boundary scanning (`raw_text_contains_word`,
which backs `text_names_gated_program` for `git`/`rm` and `raw_text_can_shadow_path_resolution` for
the six `KEYWORD_TRIGGERS`). `env` and `command` were recognised only by the former. Rounds five
through eight are the cost of having added a mechanism alongside rather than promoting one: each
round closed the spelling someone happened to test.

**Noun now primary:** *word-boundary containment of a wrapper token* — `token_names_word`.

**Decision: `promote`.** C6 promotes character-level word-boundary containment to the primary — and,
for the security decision, the ONLY — recognition mechanism for wrapper tokens. Exact token equality
is demoted to the boundary-contained special case where the token is exactly the name, and survives
in the code only where it answers a NON-security question: which token in a segment is the program
whose category to report (`resolve_segment_program_index`). Concretely: `raw_text_names_opaque_env_reparse`
(C5) is replaced, not supplemented, and the document records C5 as superseded by C6 rather than as a
peer clause.

**Why promote rather than add alongside, measured:** promoting `resolve_segment_program_index`'s own
three equality checks instead would be MORE invasive and LESS complete — it would still leave
`env {-S,}` (an obfuscated flag, not an obfuscated wrapper) and `env -u {PATH,}` (an obfuscated
`--unset` NAME) open, both of which this planning pass measured as live defers. Promoting the
presence-scan clause closes all of them in one predicate.

**Accepted debt, named:** `resolve_segment_program_index` keeps exact equality, so
`{env,} git push --force` classifies `safe` (program token `{env,}` is unrecognised) rather than
reporting `force-push` the way its control `env git push --force` does. The DECISION is identical
(both defer) and the shape is not a bypass — the real shell performs an ordinary `PATH` search and
reaches the shim. What would force a later promote of that site too: any evidence that a
category-level consumer (the gate card's own consequence sentence, the permission request's
`destructiveCategory`) needs the obfuscated form to report the same CATEGORY and not merely the same
decision.
</assumption_delta_decision>
