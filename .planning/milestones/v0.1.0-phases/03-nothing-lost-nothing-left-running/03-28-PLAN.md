    - **Layer 0 — the supervisor's install** (`packages/core/src/shim.rs`). Trusted to prove: the
      per-run shadow directory exists, both entries are non-empty executable regular files, and the
      installed entry answers the current classification contract. Cannot see: anything after the
      session is spawned — a directory removed, replaced or modified mid-session is invisible to it,
      because it runs exactly once, before the backend starts.
    - **Layer 1 — the PreToolUse hook** (`packages/sidecar/src/pretooluse-hook.ts`). Trusted to
      prove: that the shadow directory leads PATH right now, by two synchronous stat calls; the
      command's category, program and bare-name status, borrowed from the shim's pure classifier;
      and, for a safe verdict, whether the text can pre-empt PATH resolution and whether it names a
      shadowed program. Cannot see: what the command will actually do at runtime; anything outside
      the `Bash` matcher; a tool call that is not a shell command; and — say this plainly — it never
      waits, so it can never be the layer that asks a human.
    - **Layer 2 — the shim's runtime interception** (`packages/shim/src/main.rs` under `argv[0]`).
      Trusted to prove: the literal `execvp` of a shadowed name happened, whatever wrapped it, and
      to block indefinitely on the permission socket. Cannot see: an invocation by absolute path; a
      shell function or alias resolved before any PATH search; a PATH cleared or replaced before the
      search; and any program that is not one of the two shadowed names.

    **The named residuals.** A table, one row per case the closure knowingly leaves open, with three
    columns: the case, which layer was trusted to see it and does not, and the concrete trigger that
    should reopen it. At minimum:

    - `sudo` with `secure_path` replacing PATH before the inner program resolves. Layer 2 loses it;
      layer 1 defers because the text carries no shadow construct. Trigger: any evidence an agent
      runs `sudo` inside a worktree.
    - A shadow construct reached through an indirection the raw-text scan cannot see — a function
      definition sourced from a file whose name carries no shadow keyword, for example. Layer 1's
      text scan loses it. Trigger: a corpus row that defers and, on inspection, should not.
    - Claude Code's own internal git housekeeping, which runs outside the agent's visible Bash tool
      loop and therefore never reaches layer 1's `Bash` matcher at all, reaching only layer 2. This
      is already recorded in `scripts/uat/uat-03-destructive-gate.mjs`; cite it rather than
      restating it.
    - Platform coverage: the whole closure is measured on macOS. The shadowed entry names and the
      hook's witness entry differ on Windows and nothing here is measured there. Trigger: a Windows
      build target becoming real.

    **The layer-to-corpus map.** A table mapping each of plan 03-26's corpus groups to the layer
    that is trusted to catch it, so a reader can go from a failing row to the layer that owes an
    explanation. Build it from the rows' own stated `why` values rather than re-deriving it.

    **What was deliberately not done.** Two short entries, each with the trigger that would reopen
    it: enumerating launcher tokens in the classifier (D-59's rejected option — round five of
    enumerate-and-hope, with a shorter and slower-moving list), and inverting the classifier's

    the class completely but turns a narrow `git`/`rm` gate into general command allow-listing;
    `03-CONTEXT.md`'s own discretion note already defers whether the shim intercepts more than
    `git`).
