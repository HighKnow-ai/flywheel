the nested shape measured during this planning pass.

`resolve_segment_program_index` recognises the wrapper token `env` by exact string equality over
`tokenize_shell_words`'s RAW output, which resolves quote-toggling but performs zero backslash-escape
resolution. Two consequences, both measured against the compiled binary at HEAD with
`--classify-invocation` only (D-63):

1. `e\nv -S "-P /tmp git push --force"` classifies `safe` / `textCanShadowPathResolution:false` where
   the unobfuscated `env -S` form classifies `uncategorized` — the round-six decision-invariance break.
2. `sh -c 'env -S "-P /tmp git push --force"'` ALSO classifies `safe` /
   `textCanShadowPathResolution:false` — with **no obfuscation at all**. The wrapper recognition is
   positional (it inspects only the leading token of a segment), so any nesting inside a launcher's
   opaque quoted payload escapes it. This shape is not named anywhere in
   `docs/destructive-gate-trust-boundary.md` today and is a wider boundary failure than the one plan
   03-31 recorded.

Both reach zero human confirmation: Layer 1 defers, and Layer 2 never runs because BSD `env -P`
searches its own altpath and never consults the shim's shadow directory.

deletion or a recursive delete") cannot be true while a real, executable shell construct reaches zero
confirmation. This plan is the vertical slice that proves the whole stack — contract document, shim
