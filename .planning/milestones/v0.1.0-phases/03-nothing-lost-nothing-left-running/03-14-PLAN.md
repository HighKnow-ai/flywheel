<objective>
Close the one gap that fails the phase goal: a real remote branch deletion currently walks straight
past the destructive gate (Success Criterion 5, AGNT-07).

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

**User story (MVP framing):** **As a** developer supervising an agent in auto-accept permission
mode, **I want to** be stopped and asked before the agent deletes a branch on the remote, **so
that** a branch holding work I have not merged cannot disappear while I am not watching.

Purpose: `classify_push` recognises exactly two destructive shapes — a force flag, and a refspec
whose destination is the project's default branch. Everything else returns `Verdict::Safe`. That
means `git push origin --delete feature`, `git push origin -d feature` and
`git push origin :feature` are waved through with no permission request at all, even though
`git branch -D feature` — which destroys strictly less (a local ref, not the published one) — is
correctly gated by `classify_branch`. This directly contradicts the module's own stated fail-closed
rule, and it is the single reason 03-VERIFICATION.md scores Success Criterion 5 as FAILED.

Measured at HEAD, before any change (this is the reproduction, not a hypothesis):
`FLYWHEEL_DEFAULT_BRANCH=main cargo run --quiet -p flywheel-shim -- --classify-command 'git push
origin --delete feature'` prints `safe`. The `-d` and `:feature` forms print `safe` too.
`git branch -D feature` prints `branch-deletion`.

Output: a `classify_push` that detects the delete family, a unit matrix that pins every shape and
every non-regression case, an end-to-end proof through the real shim binary and a real permission
socket, and (Task 3, separable) the leading-plus force refspec hole found in the same function.

**Why WORK-04/WORK-05 are claimed here.** Those requirements' evidence (`lock_contention.rs`,
`spawn_stagger.rs`) runs through the SAME `flywheel-shim` binary whose `git` dispatch path this plan
puts under test for the first time. This plan's regression gate is what keeps that evidence standing
while the shared path changes; it adds no new retry or stagger behaviour.
</objective>
