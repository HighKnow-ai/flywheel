<objective>
Detect, at launch, what a previous session left running or left in flight — and hand each one to the
user as a decision rather than silently resuming or silently repairing it (PROC-05, D-46, D-49).

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

Purpose: success criterion 3's second half — "User relaunches after a crash and is shown every
orphaned process, every in-flight run ... and decides what happens to each; nothing is silently
resumed and nothing is silently repaired." Plan 03-02 put the kill records and run descriptors on
disk; this plan is what reads them. `agent_runs` stores no pid today, so before plan 03-02 nothing
in this product could identify an orphan at all.
Output: `reconcile_agent_runs`, `process_is_alive`, `AppState.pending_orphans`, and the
`agent_runs_pending_orphans` / `orphan_kill` commands plan 03-10's modal drives.
</objective>

`pub fn process_is_alive(pid: i32, start_time: u64) -> bool`. Build a `sysinfo::System`, refresh
only the single process (never a whole-system refresh — this runs before the window paints and must
not stall launch), look the pid up, and return true only when the process exists AND its
`start_time()` matches `start_time` exactly. A missing process, a refresh failure or any other
uncertainty returns `false` — the fail-closed direction here is "assume it is dead", because the
alternative is presenting a modal about a process that does not exist and offering to kill it.

contention log, returning `RuntimeIo`, so a resolved orphan stops being re-detected on every
subsequent launch — this is the "who cleans stale files up" discretion item 03-CONTEXT.md leaves

**`packages/core/src/domain/agent_run.rs`** — add
`pub fn reconcile_agent_runs(conn: &mut Connection, actor_id: &str) -> anyhow::Result<Vec<LiveOrphan>>`
where `LiveOrphan { run_id, task_id, task_key, task_title, project_id, external_session_id, pid, started_at }`.

Select every row whose status is `running` or `blocked` through a compile-time-literal SQL constant
joined to `tasks` for the key and title (the modal renders both, and a second query per row at
launch would be needless). For each row, in this order:
1. `read_kill_record(run_id)` → `Found(record)`: call `mark_abandoned` with
   `Some(&record.reason)`, then `clear_run_runtime_files`. Not a live orphan.
2. `Malformed(_)` or `Absent`: read the run's descriptor. When absent, or when

`mark_abandoned` already returns `Ok(false)` for an already-terminal run, so a re-run is a no-op;
rely on that rather than re-implementing the guard. One transaction per changed row, as
`reconcile_projects` does.

a `detail` naming the pid when the process is still alive afterwards — plan 03-10's modal renders

launch it did not achieve.
