<objective>
Make concurrent git operations against one repository survive lock contention, and stop parallel
starts colliding in the first place (WORK-04, WORK-05, D-51/D-52/D-53/D-54).

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

Purpose: success criterion 4 — "A stress run driving ten concurrent commits into one repository
keeps every commit — index-lock collisions back off and retry instead of failing a task, and
staggered spawn timing stops parallel starts colliding in the first place." The honest framing that
drove D-51: **agents run their own `git commit` inside their own sessions, and
`packages/core/src/git.rs` never sees those calls.** A retry policy confined to `git_at` would
satisfy a stress test Flywheel wrote for itself while leaving `anthropics/claude-code#55724`
completely untouched. The shim is the only design under which the agent's own commits are
protected.
Output: `git_retry.rs`, the `packages/shim` binary, the per-session PATH injection, and the
supervisor-enforced spawn floor. Plan 03-08 runs the stress test against all of it; plan 03-07
reuses the shim as the destructive-action gate's backstop.
</objective>

**Tunables, each a named `pub const` with a doc comment stating its tradeoff** (the "backoff curve
and retry budget" discretion item 03-CONTEXT.md leaves to planning, resolved here):
`RETRY_BASE_MS = 200`, `RETRY_MAX_ATTEMPTS = 5`, `RETRY_JITTER_MS = 120`, `SPAWN_FLOOR_MS = 400`.
The curve is `RETRY_BASE_MS << (attempt - 1)` — 200/400/800/1600ms across four retries after the
initial attempt — plus a uniform jitter in `0..RETRY_JITTER_MS`, matching PITFALLS' own suggested
starting point and extending it by one attempt because `#55724` observed 8 of 13 agents failing at
13-way parallelism, which three attempts would not have covered. Document the worst-case total wall
clock (about 3.2 seconds plus jitter) in the same comment, because that number is what the session
feed's retry row (plan 03-12) tells the user they are waiting for.

**The matcher.** `pub fn is_lock_contention(stderr: &str) -> bool` matches on the general failure
shape git emits for ANY lock file, not a literal file name: a case-insensitive test that the text
contains a `.lock` token AND one of git's lock-failure phrases (`File exists`,
`Unable to create`, `cannot lock ref`, `another git process seems to be running`). A dedicated unit
test asserts the worktree-creation wording from `anthropics/claude-code#34645` and the commit-time
wording from `#55724` both match, and that a plain "unknown revision" error does not. Do NOT match
on the bare file name of the commit-time index lock: the worktree-creation collision is a different
file, and the per-worktree index means the contended file is often a ref or a gc lock instead.

**The executor.** `pub fn with_lock_retry<T, F>(label: &str, f: F) -> Result<RetryOutcome<T>>`
where `F: FnMut(u32) -> anyhow::Result<T>` and
`RetryOutcome<T> { value: T, collisions: u32 }`. Invoke `f`; on `Ok`, return immediately with the
collision count so far — never invoke `f` again after a success. On `Err`, stringify the error and
test it with `is_lock_contention`; when false, return the error unchanged and untouched, preserving
`git_at`'s own message verbatim so a real git failure still reads as itself. When true, increment
the counter, sleep the next delay, and retry until `RETRY_MAX_ATTEMPTS`. On exhaustion return
`LockExhausted { label, attempts }` as a typed error (an `anyhow` error carrying a downcastable
struct) so the caller can distinguish exhaustion from an ordinary failure and raise D-53's event.

**The collision counter.** `pub struct CollisionCounter` holding an `AtomicU32` per run id in a
`Mutex<HashMap<String, u32>>`, with `record(run_id, n)` and `take(run_id) -> u32`. Collisions are
counted and stay silent while retries succeed; only exhaustion is surfaced (D-53). Provide
`pub fn exhaustion_event_payload(repository: &str, command: &str, attempts: u32) -> serde_json::Value`
returning a payload whose `label` reads
`Git lock contention: {command} in {repository} failed after {attempts} attempts.` — the exact
Copywriting Contract string plan 03-12 renders, produced once here so the trail entry and the
event payload cannot drift.

**The spawn floor (D-52, WORK-05).** `pub struct SpawnFloor` wrapping
`Mutex<HashMap<String, Instant>>`, with
`pub fn wait_turn(&self, repo_key: &str)` that computes the remaining time until
`last + SPAWN_FLOOR_MS` for that key, sleeps exactly that remainder while NOT holding the mutex,
then records the new instant. Keyed by repository path so two different repositories never gate
each other. This is a real guarantee, not a probability reduction — the jitter PITFALLS suggests is
applied *inside* the retry curve above, never as a substitute for the floor. Document why the floor
targets `config.lock` at worktree-creation time while the retry targets commit-time locks, so a
later reader does not collapse the two mitigations into one.

**Route `git_at` through it.** In `packages/core/src/git.rs`, wrap the existing `Command::new("git")`
