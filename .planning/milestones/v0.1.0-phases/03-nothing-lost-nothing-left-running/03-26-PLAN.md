    **(a) The unprovable matrix.** Add one test that drives EVERY `LAUNCHER_CORPUS` row, plus four
    extra harmless controls (`npm test`, `cargo build`, `ls -la`, `git status`), through `runHook`
    under each of three separately-broken environments, and asserts a `deny` for all of them:

    1. `FLYWHEEL_SHIM_BIN` unset, with an otherwise perfect shim directory leading PATH — the hook
       cannot even locate a classifier.
    2. A correct shim directory present on PATH but NOT first, with `FLYWHEEL_SHIM_BIN` pointing at
       its `git` entry — the directory exists and classifies fine, but something else would win the
       PATH search.
    3. A directory leading PATH and holding only `rm`, with `FLYWHEEL_SHIM_BIN` pointing at a
       separate real copy of the shim binary so classification still works — the witness entry the
       environment proof stats is absent.

    Each of the three is constructed to defeat exactly one condition of the proof, so a regression
    tells you which condition stopped being checked rather than only that something broke. Say that
    in the test's own comment.

    The harmless controls are the point of the whole block, not an afterthought: D-60 says an
    environment the hook cannot prove denies for every command, not only destructive ones. A matrix
    that only proved the dangerous rows deny would be satisfied by the pre-D-60 behaviour.

    **(b) The invariant.** In the same block, accumulate every decision the matrix produced and
    assert that not one of them is a no-opinion decision — an empty object with exit status 0. State
    in the assertion message that this is the invariant the whole closure rests on: the hook may
    never emit no-opinion without having established the proof, on any branch, for any category.
    This is the test that goes red the instant a future change reintroduces an unproven
    short-circuit anywhere.

    **(c) The falsifiability companion.** Assert that the SAME corpus in the proven environment
    produces at least one no-opinion decision. Without it, a harness that silently failed to build a
    usable environment at all would pass the entire matrix vacuously, which is precisely how an
    unmeasured backstop claim gets recorded as coverage.

    **(d) The idempotency edge.** Add a test that runs the hook twice on an identical payload under
    an identical environment, for three representative rows — one that defers, one denied by the
    D-61 text rule, and one denied by the D-60 environment rule — and asserts byte-identical stdout
    and identical exit status across the two runs. The hook holds no state between invocations
    because every invocation is a fresh OS process; this makes that property a test rather than an
    architectural claim.

    **(e) The concurrency edge.** Add a test that runs two hook invocations in parallel against two
    DIFFERENT shim directories — one proven, one with the witness entry missing — on the same
    command text, and asserts each receives its own verdict: no-opinion from the proven one, `deny`
    from the other. Neither invocation can observe or weaken the other's proof. Name D-57's
    no-local-cache rule in the comment and say it is true here by construction, since each
    invocation is a separate process holding no map, file or record of any prior answer.

    **D-63 binds this task.** Every row is still a string on stdin. Nothing here executes a corpus
    row, touches a remote, or creates or deletes a branch or worktree. The only processes spawned
    are the hook script and, through it, the shim's pure classification mode.
  </action>
