<objective>
Give the user the decision D-45 promises: a worktree the database records but the disk does not have
is surfaced, explained, and resolved by the user choosing between recreating it and dropping the
record (WORK-06, D-45).

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

Purpose: success criterion 3 — "User relaunches after a crash and is shown ... every worktree that
disagrees with the database, and decides what happens to each; nothing is silently repaired." Plan
03-03 made the detection real and the two decisions exist as domain verbs; this plan is the surface.
It also closes broken window #6, whose "missing from disk" clause was explicitly deferred from Phase
2 to WORK-06.
Output: the `worktree-missing` mark, the banner inside `WorktreeSummary`, and the two commands that
resolve it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → `worktree_recreate` | a task id from the renderer triggers a real git worktree creation |
| recorded row → git | a path and a branch stored earlier are replayed into a git command |
| interpolated path → DOM | a filesystem path is rendered into the banner body |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09-01 | Elevation of Privilege | `worktree_recreate` used as an unguarded second creation path | high | mitigate | The domain verb refuses any status other than `missing` and reuses only the recorded branch and base rather than resolving a new one (plan 03-03); the command layer adds no bypass parameter (Task 1) |
| T-03-09-02 | Tampering | `worktree_forget_record` reaching the filesystem | high | mitigate | The domain verb makes no filesystem call at all, asserted by plan 03-03's source gate; the command is a thin delegate (Task 1) |
| T-03-09-03 | Tampering | the Remove Worktree action firing against a path that is not there | medium | mitigate | The banner is an early return, so plan 03-01's action is structurally unreachable while the row is `missing`; asserted by a test rather than by a second guard (Task 2) |
| T-03-09-04 | Information Disclosure | a filesystem path rendered into the panel | low | accept | The path is the user's own worktree path, already rendered by this component today, and is a React text node (auto-escaped); no `dangerouslySetInnerHTML` is introduced |
| T-03-09-05 | Repudiation | a failed recreate clearing the outstanding recovery item | medium | mitigate | The banner never clears locally; it disappears only when the query re-reads a changed status, so a rejected call leaves both the banner and the recovery item in place (Task 2) |
</threat_model>
