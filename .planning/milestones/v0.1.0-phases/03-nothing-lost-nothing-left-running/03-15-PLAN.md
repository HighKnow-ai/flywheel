<objective>
Close the two confirmed Critical blockers in this phase's own changed files: an unvalidated
path join reachable from any IPC caller, and a reachable panic inside the one code path that
cannot unwind.

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

**User story (MVP framing):** **As a** developer running a desktop app that supervises agent
processes, **I want to** know that neither a malformed identifier nor a noisy sidecar can make
Flywheel read a file it has no business reading or die before it draws a window, **so that** the
crash-avoidance machinery this phase built is not itself a source of crashes.

Purpose. Two findings, both independently confirmed in source at HEAD by the orchestrator:

1. `agent_run_log_window` and `agent_run_raw_window` accept a renderer-supplied `agent_run_id:
   String` and hand it straight to `flywheel_core::session_log`, which does
   `sessions_dir()?.join(format!("{agent_run_id}.jsonl"))`. No shape check, no existence check —
   an arbitrary-file-read primitive reachable from any `invoke`. The correct guard already exists
   twice in this workspace: `flywheel_core::ids::is_ulid` (26-character Crockford base32, the shape
   `new_id()` mints and the `CHECK (length(id) = 26)` constraint in `0003_agent_runtime.sql`
   enforces), and `sidecar.rs`'s `is_plausible_run_id`, a looser hand-rolled cousin applied only to
   the sidecar-stdout boundary. Two predicates that can drift, neither applied to the boundary a
   renderer can actually reach.

2. `stderr_tail.truncate(stderr_tail.len().min(READINESS_STDERR_TAIL_CAP))` in `sidecar.rs`'s
   readiness handshake. `String::truncate` panics when the cut is not a UTF-8 character boundary,
   and `String::from_utf8_lossy` emits three-byte U+FFFD replacement characters, so a stderr burst
   straddling the 4096-byte cap panics. The surrounding code's own comment records that a previous
   panic in this exact frame aborted the process before any window was shown, because
   `tauri::async_runtime::block_on` inside `main.rs`'s `.setup()` closure cannot unwind — and the
   workspace release profile sets `panic = "abort"`.

   Why this is a PROC-03/PROC-04 concern and not merely a crash: the readiness handshake is the gate
   that brings up the Node sidecar, and the sidecar is what spawns every session under D-47's
   per-session watchdog wrapper. A panic here means the supervisor never starts — no heartbeat is
   ever touched, no watchdog is ever spawned, and the whole "no agent process survives application
   quit" chain has nothing standing it up. The crash-avoidance machinery must not itself be the
   thing that crashes.

Output: the guard pushed down to the single join site so both boundaries share one implementation,
and a testable, boundary-safe bounded appender for the startup stderr tail.
</objective>

| Boundary | Description |
|----------|-------------|
| renderer → Tauri IPC (`invoke`) | The renderer supplies `agentRunId` as an arbitrary string to `agent_run_log_window` and `agent_run_raw_window`. Anything reaching the renderer — including agent-produced content rendered in a future diff or log view — can reach this surface. |
