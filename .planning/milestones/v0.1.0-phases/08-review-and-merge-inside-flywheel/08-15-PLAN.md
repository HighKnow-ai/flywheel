<design_decision>
## Shape (b) — real bindings — and the measured reason (a) was rejected

The gap offers two shapes: **(a)** enable full keyboard access on the webview so every button joins
the Tab order, or **(b)** give Merge and Open request real bindings in the `review-surface` layer.

**(b) is chosen.** The decisive argument is not taste, it is verifiability:

1. **(a) cannot be verified by the test that found the gap.** The acceptance harness runs in
   **Playwright's WebKit**, driven by `vitest.browser.config.ts` — our Rust process is not running
   and `src-tauri` configures nothing about that browser. Setting `WKPreferences.tabFocusesLinks`
   in the Tauri shell would therefore leave `keyboard.browser.test.tsx`'s reachability test exactly
   as red as it is now. A fix whose own acceptance test cannot observe it is not a closed gap.
2. **(b) is the in-repo precedent.** The criteria list is already keyboard-reachable precisely
   because it carries an explicit `tabIndex={0}` rather than relying on being a button, and every
   other review verb (`j`/`k`, Enter, `c`) is already a `review-surface` binding. (b) adds two more
   entries to a table that already exists; (a) introduces an `unsafe` objc call behind
   `#[cfg(target_os = "macos")]` with no automated verification path.
3. **(b) is narrow.** (a) changes Tab order across every surface in the app, on one platform only,
   as a side effect of fixing one surface.

**Reversibility: `reversible`** — hence no `checkpoint:decision`. Two additive `ActionId`s, two
`BINDINGS` rows and two sheet focus calls are removable in one revert, and (a) stays available
later as a general accessibility improvement; nothing here forecloses it.

## Why the confirm button takes initial focus

A binding that opens a sheet is only half a route: inside the sheet, Tab is just as dead in WebKit,
and Radix `FocusScope`'s default grab lands on the first tabbable candidate — which is Cancel by
DOM order in both sheets. So the sheets must focus their primary button on open. That is also
exactly what UAT item 6 expects ("Enter and Space on the confirm button") and what CR-03 was built
to make safe.

Accidental activation is the cost and it is accepted, not ignored: reaching a focused confirm
button requires a deliberate `m`/`r`, the full preview is rendered above it, Escape cancels, a
merge is local and reversible with no push (D-144's no-retry discipline unchanged), and the epic
request is now guarded by plan 08-14's content hash and by the forge's own `alreadyOpen`
idempotence. Recorded as T-08-15-03 with disposition `accept`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keystroke → board/git/forge action | A key must only reach the action whose surface currently owns focus; `bindingAllowedInLayer` is the single place that is decided (T-01-02, T-02-15 precedent) |
| focused control → irreversible outward action | The epic request publishes outside the machine; the merge writes git history locally |
