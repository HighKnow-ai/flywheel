<objective>
Close G-08-1: eleven syntax-token/row-kind pairs measure below WCAG AA (4.5:1) on tinted diff rows
in WebKit, worst insert/keyword at 2.91:1. The measurement already exists and is already red —
`legibility.browser.test.tsx` is the acceptance test.

The cause is arithmetic, not taste. `markEdits(hunks, { type: "block" })` (D-135, `FileDiff.tsx`)
wraps word-level edits in `.diff-code-edit`, and `react-diff-view`'s own stylesheet paints that
span with `--diff-code-insert-edit-background-color`. In `review.css` that resolves to
`color-mix(in srgb, var(--success-text-rack) 30%, transparent)` — STACKED on top of the row's own
12% mix, which is itself over `--surface-dominant`. Two signal-hue layers compose to #335a4b
(added) and #613e3e (removed), and every one of the eleven failures is on that second layer. The
row layer alone is fine: its worst role measures 5.24:1 (added) and 5.51:1 (removed).

Purpose: a reviewer reads agent-written code against acceptance criteria. If the tint that says
"this line changed" is what makes the changed line hardest to read, the surface fights its own job.

Output: the row tint becomes the only paint behind code glyphs; the word-level edit keeps a
full-strength signal that does not sit behind the text. No new colour value, so
`styles/tokens.css` and `theme/tokens.ts` are untouched and
`theme/__tests__/contrast.test.ts` keeps passing unchanged (per D-131's surface conventions and
01-UI-SPEC.md "Color & Token Roles", `tokens.css` stays the one source of colour).
</objective>

<design_decision>
## Why the fix is "stop stacking", not "lower the percentages"

Three shapes were available. Two were measured against the real composite model (base
`--surface-dominant` #171b22, then the row's 12% mix, then the edit's mix on top — a model
validated by reproducing the UAT's own reported #335a4b and #613e3e exactly):

1. **Lower the edit-block mix percentages.** Infeasible, measured. To bring insert/keyword
   (`--accent-text-rack` on the added edit tint) to 4.5:1 the mix must drop to roughly 8%, at
   which point the edit block contrasts with its own row at about 1.16:1 — the word-level
   highlight stops being a highlight. At 14%, where the mark is still visible (1.30:1), the token
   still measures 4.02:1. There is no percentage that satisfies both.
2. **Lift the syntax-token colours on tinted rows.** Feasible but expensive and wrong-shaped: it
   needs four new colour roles in `styles/tokens.css`, their mirror in `theme/tokens.ts`, new
   assertions in `theme/__tests__/contrast.test.ts`, and it would make the diff's "string" green
   and "success" green two different greens — splitting the one signal vocabulary 02-UI-SPEC.md
   established.
3. **Chosen.** Make the row tint the only paint behind code glyphs, and express the word-level
   edit as a mark rather than a fill. Zero new colour values, the diff confined to `review.css`,
   and every token/row pair inherits the row layer's already-passing ratios with real margin
   (5.24:1 and 5.51:1 worst, not a hair over the threshold). It removes the failure class instead
   of tuning a number that the next palette revision would re-break.

This is not a test dodge. WCAG 1.4.3 is about the colour immediately behind the glyphs; a 2px
inset mark at the bottom edge of the inline box is not that colour, and Task 1 proves the mark
still exists and still differs by row kind rather than deleting the signal.
</design_decision>
