<objective>
The last door closes the loop: an epic's accumulated diff read on the same surface as its tasks'
diffs, and its integration branch proposed to the forge in one action from exactly where you
finished reading it.

The scope toggle and the request action belong in one plan because they are one gesture — D-132's
whole argument for putting both scopes on one surface is that "the epic diff is what you read
immediately before opening its request". Everything the request needs landed in plan 08-05: the
deterministic draft, the four named preconditions, the push-then-create sequence, and an outcome
type that can say the push landed and the request did not.

Purpose: this is the one action in the phase that publishes board content outside the machine, so
the preview-then-confirm discipline Phase 7 established is not a nicety. The component passes an
epic id alone; the body is assembled once by the same pure function for both the preview and the
publish. That is what makes "what you saw is what you sent" a property of the design rather than
a promise.

Output: three commands, the epic request sheet with its blockers and its partial outcome, the
header scope toggle, and one test file.
</objective>

<decisions_resolved>
- **The epic commands live in `commands/forge.rs`, beside their task-scoped siblings**, not in
  `commands/review.rs`. They are forge commands that happen to be reachable from the review
  surface, and keeping them next to the shape they copy is what stops the two from drifting.
- **Three commands, matching the task-scoped trio:** a preview draft, an open action, and a live
  read of an existing request for the epic's branch. The read goes through the existing Phase 7
  adapters, so it is a new *caller* rather than a change to how the forge is called — which is
  what this phase's boundary permits.
- **The epic request ships read-only** (orchestrator decision 2). No status write, no poll
  registration. The missing epic-request observer is recorded as a follow-up for a later phase in
  plans 08-03 and 08-05 and again here.
- **The action is absent, not disabled, when the project has no forge** (D-120). The other three
  blockers render as a named sentence, because each one is actionable by the user — cut a branch by
  starting work, land some commits, add a remote — while "this project has no forge" is a
  permanent property of the project and a disabled control for it is noise.
- **The scope toggle rewrites the store field rather than holding local state.** One field, one
  writer: toggling sets `reviewSurface` to the other scope and the surface re-resolves, which also
  means the toggle survives a remount and the board keystroke can land on either scope directly.
- **Epic scope hops to the epic of the task being reviewed.** From a task's review the toggle needs
  an epic id; it comes from the resolved target the surface already holds, and the toggle is absent
  for an epic-less task because there is no epic to hop to.
- **No compare-page fallback** (plan 08-05's decision, restated): the typed not-installed and
  not-authenticated outcomes are the baseline, and the fallback's URL shapes were never verified.
</decisions_resolved>

<flagged_assumptions>
