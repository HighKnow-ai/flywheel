# Phase 08.1 Plan 10: The Rack's Row Model Summary

**One virtualized rack with four row kinds sized by a single O(1) height lookup, a grouping key that switches it between an epic roster and the five status bands over one scoped query, and rows keyed by identity so a collapse moves them.**

## Performance

- **Duration:** 11 min
- **Started:** 2026-10-08T05:52:00Z
- **Completed:** 2026-10-08T06:04:00Z
- **Tasks:** 3 (each RED then GREEN)
- **Files modified:** 22 (1 created)

## Accomplishments

- `ROW_HEIGHT_BY_KIND` replaces the single `ROW_HEIGHT`. The virtualizer's `estimateSize` is `rackRowHeight(rows[index])`, a table lookup. No `measureElement`, no `ResizeObserver`, no scripted animation anywhere in the rack (all three are negative-grep acceptance checks).
- `volume.ts` no longer declares a height. It imports `ROW_HEIGHT_BY_KIND`, `RACK_OVERSCAN` and `BAND_ORDER`. Its margin test did what it was designed to do when the task row shrank from 40px to 32px, so `VOLUME_ROW_COUNT` went 60 to 100.
- `groupingKey` (`epic | status`, default `epic`) in `uiStore`. The rack builds groups for the active key and every group's rows come from the same scoped `board_list`. The status lens now sweeps all in-review items instead of whatever the 200-row window held.
- Header counts are the list command's `counts` (status) and the plan 05 aggregate (epic), never the loaded rows. A test loads one row under a header that says 181.
- `getItemKey` returns `band:<status>`, `epic:<id|none>`, `quick-add` or `task:<id>`. Every row wrapper carries `data-row-key` and the `displace-transition` class, so rows below a collapse slide.

The existing signature still works unchanged.
