Implements **D-05** (the epic roster leads; each epic row carries title and key, a progress bar, a
task-distribution strip by status, a count of agents running on it and a count of proposals waiting;
expanding an epic reveals its content in place), **D-06** (progress is tasks done over total, with
criteria as a finer second number where present; an epic whose tasks carry no criteria prints a true
statement, never a zero percent that lies), **D-09** (the summary line is computed from board state
by a fixed rule set — zero cost, zero latency, cannot hallucinate) and **D-18** (an epic's change
signal rolls up from its child tasks, and because the epic-pill slot already holds the
pending-proposal count from plan 05-08, the roll-up needs a different slot).

**Why D-06 reads the way it does.** The database held four acceptance-criteria rows across a
907-task board, all of them probe text, before plan 03 seeded the active-worktree tasks. A
criteria-driven progress bar would therefore have read zero percent on every epic and looked
plausible. Tasks-done works today on the real board with no backfill, and the absent-criteria case
has to stay visible as a sentence rather than collapse into a number — which is why plan 05 carried
it as an optional value all the way through the serde boundary.

**What D-09 is not.** An agent reading the board and writing a genuine prose read of where the
project stands is the more agent-native version and is explicitly deferred to its own phase. The slot
this plan creates is the seam it will land in. Build the computed line, not a placeholder for the
agent version, and do not stub a hook for it.

This plan builds only what amendment A-01 approved. Read `08.1-AMENDMENTS.md` first; if A-01 was
declined, stop and report rather than building the roster.
