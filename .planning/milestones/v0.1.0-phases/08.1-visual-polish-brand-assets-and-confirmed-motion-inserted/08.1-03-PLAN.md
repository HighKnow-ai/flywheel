  <action>
Add `packages/core/tests/bin/seed_criteria.rs` and a matching `[[bin]]` entry (`name = "seed_criteria"`,
`path = "tests/bin/seed_criteria.rs"`) in `packages/core/Cargo.toml`, following the existing entries'
convention exactly.

The binary takes a mode argument: `seed_criteria <delete-probes|seed-worktree-tasks|both>`. It
resolves its database the way `uat_seed_ui` does, honouring the app-data-directory environment
variable. One deliberate difference from `uat_seed_ui`: this tool is *meant* to be pointed at the
real fleet database, so when that variable is absent it requires an explicit
`--i-mean-the-real-database` flag to proceed against the default app-data location, and exits
non-zero otherwise.

The deletion guard is the load-bearing part. Hard-code an allowlist of probe statements — exactly
the two words recorded in `08.1-RESEARCH.md` Correction 7, compared after trimming — and delete a
row only when its statement matches that allowlist exactly. Any other row is skipped with a printed
line naming its id. The guard means a mistyped argument cannot destroy real criteria. Route every
deletion through `acceptance_criterion::delete_criterion` and every creation through
`acceptance_criterion::create_criterion`, with a real actor id; never write your own `INSERT` or
`DELETE` against that table, because a raw row leaves no event and is then distinguishable from one
the application produced.

Seeding selects tasks by joining `worktrees` on active status, reads each task's key, title and
description, and creates two to four criteria per task that are each checkable against a diff —
concrete statements a reviewer could tick while reading the patch, not restatements of the title.
Because a task that already has an agent run cannot have a criterion edited in place
(`criteria_locked_for_task`), write final wording on the first pass. If `create_criterion` refuses
for a locked task, print the refusal and exit non-zero rather than working around it; that is a
finding to report, not a thing to bypass.

End with a parsable final line shaped `SEEDED <mode> deleted=<n> created=<n>` so a shell check can
assert on it.

Extend `packages/core/tests/criteria.rs` with the five `<behavior>` cases against fixture databases
built from `common::seeded_project`. Write them first and watch them fail. Factor the binary's
deletion and seeding logic into functions the test calls directly, so the test exercises the real
guard rather than a reimplementation of it.
