## Pattern Assignments

### `packages/core/src/git.rs` — add `ahead_behind(repo_path, target_ref, branch)`

**Analog:** same file, `diff_stat_and_names` (lines 159-183) and `git_status_porcelain` (lines 144-147)

**Core pattern** (one-function-per-git-read, routed through `git_at`, no second `Command::new`):
```rust
pub fn git_status_porcelain(worktree_path: &Path) -> anyhow::Result<String> {
    let output = git_at(worktree_path, &["status", "--porcelain"])?;
    Ok(String::from_utf8_lossy(&output.stdout).into_owned())
}
```
Follow this exact shape for `ahead_behind`: a single doc comment explaining the git flags chosen and why (mirrors `diff_stat_and_names`'s explanation of `--no-renames`), a single call (or two, like `diff_stat_and_names`'s stat+names pair) through `git_at`, zero parsing beyond splitting the known-shape stdout. RESEARCH.md's own illustrative body (`rev-list --left-right --count`) is the right shape to fill in — do not invent a parsing approach different from the `stat`/`names` split-and-collect idiom already used here.

**Hard constraint carried over:** `packages/core/tests/supervisor_cwd.rs` asserts exactly one `Command::new("git")` site in the whole workspace (inside this file). `ahead_behind` must call `git_at`, never construct its own `Command`.

### Status transitions — reuse `domain::task::set_task_status`, do not reimplement

**Analog:** `packages/core/src/domain/task.rs` lines 408-461 (verbatim, read this session):
```rust
pub fn set_task_status(
    conn: &mut Connection,
    actor_id: &str,
    task_id: &str,
    new_status: &str,
) -> anyhow::Result<()> {
    ...
    if current_status == new_status {
        tx.commit()...;
        return Ok(());   // no-op guard already here — D-121's edge-triggered writer needs none of its own
    }
    tx.execute("UPDATE tasks SET status = ?1, updated_at = ?2 WHERE id = ?3", ...)?;
    let sequence = next_sequence(&tx, &project_id, "local")?;
    let payload = serde_json::json!({ "field": "status", "before": current_status, "after": new_status, "label": ... });
    append_event(&tx, &project_id, "local", sequence, "task", task_id, Some(task_id), epic_id.as_deref(), actor_id, "task.status_changed", &payload, &now)?;
    tx.commit()?;
    Ok(())
}
```
D-121/D-122's scheduler-driven transitions call this function directly, passing `actor_id = system_actor(conn)?.id` (see `domain/actor.rs` lines 48-61, `system_actor` — "used for any mutation performed by Flywheel itself rather than a human at the keyboard... this phase is its first real consumer", per RESEARCH.md). Never update `tasks.status` with a raw `UPDATE` statement outside this function.

## Shared Patterns

### Single git construction site (PROC-02)
**Source:** `packages/core/src/git.rs` header comment (lines 1-10) and `spawn_git` (lines 30-39)
**Apply to:** `git.rs`'s `ahead_behind`, and nowhere else — every other new file in this phase (forge adapters, scheduler, hooks) that needs a git read calls into `git.rs`'s existing public functions, never constructs its own `Command::new("git")`. Structurally enforced by `packages/core/tests/supervisor_cwd.rs`.

### Derive at read time, cache nothing (D-75)
**Source:** `packages/core/src/drift.rs` header comment (lines 9-13); `packages/core/src/query/events.rs` header comment (lines 10-14)
**Apply to:** `ahead_behind` (ahead/behind figure derived fresh, never stored verbatim — only the fetch *timestamp* is stored for the staleness label, D-116), and D-128's hash/branch resolution (reads git fresh every time, no sha→task index).

### Actor stamped in Rust, never claimed by the renderer (T-01-04)
**Source:** `packages/core/src/domain/actor.rs` header comment (lines 1-5) and `system_actor` (lines 48-61)
**Apply to:** every automatic status transition and every `events` row this phase writes (D-115, D-121, D-123, D-124) — resolve `system_actor(conn)?.id` inside the Rust core, never pass an actor id in from the frontend or a shell script.

### Schema-enforced status vocabulary, writer goes through `set_task_status`
**Source:** `packages/core/src/domain/task.rs` lines 408-461; `packages/core/src/db/migrations/0002_board_schema.sql` lines 41/67
**Apply to:** D-121/D-122's edge-triggered writer — call `set_task_status`, rely on its built-in no-op guard, never bypass with a raw `UPDATE tasks SET status = ...`.

### Marker-comment self-recognition for generated git hooks
**Source:** `packages/core/src/git_hooks.rs` `PRE_PUSH_MARKER` (line 29) and its use in `is_flywheel_hooks_dir`/`verify_install`
**Apply to:** the new commit-msg hook — define its own marker constant, reuse the existing refusal/verification functions' shape rather than writing new ones from scratch.

### Push, then invalidate (no polling in the frontend)
**Source:** `packages/desktop/src/board/useBoardQuery.ts` lines 499-521 (header comment + the single `board:changed` subscription)
**Apply to:** D-113's scheduler tick — emit into the existing `app.emit("board:changed", …)` → `useBoardQuery.ts` invalidation path; do not add a second Tauri event name or a `refetchInterval` in the frontend.

### Absence is the design
**Source:** `packages/desktop/src/item-detail/WorktreeSummary.tsx` header comment (lines 1-7)
**Apply to:** `ForgeSection.tsx` (D-120) — render nothing, not an empty labeled header, when no forge is configured.
