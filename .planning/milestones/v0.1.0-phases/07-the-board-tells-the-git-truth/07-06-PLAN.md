<objective>
Notice work the user did themselves. A commit on a task's branch that no recorded agent run
produced is marked in the commit list and written to the activity trail — and nothing else
happens to it.

**Phase goal (ROADMAP, verbatim):** Cyril can answer "where does this task actually stand in git
and on the forge?" from the board, without opening a terminal.

The ROADMAP's own note: "LINK-10 matters more than it looks: the moment the board and the working
tree disagree about a branch, the user stops trusting the board and goes back to the terminal —
which is exactly the v1 failure condition."

"Never silently overwritten" is satisfied structurally rather than by a dialog: Flywheel never
rewrites git at all, and this plan's only write is one append-only `events` row.

Output: agent-run coverage per commit, an idempotent event write driven by the existing tick, and
a per-row marker in the commit list.
</objective>

<decisions_resolved>
- **D-129 applied literally: coverage, not trailer absence.** Because plan 07-02's `commit-msg`
  hook stamps *every* commit on a `flywheel/` branch, a hand-typed commit carries the same
  trailers an agent's does. The marker is therefore computed from whether some `agent_runs` row
  for the task has `started_at <= commit.committed_at <= coalesce(ended_at, <now>)`. The plan
  states this in the function's own doc comment so a future reader does not "simplify" it to a
  trailer check.
- **Inclusive on both boundaries.** A commit timestamped exactly at a run's `started_at` or
  `ended_at` is covered. Git's committer timestamps have one-second resolution, so an exclusive
  bound would mark a genuine agent commit as the user's on an exact-second collision — a false
  accusation is the worse error, and the window's own endpoints belong to the run that owns them.
- **A still-running run has an open right edge.** `ended_at` is NULL while a run is live, so the
  coverage window extends to the time of the read. This is the correct reading: a commit landing
  now, during a live session, was produced by that session.
- **Idempotency is a query, not a stored flag.** Before appending, the writer checks for an
  existing `events` row with this event type, this `task_id`, and this sha in its payload, using
  `json_extract(payload, '$.sha')`. The append-only log is itself the record of what has already
  been noticed — no `seen` column, no second source of truth (D-75).
- **Event type `task.outside_commit_detected`, with a `label` in its payload.** Because
  `render_description` returns a non-empty `label` verbatim, this requires no change to
  `ActivityTrail.tsx` at all — the trail renders the new entry correctly the moment the first row
  is written.
- **Detection runs on both tick tiers, scoped to the rendered window.** The writer examines only
  the commits `git_facts_for_task` already read (capped at `COMMIT_WINDOW`), so detection costs no
  extra git invocation and no unbounded history walk. A commit older than the window is outside
  what the item displays and is not retroactively announced.
- **D-115's rejected escalation stays rejected.** No board-card indicator, no acknowledgement
  flow, no new status. `drift.rs`'s existing `StaleSinceLastSummary` detector already carries an
  outside commit into the next agent's context packet for free; this plan is about what the *user*
  sees.
</decisions_resolved>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the user's own git history → a board claim | Flywheel reads commits it did not create and makes an assertion about who created them |
| background job → the append-only event log | the tick writes `events` rows with the system actor |
| the detection → the user's work | the one boundary that must stay read-only with respect to git |
