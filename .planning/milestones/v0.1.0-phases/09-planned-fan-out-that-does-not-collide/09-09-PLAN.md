Build `packages/desktop/src/dispatch/DispatchGateLine.tsx` and place it with the epic dispatch controls from
Task 2, so the reason sits where the user looks when a fan-out appears to have stalled.

Three states, three renders. Open renders nothing — an always-present line that usually says "fine" trains
the eye to ignore it. Paused renders the reason the Rust core returned plus a resume-now action, and
distinguishes the two paused variants: with a resume instant it says when dispatch will resume; with none it
says the reset time is unknown and that a manual resume is the only way out, because that is exactly what
the gate does and a hopeful "retrying soon" would be a lie. Warning renders the reason plus an advance-now
action, and says the running wave will finish — the whole point of the warning tier is that the user is not
cut off mid-wave with half an epic merged.

Every reason string comes from the command's response. The renderer composes none: the gate's state machine
is in the core, and a second wording of the same condition in the renderer is a second source of truth
about what the backend said.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → plan edit and approve | A path string and a wave number edited in the webview become the declaration the guarantee rests on, and approval starts unattended work. |
| Rust response → rendered verdict | A sequencing reason, a refusal and a gate reason are facts the renderer must display rather than derive. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-09-01 | Tampering | an invalid entry edited in the sheet | medium | mitigate | The renderer validates nothing; the shared validator in the core refuses and the refusal text is displayed |
| T-09-09-02 | Repudiation | a renderer-computed overlap disagreeing with the core's | high | mitigate | Sequenced pairs and colliding paths come from the plan response; a source gate asserts the sheet contains no containment computation |
| T-09-09-03 | Elevation of privilege | approval or stop reachable without a human | high | mitigate | Both are human-only commands with server-side actors; the sheet's approve is the only path that starts dispatch |
| T-09-09-04 | Information disclosure | a gate reason composed in the renderer misstating the backend's message | medium | mitigate | Reason strings are read from the response; a source gate asserts no hard-coded gate reason text |
| T-09-09-05 | Denial of service | double-submission starting two dispatches | medium | mitigate | Every action disabled while in flight, asserted by a second click during the window |
| T-09-09-06 | Repudiation | a task excluded from the plan and invisible on the sheet | medium | mitigate | Excluded tasks render with their reason; asserted |
</threat_model>
