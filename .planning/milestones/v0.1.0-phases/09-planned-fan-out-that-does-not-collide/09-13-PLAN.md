## The manual-launch question, answered

`09-07-SUMMARY` recorded, deliberately, that a user's own launch is never refused; the launch body's doc
comment states it as a contract; and the verification does not complain that the manual overlap is
ALLOWED — it complains that it is "SILENT, with no warning to the user that the launch overlaps a live
task". So this plan makes it visible and leaves it allowed.

That is the right reading of the goal, too. "Parallelism bounded by real disjointness rather than optimism"
is violated by a machine that puts two agents on one file set because nobody checked. It is not violated by
a developer who is told the collision, by name and by path, and proceeds anyway. Optimism is the absence of
the check, not the presence of an override.

**Flagged for the owner, not planned:** if the owner wants a manual overlapping launch REFUSED, that
reverses a recorded decision and should be its own decision. The pieces would be in place — this plan's
disposition parameter already has a refusing variant, so the change would be one call site.

One refusal does apply to both paths: launching a task that already has its OWN running or blocked run.
That is not a cap refusal — two agents in one worktree corrupts the work, `readiness` already refuses it
for the dispatcher, and no contract anywhere promises a user they may do it.

Purpose: the invariant stops depending on which caller happens to be launching.

Output: the conflict read in the shared launch body, the dispatcher refusing, the manual path recorded and
surfaced.

**Not in this plan:** the rule itself (plan 09-12), the declare path (plan 09-11), the `why` answer (plan
09-10). Out of scope per the phase's scope fence: D-REV-39 (including the WR-03 leaked run row and the
WR-05 relaunch, which this plan narrows but does not fix), D-REV-41, D-REV-42, D-REV-32 through D-REV-36.
