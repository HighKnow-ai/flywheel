<objective>
**Phase goal (ROADMAP `**Goal**`, verbatim — it is not in `As a / I want to / so that` form):** Cyril turns
one epic into several agents working at once, with parallelism bounded by real file-set disjointness rather
than optimism.

The dispatcher works on declared sets. This plan is where the declarations come from: a short agent run
over the epic, immediately before fan-out, that reads the repository as it is *now* and attaches a file-set
and a wave to each of the epic's existing tasks — then stops, and hands the user a draft to check.

Purpose: PLAN-01 and D-147. A file-set forecast made at authoring time is stale by the time dispatch
happens, and the overlap guarantee is only as good as the freshness of what it compares. A wrong file-set is
also the single error that silently voids the entire parallelism guarantee, so it gets one human look
(D-149) before anything spawns.

Output: the `submit_plan` tool as a held call with Rust-side authority and validation, the planning run,
`render_planning_prompt`, and a stored draft plan.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent tool call → plan storage | A model-authored list of paths and waves becomes the declaration the whole parallelism guarantee rests on. |
| MCP tool visibility → authority | Every tool is listed to every run, so visibility cannot be the control. |
| planning run → epic integration worktree | A run whose working directory is the integration worktree can strand every later merge. |
