<objective>
FLEET-03: **the user jumps from any fleet entry directly to that agent's live output and to its board item.**
Both destinations, from the row, without a menu.

Purpose: the fleet is opened to watch something, so the row's primary action is the session (D-166) — the
board item is a second, distinct target on the same row. Research measured that the second one is not the
one-liner it looks like. `BoardView` runs an effect keyed on the project id that clears selection, detail
and delete state, and it resolves a selected item only from its loaded window; the command palette's
existing git-identifier jump sets three fields in one handler and that effect immediately undoes them
whenever the target project differs from the current one (Finding 9). A cross-project jump therefore needs a
request that survives the project change.

The primary target has its own trap: `agent_runs.task_id` and `epic_id` are both nullable and mutually
exclusive, so authoring and planning runs carry an epic or nothing (Finding 10), and `SessionSurface`
defaults its status to running (Pitfall 7). The row must hand over all four identifiers and the mapped
status, or the surface mounts in the wrong shape.

Output: the row's primary and secondary targets, a one-shot `pendingFocusItemId` in `useUiStore`, and
`BoardView` consuming it once the item exists.
</objective>
