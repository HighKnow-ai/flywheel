<objective>
The DONE / FAILED band becomes answerable: every finished row shows what it spent, the footer totals the
fleet's visible spend, and the user can clear a row they have dealt with.

Purpose: ROADMAP criterion 5 names cost visibility as something the user must see, and AGNT-08 is already
implemented — the adapter reports `total_cost_usd` and the summed token counts at the terminal `result`
event and `apply_session_closed` persists them (Finding 11). This plan **surfaces** that, and it does the
one thing D-165 needs to work at all: widen the acknowledge statement past `abandoned` and give the user a
way to use it. Without the second half, migration 0020's backfilled rows leave but nothing new can ever
leave, and the band fills up again.

Two honesty constraints come from research rather than from the sketch, and both are in this plan's
prohibitions: `total_cost_usd` is a client-side estimate from a bundled price table, so the footer says so;
and `tokens_in` is a sum that includes cache reads, so a tokens column reads far larger than the plain
input figure and must not be presented as the prompt size.

Output: `domain::agent_run::acknowledge_run`, the widened `agent_run_acknowledge` command with its
capability description corrected, the spend column and labelled footer total, and the per-row and
band-header dismiss actions.
</objective>
