<objective>
Pursue the ROADMAP's fork branch 1 — "own the command shell's environment" — through the mechanism
Claude Code actually documents for it, and make its uncertainty visible instead of assumed.

Purpose: the ROADMAP names the per-run `--settings` `env` block as branch 1's candidate. That candidate
is refuted: the shell snapshot is sourced after process-environment setup and its trailing
`export PATH=` wins, which is the same mechanism that defeated round ten's Part 1. Claude Code ships a
purpose-built replacement — `CLAUDE_ENV_FILE`, writable from a `SessionStart` hook, with an official
worked example that is literally a PATH prepend. If its ordering holds, P1 becomes true by construction
and `shimWillIntercept` stops being a bet.

**It is `[CITED]`, not `[VERIFIED]`, and this plan does not pretend otherwise.** Two caveats are
carried in the code's own comments rather than smoothed over: an open Windows bug in which the file is
written but never sourced for subsequent Bash commands, and a documented self-contradiction between
Anthropic's Settings guide and Hooks guide about this variable's role. The live falsification run is
plan 12-05, and the guarantee is authored above as a `backstop` truth so the verifier abstains rather
than silently passing.

**Why this is safe to land before the live measurement, where round ten was not.** This plan changes
no gate decision path. `pretooluse-hook.ts` is not touched. If `CLAUDE_ENV_FILE` works, the shim
reaches `PATH[0]` and the already-tested Layer 2 path runs. If it silently fails, behaviour is exactly
today's. There is no configuration of this change in which a benign command becomes a refusal — which
is precisely the property round ten lacked.

Output: `packages/sidecar/src/sessionstart-hook.ts`, its registration in `writeHookSettings`, and an
offline test pair covering both the success and the degrade-silently arms.
</objective>

  <action>
Create `packages/sidecar/src/sessionstart-hook.ts`, a standalone single-purpose hook script in the same
shape as `pretooluse-hook.ts`: a compiled module invoked as `${process.execPath} <script>`, which does
its work synchronously and exits. It never waits, never opens a socket, never polls.

Its only job: read `process.env.CLAUDE_ENV_FILE` and `process.env.FLYWHEEL_SHIM_BIN`, derive the shim
directory as `dirname(FLYWHEEL_SHIM_BIN)` — the SAME derivation `shimWillIntercept` uses, not a second
independently-computed path — and `appendFileSync` one line that exports `PATH` as the shim directory
followed by the path delimiter followed by a reference to the shell's existing `$PATH`. Quote the
assignment value so a directory containing a space survives, and escape the `$PATH` reference so it is
expanded by the sourcing shell rather than by this process.

**Failure mode, stated as a deliberate difference from `pretooluse-hook.ts`:** that hook fails CLOSED
(an unparseable payload becomes a deny) because it makes a permission decision. This hook makes no
decision — its only effect is a best-effort PATH restoration — so its failure mode is a silent no-op
and never a throw or a non-zero exit. A throw here would surface as a `SessionStart` hook error and
could abort session startup, turning a best-effort improvement into an outage. Wrap the whole body in
one try/catch that swallows to `process.exitCode = 0`. State this distinction in the module doc comment
so a future reader does not "fix" it into fail-closed by analogy with its sibling.

**Both research caveats go in the module doc comment, named, with their identifiers:** that
`CLAUDE_ENV_FILE` is scoped to `SessionStart`/`Setup`/`CwdChanged`/`FileChanged` hooks only and is NOT
available inside `PreToolUse` (which is why this is a second, independent hook registration and not an
addition to `pretooluse-hook.ts`); that `anthropics/claude-code#27987` reports the file being written
but never sourced on some Windows builds; that `anthropics/claude-code#19357` records a contradiction
between Anthropic's own Settings and Hooks guides about this variable's role, closed "not planned"; and
that the ordering claim is `[CITED]` and is measured live by `scripts/uat/uat-11-env-file-ordering.mjs`
(plan 12-05), not by any offline test in this repository.

In `packages/sidecar/src/claude-code-adapter.ts`:
- Add `sessionStartHookScriptPath()` next to `pretoolUseHookScriptPath()` and
  `stageGateHookScriptPath()`, using the identical `fileURLToPath(new URL("./sessionstart-hook.js", import.meta.url))` idiom.
- In `writeHookSettings`, add a `SessionStart` key to the settings object alongside the existing
  `PreToolUse` key. Its value is an array with one entry whose `hooks` array holds one
  `{ type: "command", command: \`${process.execPath} ${sessionStartHookScriptPath()}\` }` — no `matcher`
  field: `SessionStart` is not tool-scoped. Do NOT change the `PreToolUse` array's construction,
  ordering, or contents, and do NOT change `writeHookSettings`' signature — its three existing callers
  must not need an edit.
- Add no new try/catch. The existing catch block already covers the same `fs.writeFileSync` call and
  already degrades to `return undefined` with a logged line; a `SessionStart` entry that cannot be
  written must take that exact pre-existing path. Extend that catch's log text to name hook settings
  generally rather than `PreToolUse` specifically, so the message does not mislead when the
  `SessionStart` entry is the part that failed.
