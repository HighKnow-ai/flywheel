<objective>
Make the live acceptance arm physically incapable of throwing away what it captured.

This is gap `G-05-7`'s BLOCKER. Live run `01M3C48C3PV1NSGHERBZ587YB1` authenticated on the
developer's own claude.ai login, captured 539 characters of genuine agent speech across 2 chunks
and a ~130-event trace, and then discarded all of it, because `driveChallengeConversation` THREW
and every evidence write sits downstream of the call that threw. The comment at the point where the
sheet path is resolved promises failure-path evidence in so many words; the control flow does not
provide it. That is the eighth instance of this phase's recorded defect class.

The fix is structural, not additive. Evidence emission moves to ONE writer reached from ONE exit
point, the throw carries its own partial capture rather than stringifying it into a message, and
the driver attaches the exchanges it had already accumulated to whatever error escapes it. After
this plan there is no failure shape that can bypass the sheet, because there is nothing left to
bypass.

Purpose: SHAPE-01 and SHAPE-03 have been UNJUDGED for nine rounds, and one real credential spend
has already produced nothing. The next live run must be judgeable whatever happens to it.
Output: a single evidence writer on a `finally`-shaped path, structured partial capture carried
through two throw boundaries, a preserved scratch root on failure, and an offline scenario that
reproduces the exact thrown-deadline shape and proves the sheet lands.
</objective>

Read this before writing any code. Each item was measured directly during planning, at zero
credential cost, and two of them CORRECT the gap report. Planning from an uncorrected gap report is
how this phase has repeatedly fixed the wrong thing.

1. **The evidence sheet genuinely did not survive.** `05-LIVE-CHALLENGE-TRANSCRIPT.md` is
   byte-unchanged from the previous run. Confirmed. This half of the gap is real.

2. **The credential-path artifact DID survive — the gap report is wrong about this.** The file
   `socratic-authoring-2026-09-25T11-12-22-899Z-uat-08-credential-path.json` (199 bytes) is still
   present in the artifact directory the run's own stdout named. `Harness.artifactDir()` resolves
   OUTSIDE `harness.root` (an `os.tmpdir()` sibling), is never registered with `onCleanup`, and its
   own doc comment says so. Do NOT implement "preserve the run artifact directory on failure": there
   is no such defect, and implementing a fix for a non-defect is this phase's failure mode wearing
   the other face. The real gap underneath the report's wording is that NOTHING PROVES the survival
   — plan 05-33 self-tested that the artifact renders and never that it outlives a failure. Close
   that with a test (Task 2).

3. **What IS destroyed on failure is `harness.root`.** The constructor registers
   `fs.rmSync(this.root, …)` as the FIRST teardown, and teardown is LIFO, so it runs LAST on every
   exit — success, assertion failure and thrown exception alike. Everything an operator needs to
   diagnose a failed live run lives under it: the composed config directory, the scratch repository,
   the app-data directory and the runtime protocol's lifecycle JSONL. That is the real, verifiable
   half of the gap's second bullet.

4. **`new Harness(...)` and `harness.cleanup()` have exactly one call site each**, both inside
   `scripts/uat/lib/sidecar-harness.mjs` (`runScript`). Making cleanup failure-aware is a
   single-call-site change and affects no other UAT script.

5. **`driveChallengeConversation` accumulates `exchanges` in a function-local array.** When
   `waitForTurn` rejects, that array is unreachable to every caller — which is why a run that
   captured two chunks and 539 characters reported them only inside a message string. The counts in
   that string were produced by `accumulateTurn(this.events, runId, cursor)` inside `fail()`; the
   partial object it returns is complete and is simply not attached to the Error.

6. **`renderChallengeEvidenceSheet` already carries two byte-identical-when-absent sections**
   (the non-conversation section and the credential-path section), assembled at the tail as
   `${nonConversationSection}${credentialPathSection}${verdictsSection}`. The failure section this
   plan adds must follow that established discipline exactly, and the verdict section must stay
   last — it is the part a human fills in by hand.
</measured_ground_truth>
