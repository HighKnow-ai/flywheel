<objective>
`WR-04` is the one review finding `05-VERIFICATION.md` explicitly flagged as "worth tracking before
the next live attempt", and it is the last instrument defect standing between the developer and a
live run he can trust. `TURN_IDLE_MS` is five seconds. It is the only thing between "the model
paused mid-turn" and "the capture concluded early". And the callback that keeps it alive fires on
ANY sidecar event — not specifically an event belonging to the awaited turn — so the clock is kept
alive by unrelated traffic and left to expire by relevant silence. A real Bash tool call that takes
longer than five seconds with no other traffic in flight lets the timer fire, the driver treats the
partial capture as a complete turn, extracts whatever questions happen to be in the fragment
(possibly none, reporting the conversation as settled), and sends the next developer turn while the
agent is still generating — interleaving developer input with an unfinished agent turn on the wire.

No offline arm can catch it today, and the reason is precise: `fake-authoring-claude.mjs` always
replies instantly, so there is no fixture in this repository capable of expressing a mid-turn pause
at all. That is the real gap — not the constant's value.

The fix is not a bigger number. A turn that has issued a tool call and not yet received its result
is *provably* mid-flight, and that is an observable fact on the wire, not a guess. This plan gives
the fixture the ability to pause, makes the idle window respect its own turn's progress and stand
down while a tool call is outstanding, and leaves the outer deadline as the honest backstop it was
always meant to be.

Purpose: remove the last known way for the next live run to produce a transcript that lies about
what the model said.
Output: a fixture that can pause mid-turn, an idle policy scoped to its own turn, an explicit live
idle window, and a scenario that fails in the right direction.
</objective>
