<objective>
**As a** solo developer running a fleet of agents, **I want to** reopen an epic weeks later and have
the agent argue with the change against what the epic already contains, **so that** continuing to
shape something does not mean re-explaining it.

That argument is model judgement (D-91), and the discipline that carries over from Phase 4's ban on
judgement is not *whether* judgement is allowed but **what facts it is grounded on**. This plan
builds those facts: an epic-scoped sibling of `context_packet.rs` holding the epic, its task roster
with criteria and statuses, its prior authoring history, and — the ammunition the challenge actually
needs — the set of proposals the developer already rejected.

It also pays a debt this phase inherits. `01-SECURITY.md` AR-01-04 records `epic_roster` as "the
phase's sharpest latent DoS surface, unguarded by design", with an explicit trigger: *re-rate when
Phase 2+ gives an agent an epic-creation path*. Phase 5 gives an agent a board **read** path, which
is the same trigger arriving from the other side. D-87 puts closing it in scope here.

The closure has to respect why the exemption existed. AR-01-04's own words: "any cap would silently
truncate the roster and reintroduce the exact defect this plan closes" — G-01-2, where an epic
sorting outside the window made `BoardRow.tsx` render a raw ULID. So the answer is not one cap. It
is two reads with two ceilings: the agent gets a properly clamped page, and the renderer's
label-resolution roster gets a high ceiling whose truncation is **surfaced rather than silent**,
which is D-16's rule and the only version that closes the exemption without reopening the defect.

Purpose: ground SHAPE-05's challenge in facts, and remove the last unbounded read before an agent
can reach it.
Output: the epic packet and its renderer, the bounded rejected set, the triage-lane query, and the
two-ceiling epic read.
</objective>

`pub fn assemble_epic_context_packet(conn: &Connection, project_id: &str, epic_id: Option<&str>)
-> anyhow::Result<EpicContextPacket>`. The `Option` is load-bearing: SHAPE-01's primary case is an
epic that does not exist yet, and a packet for "nothing yet" is a real packet with most sections
absent, not an error.

`EpicContextPacket` sections, each its own `#[derive(Debug, Clone, PartialEq, Serialize)]` struct,
each using `Option<T>` for absent rather than an empty-string or empty-vec sentinel:

- `epic: Option<EpicFacts>` — title, description, status, key.
- `task_roster: Vec<TaskRosterEntry>` — every task under the epic with its key, title, status, and
  its **current-revision** criteria only (`superseded_at IS NULL`). A superseded criterion is visible
  to the developer and never to an agent (D-79); this packet is an agent-facing read and must hold
  that line.
- `answered_assumptions: Vec<AssumptionEntry>` — the accepted `assumption` proposals from prior
  authoring runs on this epic, each an addressable row with its own assumption and answer fields,
  never a prose blob.
- `rejected: RejectedSet` — see below.
- `prior_authoring_runs: Vec<AuthoringRunEntry>` — run id, started/ended, and the stage it reached,
  so the model can tell "we got as far as criteria last time" from "we never left challenge".

`RejectedSet` is where D-83's bounding obligation is paid, and it copies `compaction.rs`'s contract
rather than inventing a second one: the most recent `REJECTED_VERBATIM_WINDOW` rejected proposals are
carried whole; everything older is folded to its `target_type` and its payload's title/statement
alone, with the narrative dropped entirely. **Bounded by position, never by size** — no character
count, no token count, no size ceiling anywhere, for exactly the reason `compaction.rs`'s header
gives: a size ceiling moves the boundary for reasons a developer cannot see. Carry a
`RejectionBoundary` naming where the fold begins, and have `render_epic_prompt` state it in a
sentence, exactly as the summary fold already does.

`pub fn render_epic_prompt(packet: &EpicContextPacket) -> String` — the deterministic renderer.
Stable headings, and the omit-the-heading-rather-than-emit-an-empty-section rule copied verbatim: an
epic that does not exist yet produces a prompt with no epic heading, not a heading followed by
"none". Two obligations specific to this packet:

- The rejected section's prose must tell the model plainly that these were rejected by the developer
  and are not to be re-proposed. D-83 is the re-proposal guard and the prompt is where it acts;
  D-93's rejected option — a structural bar in the tool handler — is a Deferred Idea precisely
  because near-duplicate matching is the hard problem, so the prompt is carrying this load on
  purpose.
- The prompt must ask for challenge, not for a plan. State the current stage's job in one sentence
  and, for the challenge stage, name what a good turn looks like: surface an assumption the developer
  has not stated, or a risk the epic's existing contents contradict. An authoring turn that only
  affirms the developer's framing is the failure this phase exists to prevent, and the prompt is the
  first place to say so.

Add `packages/core/tests/epic_context_packet.rs` covering: a packet for `epic_id = None` on a seeded
project (epic section absent, roster empty, prompt has no epic heading); a packet for a real epic
with tasks and criteria; a superseded criterion absent from the packet while its successor is
present; the rejected fold at exactly `REJECTED_VERBATIM_WINDOW` and at one above it, asserting the
boundary sentence; two assemblies over identical board state comparing `PartialEq`-equal; and a
cross-project case — an epic in project A with a same-shaped epic in project B, asserting no row from
B appears.
