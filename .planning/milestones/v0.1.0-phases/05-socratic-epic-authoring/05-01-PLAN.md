<objective>
**As a** solo developer running a fleet of agents, **I want to** shape a new epic by being
challenged rather than interviewed, **so that** I walk away with structured board items instead of
a document.

*(Formatting of `ROADMAP.md`'s Phase 5 Goal line — actor, want and so-that are all present in that
sentence; nothing is invented here.)*

This plan builds none of that. It is the measurement gate `ROADMAP.md`'s own Phase 5 Notes demand
("Spike the flow during planning... before building the full surface") and `05-RESEARCH.md` repeats
as Pitfall 2 ("Do NOT write the phase's PLAN.md tasks assuming Option A works until this spike has
run once against the real binary"). Three claims the rest of the phase rests on are, today,
unmeasured:

- **A1** — does `--input-format stream-json` deliver sequential conversational turns to one
  long-lived `claude` process against the installed 2.1.267 binary, without the duplicate-`.jsonl`
  bug (`anthropics/claude-code#5034`) corrupting the persisted session log?
- **A2** — does a `PreToolUse` matcher shaped `mcp__<server>__.*` actually intercept a tool call on
  a *second* MCP server, the way the shipped `"Bash"` matcher does for the permission server?
- **A3** — does a hook `deny` on an MCP tool call surface to the model as an actionable refusal it
  can recover from, or does it end the stream?

Plus the phase's two standing non-code actions: the heartbeat cadence question (`05-RESEARCH.md`
Open Question 3 — an authoring run sits idle while a human thinks, and `HEARTBEAT_STALE_MS` is
15,000 ms) and the Nimbalyst re-scout `STATE.md` has carried as a blocker since the roadmap was
written.

Purpose: every downstream plan in this phase reads one recorded decision instead of guessing.
Output: two throwaway-but-tracked harnesses, one findings document, one competitive re-scout.
</objective>

Create `scripts/spike/authoring-transport-spike.mjs`, a standalone Node ESM script (no build step,
run directly with `node`) that drives the installed `claude` binary through a fixed four-turn
conversation in both candidate transports and writes its measurements into
`.planning/phases/05-socratic-epic-authoring/05-SPIKE-FINDINGS.md`.

Two modes, selected by `--transport=a` / `--transport=b`:

- **Option A** — one long-lived child: spawn `claude` with `--input-format stream-json` alongside
  the existing mandatory argv (`-p`, `--output-format stream-json`, `--verbose`,
  `--permission-mode`), keep stdin open, and write one JSON line per user turn. The exact user
  message shape is the thing under measurement: try the documented `{"type":"user","message":
  {"role":"user","content":[{"type":"text","text":"..."}]}}` envelope first and record verbatim
  what the binary accepted or rejected, including its stderr.
- **Option B** — one child per turn: spawn `claude -p <prompt>` per turn with the
  conversation-so-far folded into the prompt, matching `buildClaudeArgv`'s existing argv exactly and
  adding nothing new.

Per transport, record: whether each of the four turns produced an assistant reply; wall-clock
milliseconds per turn; total `cost_usd` and token counts from the terminal `result` event; and the
duplicate-entry check — count how many persisted log lines share an identical `(type, message.id)`
pair, which is the observable shape of `anthropics/claude-code#5034`.

Add a `--self-test` mode that runs with **no** `claude` binary: it asserts the argv this script
builds for each transport, asserts the duplicate-detection function flags a hand-built duplicate
pair and passes a clean pair, and exits 0. `--self-test` must never spawn a child process.

Add a `--heartbeat-idle=<ms>` measurement to Option A's run: after turn two, hold the process idle
for the requested window with a production-cadence heartbeat writer running (mirroring
`scripts/uat`'s `--touch-heartbeat` on `HEARTBEAT_TICK_MS`), then send turn three and record whether
it was answered. This is `05-RESEARCH.md` Open Question 3 measured rather than assumed;
`runtime_protocol.rs`'s `HEARTBEAT_STALE_MS` is 15,000 ms and a human reading a challenge will
exceed that.

Create `.planning/phases/05-socratic-epic-authoring/05-SPIKE-FINDINGS.md` and write into it: a
`claude_version:` line carrying the output of `claude --version`; the per-transport measurement
table; a `heartbeat_verdict:` line; and a `transport_decision:` line whose value is exactly
`option-a` or `option-b`.

The decision rule is mechanical, written into the document above the line so no later reader has to
re-judge it: **choose `option-a` if and only if all four turns were answered AND the duplicate-entry
count is zero; otherwise `option-b`.** Record the rule and the measurement that selected it.

State once, in the findings document, the invariant that keeps this fork from rippling into the
schema: **one authoring conversation is one `agent_runs` row regardless of transport** — under
Option B the follow-up turns are further child processes inside the same run, never additional runs.
That is what keeps D-84's "an epic-authoring session IS an `agent_run`" literally true either way,
and it is the reason plans 05-02 onward do not branch on this decision.

It stands up a **throwaway second MCP server** — a minimal stdio server registered under the server

It writes a per-run `--settings` file carrying **two** `PreToolUse` entries — the existing
`matcher: "Bash"` entry pointing at `pretoolUseHookScriptPath()`, and a new entry whose `matcher` is
`mcp__flywheel-authoring-spike__propose_.*` pointing at a tiny inline hook script the spike itself

`propose_task_spike` immediately, and records three facts:

- **A2 answer** — did the hook script run at all for the MCP tool call? Measured by the hook writing
  a marker file, and cross-checked against whether the spike MCP server's own tool handler recorded
  an invocation. The gate holds only if the hook ran AND the tool handler did not.
- **A3 answer** — after the denial, did the session continue and produce at least one further
  assistant turn, or did the stream terminate? Record the terminal event verbatim.
- **The denial's visible shape** — whatever text the model produced in response, quoted, so plan
  05-03 writes a reason string that is actually actionable rather than guessing.

matcher (`read_epic_spike`) must execute normally. Without that control, "the hook ran" is
indistinguishable from "everything is being denied", which is exactly the fail-shape Phase 3's own
