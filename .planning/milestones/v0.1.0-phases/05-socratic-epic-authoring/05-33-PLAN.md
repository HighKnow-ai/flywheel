<objective>
Separate config isolation from credential availability in the live acceptance arm, so the arm can
authenticate as the developer whose machine it runs on — using that developer's existing claude.ai
subscription login — while the developer's personal behavioural configuration stays out of the
session under test.

This is gap G-05-6's BLOCKER (`05-UAT.md`, third gap). The live arm currently points
`CLAUDE_CONFIG_DIR` at a scratch directory and asserts nothing in the spawn env reaches the
developer's personal `~/.claude`. Claude Code stores the OAuth credential under that same
directory, so today isolation and authentication are one switch, and SHAPE-01's and SHAPE-03's
live judgements are UNREACHABLE rather than merely unspent.

**The seam is real and was measured, not assumed.** A scratch `CLAUDE_CONFIG_DIR` containing only a
symbolic link named `.credentials.json`, pointing at the developer's own file, reports
`{"loggedIn": true, "authMethod": "claude.ai", "configDirectory": "<the scratch dir>"}` — the
credential is presented, and settings/skills/memory still resolve against the scratch directory.
The same directory with nothing linked reports `{"loggedIn": false, "authMethod": "none"}`. Both
readings were taken directly, cost nothing, and are the ground truth this plan implements against.

Purpose: make the live judgement reachable at all, without an API key and without leaking the
developer's config into the run under test — and make the credential path VISIBLE in the evidence,
because the project's only live run that ever reached the API (ledger row `05-22-03`) must have
authenticated via an API key and nothing recorded which path was in play.
Output: a composed, content-asserted config directory; a pre-spawn authentication precondition that
fails fast with a named cause; and a credential-path record in the run's own evidence.
</objective>

<measured_ground_truth>
Read this section before writing any code. Every line was measured directly on this machine on
2026-09-25, at zero credential cost, and none of it is inference.

1. `claude auth status` prints JSON on stdout. With the developer's ordinary environment it returns
   `loggedIn` true, `authMethod` `claude.ai`, `apiProvider` `firstParty`, `configDirectory`
   `/Users/<user>/.claude`, and ALSO `email`, `orgId` and `orgName` — real identity fields that
   must never be persisted anywhere by this harness.
2. With `CLAUDE_CONFIG_DIR` pointed at an empty scratch directory, the same command returns
   `loggedIn` false and `authMethod` `none`.
3. With `CLAUDE_CONFIG_DIR` pointed at a scratch directory containing ONE entry — a symbolic link
   named `.credentials.json` whose target is the developer's own `~/.claude/.credentials.json` —
   the same command returns `loggedIn` true, `authMethod` `claude.ai`, and `configDirectory` equal
   to the scratch directory. That is the whole seam: one credential file, referenced not copied.
4. The developer's personal configuration directory on this machine contains, among other entries:
   `settings.json`, `skills`, `agents`, `hooks`, `plugins`, `commands` may or may not be present,
   `.claude.json`, `projects`, `sessions`. None of these is the credential. `CLAUDE.md` is absent
   on this machine but is the canonical user-memory filename and must still be denied.
5. Running `claude` against an empty scratch config directory creates `.claude.json`, `backups`,
   `projects` and `sessions` inside it by itself. The isolation assertion must therefore check for
   entries the harness LINKED or that the developer's own config would supply — it must not fail on
   directories the backend creates for itself inside the scratch root.
</measured_ground_truth>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| harness process → developer's personal configuration directory | The harness reads the developer's own filesystem to reference a credential. It must reference, never ingest. |
| composed config directory → spawned backend process | Everything in this directory becomes the session-under-test's behavioural configuration. Anything personal that lands here contaminates every SHAPE judgement. |
| auth-status payload → evidence artifacts and the repository | The payload carries real identity fields. The repository is a git repository that will be pushed. |
| spawn environment → backend credential resolution | Whatever authenticates here determines the billing and identity path, which the locked decision constrains. |
