<objective>
**As a** solo developer running a fleet of agents, **I want to** have the agent propose the whole
shape of an epic — its tasks, its criteria and the assumptions it challenged — and look things up on
my board while it does, **so that** its challenges are about what actually exists rather than
generic.

Plan 05-02 proved one tool through the seam. This plan builds the rest of it: the six write tools
D-81's verb set needs, the three capped read tools D-87 calls for, and D-89's distillation — the act
of advancing out of the challenge stage is what makes the agent write out what it challenged and
what it was told.

Two things about the read path are deliberate rather than incidental. It reuses the permission
gate's own request-and-answer shape over the per-run socket, so there is still exactly one channel
between the MCP server and the supervisor. And the sidecar still never opens the database file —
every read is answered by the Rust core, which is the one process that owns the connection
(`ARCHITECTURE.md` Anti-Pattern 3).

Purpose: give the session everything it needs to shape an epic, without giving it anything it could
use to write one.
Output: six write tools, three read tools, the distillation turn, and the decision relay that makes
a rejection a turn in the conversation rather than a silent verdict.
</objective>

Server-side scoping, in `sidecar.rs`'s handler: resolve the run's `project_id` from the `agent_runs`

prompt-enforced, and "not found" rather than "forbidden" is the right answer because the difference

Bounding: each tool's `inputSchema` declares `limit` as an optional integer with a documented
maximum, and every handler passes it through `query::authoring`'s clamp. No handler may pass
`i64::MAX`, omit the parameter, or call anything outside `query::authoring`. Pitfall 4 names both

Add a bounded response too: a read that would return more rows than the clamp allows returns the
clamped page **plus** a `truncated` flag and the true total, so the model is told it is looking at a
page rather than silently believing it saw everything. A model that thinks it has seen the whole
board will confidently tell the developer no duplicate epic exists.

**(b) Distillation on advance (D-89).** Extend `domain::authoring_session::advance_stage` so that
advancing **out of** `challenge` returns, alongside the new stage, a distillation instruction the
command layer sends as an `authoring_turn`. The instruction asks the agent to call

inside another row's field.** `PITFALLS.md`'s pitfall 3 states the general rule this is an instance

The instruction must also say what the distilled rows are *for*: they are a draft of the reasoning
the developer will accept, amend or reject, and a later session will be primed with the accepted
ones. That framing is what makes a distilled record acceptable at all — D-89's own sentence is that
the model's reading of the conversation must be **correctable rather than authoritative**, and the
tool call is a proposal like every other, going through the same path.

Distillation is a request, not a precondition: the stage advances whether or not the agent answers.
A stage machine that cannot move because a model declined to emit a row is a worse failure than a
thin assumption record, and D-90 gives the developer the gate unconditionally.

**(c) A decision is a turn (D-93/D-94).** Add `send_decision_turn`-shaped handling so that when the
developer rejects a proposal (optionally with a reason) or amends one before accepting, the running
session is told: which proposal, what happened, and the reason or the developer's replacement text.
Plan 05-06 owns the decision write path and calls into this; this task owns the relay and the turn's
wording. Two rules the wording must carry: a rejection is an invitation to propose something better,
not a verdict to argue with; and an amendment is the developer's own text, which the next batch of
drafts should move toward rather than repeat past.

If the session is no longer running, the relay is a no-op that records why — a decision made after
the conversation ended is an ordinary board edit, not a lost message, and it must not surface as an
error to the developer.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model → write tool arguments | Model-authored arguments reach a staging write path |
| model → read tool arguments | Model-authored ids and search terms reach the board's query layer |
| MCP server process → sidecar → Rust core | A read request crosses two process boundaries before a row is returned |
| supervisor → running session | Developer decisions and distillation instructions are injected into a live model conversation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05-01 | Spoofing / Elevation of Privilege | write-tool arguments | high | mitigate | No write tool declares a `run_id`, `project_id` or `epic_id` schema property; identity comes from the socket and the `agent_runs` row; a grep gate asserts no such property string exists in the server source |
| T-05-05-02 | Elevation of Privilege | `amend_proposal` / `delete_proposal` targeting another epic's row | high | mitigate | The supervisor resolves the run's project and epic scope and rejects a `target_id` outside it; the proposal is staged regardless and still requires human acceptance, so the verb is never itself destructive |
| T-05-05-03 | Information Disclosure | read tools returning another project's rows | high | mitigate | The project id is resolved server-side from the run row; an out-of-scope `epic_id` returns not-found rather than forbidden, since the distinction is itself a disclosure; asserted in a Rust test |
| T-05-05-04 | Denial of Service | unbounded read tool calls | high | mitigate | Every handler calls only `query::authoring`, which clamps; grep gates forbid `i64::MAX` and `LIMIT -1` in the handler file |
| T-05-05-05 | Tampering | sidecar opening the database | high | mitigate | Grep gate asserts no database driver import and no `.db` path anywhere in `packages/sidecar/src`; reads are a round trip to the core by design |
| T-05-05-06 | Denial of Service | proposal flooding the tray | medium | accept | `ARCHITECTURE.md` §6's rate limit is Phase 6's shared mechanism for `propose_issue` and `05-CONTEXT.md` does not decide it for this phase; accepted here because an authoring session is attended — the developer is watching the tray fill in real time and holds Stop. Re-rate when Phase 6 lands the shared limiter, and when an authoring session can run unattended |
| T-05-05-07 | Tampering | injected turns reaching the wrong session | medium | mitigate | `sendAuthoringTurn` rejects an unknown run id with `UnknownRunError` before any write, reusing the guard `interruptSession`/`killSession` already apply for the same class of renderer-supplied id |
| T-05-05-SC | Tampering | npm/cargo installs | high | mitigate | No package is added by this plan; `05-RESEARCH.md`'s Package Legitimacy Audit records that this phase introduces none. An executor that finds itself needing one stops and routes back to research rather than installing |
