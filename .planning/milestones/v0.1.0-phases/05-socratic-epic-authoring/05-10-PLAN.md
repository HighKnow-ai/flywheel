<objective>
**As a** solo developer running a fleet of agents, **I want to** reopen an epic weeks later, keep
shaping it, and be argued with about the change, **so that** an epic stays a thing I thought about
rather than a thing I once thought about.

This is SHAPE-05, and it is the last of the four roadmap criteria to become reachable, because it
needs everything else: the epic packet (05-04), the rejected set (05-04), the stage machine (05-03),
the verb set (05-05), the decision paths (05-06) and the lane (05-08). What is left to build is the
door.

The plan then closes the phase honestly. `05-VALIDATION.md` is a seeded draft; `ROADMAP.md` lists
four success criteria; `REQUIREMENTS.md` has five unchecked SHAPE rows. Phase 3's own history in this
project is a long argument for not letting a ledger drift from its evidence — eight requirement rows
sat at Gaps Found through six rounds because the evidence and the ledger were maintained separately.
So the last task is the evidence, and the ledger update that matches it.

Purpose: make reopening real, and then prove the phase rather than declare it.
Output: the reopen entry points, one automated acceptance test covering all four criteria, and a live
acceptance script joining the existing UAT set.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live acceptance script → real credentials and a real repository | The script drives the developer's authenticated CLI against a scratch project |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-10-01 | Elevation of Privilege | a renderer-supplied epic id | medium | mitigate | `authoring_run_start` resolves the project from the epic row and rejects an epic outside the named project; the packet is assembled with both ids bound through `params![]` |
| T-05-10-02 | Denial of Service | two concurrent authoring sessions on one epic | medium | mitigate | The start path refuses a second run when one is already running for that epic and routes to it instead, naming the existing run |
| T-05-10-03 | Information Disclosure | the live script's scratch project | medium | mitigate | The script creates its own throwaway repository and isolated `CLAUDE_CONFIG_DIR`, following `uat-06`/`uat-07`'s established handling; it never operates on the developer's real project |
| T-05-10-04 | Denial of Service | live-run spend | low | mitigate | A fixed short conversation, a `--self-test` mode for every non-live assertion, and `run-all.sh` membership so it is run deliberately rather than on every build |
| T-05-10-05 | Repudiation | a ledger claiming evidence it does not have | medium | mitigate | Requirement statuses are updated in the same commit as the evidence and each names its supporting test; an unsupported requirement is left unchecked with the gap stated, which is the failure mode Phase 3 spent six rounds on |
