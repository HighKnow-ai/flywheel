<objective>
**As a** developer about to spend real credentials on the one check no machine can make for me,
**I want to** run one command and get a file I can read a verdict into, **so that** a genuine pass
is not misreported as a failure and the judgement does not evaporate into a terminal scrollback.

Two things block the live acceptance run, and both live in one file.

`05-REVIEW.md` WR-06, confirmed unfixed at HEAD: `criterion4Reopened` and `criterion4PrimedRejected`
(`scripts/uat/uat-08-socratic-authoring.mjs:440-479`) are declared `false` and never reassigned
anywhere in the file's control flow — by the script's own explicit design, since a single-session run
structurally cannot exercise SHAPE-05's reopen leg. They still feed the fourth row of `results`, so
`reportCriteria` always returns `allPassed = false` and the trailing `assert.ok(allPassed, …)` always
throws. The script cannot exit `0` even when SHAPE-01 through SHAPE-04 all genuinely pass. This is
the script `05-VERIFICATION.md`'s human verification #1 is supposed to be read from.

Second, the run's judgeable material — the two verbatim assistant replies — exists only as `step()`
lines on stdout and inside a timestamped JSON blob under the OS temp directory. The standing
preference is that a verification result lands in a file the next pass can read. It does not today.

The live run itself is still human-judged, and this plan does not pretend otherwise. What it does is
shrink the human residue to exactly one act: reading two verbatim replies and deciding whether the
agent pushed back. Everything around that act — staging, driving, draining, timing, counting,
formatting, persisting — is the script's job.

Purpose: make a genuine pass reportable, and make the judgement durable.
Output: an informational, non-gating SHAPE-05 line; a pure results builder; and a tracked evidence
sheet with an unfilled verdict.
</objective>
