<objective>
The instrument half of gap `G-05-8(a)`. Plan 05-41 makes the questions arrive at the seam as typed
data; this plan makes them arrive in the artefact a human reads, and makes the driver answer them so
the Socratic exchange can develop past turn one.

The live run's sheet reads *"...three things would materially change the shape of the spec:"* and
then *"You didn't pick — no problem."* Between those two lines, three questions with fifteen options
existed on the wire and were thrown away. SHAPE-01's verdict is *"did the agent push back on the
stated premise?"* — and the evidence of the push-back was the part that went missing.

Purpose: `scripts/uat/README.md` Item 8 records, as a standing rule, that an offline arm only proves
a property if it exercises the same code path, in the same order, with the same inputs the live arm
will hit. This plan therefore routes every evidence-sheet exchange through ONE builder the offline
scenario and the live arm both call, rather than proving the new rendering against a hand-assembled
parallel.
Output: a named zero-token replay scenario, a driver that answers an offered option, and a sheet
that carries the questions.
</objective>

<wr01_scope_note>
`05-REVIEW.md` WR-01 records that the live arm's own `try/catch/finally` — the 337-line inline
callback that is the fix for `G-05-7` finding 1 — is executed by no automated command. The gap
contract for this round says WR-01 may be folded in ONLY if the `G-05-8(a)` fix already requires
touching that seam, and that the reason must be stated rather than left as scope creep.

It does. Rendering the questions means adding a field to the agent-exchange object, and that object
is constructed by nine separate literal expressions spread across `driveChallengeConversation`,
`runReplayCheckScenario`'s scenario branches, and the live arm's inline callback — including two on
timeout/recovery paths that only run when something has already gone wrong. Adding the field at nine
sites by hand is how the duplicate-turn defect `README` Item 8 records as NF-01 happened.

So this plan extracts exactly one thing — `buildAgentExchange` — and routes every capture site
through it. That is the narrowest structural change that makes the new property provable through the
same path the live arm uses.

**WR-01 remains OPEN after this plan.** The live arm's callback is still not invoked by any
automated command; the full extraction WR-01 asks for is not attempted here. The claim made is
narrow and must stay narrow: the property this round ADDS is not one of the things WR-01 leaves
unproven.
</wr01_scope_note>
