<objective>
`isAttemptRefused` (`scripts/uat/uat-08-socratic-authoring.mjs:2218-2233`, inside
`readNoWorkPlanned:2179-2236`) scans forward from `attempt.index + 1` for the first subsequent
`tool_result` in the window, independently for every attempt, tracking nothing. Two `propose_*`
calls issued back-to-back — one turn carrying two `tool_use` blocks before either is answered, an
ordinary Claude Code shape — make the second attempt's scan start on the exact index the first
attempt's scan already consumed. If that shared result reads as a refusal, both attempts read
refused and the second attempt's own later, unrefused answer is never reached. The reading returns
`"refused"` where `"violated"` is correct: a **vacuous SHAPE-01 pass**, certifying the one outcome
SHAPE-01 must never certify.

This is the fifth consecutive round in which this phase has shipped a criterion that cannot report a
genuine result, always in the same narrow region of code. Two facts make this instance worse than
its predecessors, and this plan is shaped around both:

1. **The collision is the DEFAULT on a live wire, not an edge case.**
   `packages/sidecar/src/claude-code-adapter.ts:598-600` normalises every `tool_result` as
   `{ ...base, type: "tool_result", output: toolResult.text }` — with **no `toolName`**, because the
   CLI's own `stream-json` `tool_result` block carries a `tool_use_id`, not a tool name. So the
   name-based exclusion inside `isAttemptRefused` can never fire on a real run. Positional
   correlation is the only correlation available, which makes claiming indices mandatory rather than
   an optimisation. (Observation only — `packages/` is out of scope for this round and is not
   touched; the harness must simply be correct for the shape the wire actually produces.)

2. **The 05-23 executor met this exact ambiguity and resolved it by editing the FIXTURE.**
   `05-23-SUMMARY.md`'s own "Issues Encountered" records that an earlier draft of the
   order-independence self-test "turned out to let both attempts converge on the same later
   `tool_result`" and was corrected with a wrong-tool-name exclusion. The ambiguity was the finding;
   it was filed as a fixture note instead.

Purpose: make the attempt→answer pairing one-to-one, make that pairing directly observable, and
prove it end to end offline on the shape the live wire actually produces — with the pre-fix reading
asserted beside it so the regression keeps its teeth.
Output: a claimed-index correlation promoted to its own named pure function, an eighth scripted
scenario driven through the real sidecar, and self-tests covering the shape five rounds of tests
never constructed.
</objective>
