<objective>
Close gap `G-05-7`'s second finding: the live arm failed a healthy turn.

Turn 1 of live run `01M3C48C3PV1NSGHERBZ587YB1` exceeded a 120000ms wall-clock bound. This was not a
stall. The separate idle guard never fired, and the captured event list shows unbroken activity to
the deadline — roughly sixty tool-call/tool-result pairs, several board-read round trips and repeated
permission drains. The backend is `claude-opus-5` doing genuine exploratory tool work on its first
turn. The bound was calibrated against a scripted fake whose turns are instant.

There is a second, sharper mechanism underneath. Plan 05-25 correctly stood the idle window DOWN
while a tool call is outstanding — a turn mid-flight on a tool is provably working — and named the
trade in its own doc comment: in that state the wall-clock deadline becomes the only backstop. The
real run spent essentially its whole first turn in exactly that state, so the trade was taken
continuously and the wall clock was the only thing that could fire. The fix is not a bigger number:
it is to give the mid-flight state its own finite idle bound, so the turn is bounded by SILENCE in
every state rather than by a budget in one of them.

This plan also honours a constraint the gap report imposes and the evidence limits: any surviving
wall-clock ceiling must carry its derivation beside it, and the only derivation available is a LOWER
bound. No upper bound was ever observed, because the instrument stopped the run. A closure that
writes a larger number and calls it calibrated would be this phase's defect class in its purest form.

Purpose: the next live run must not be killed for working.
Output: idle-primary turn bounds with a finite mid-flight window, reasoning counted as progress, a
wall-clock ceiling that states what it is and is not, and offline proof of each.
</objective>

<measured_ground_truth>
Read this before choosing any number. These are the only measurements this repository has, and the
third one is the reason this plan is written the way it is.

1. **The turn was still working at the bound.** Live run `01M3C48C3PV1NSGHERBZ587YB1`, backend
   `claude-opus-5`, turn 1. At 120000ms the event list held roughly 130 entries: about sixty
   tool-call/tool-result pairs, several board-read round trips, repeated permission drains, and two
   captured assistant text chunks totalling 539 characters. Nothing about it reads as a stall.

2. **The idle guard never fired.** `LIVE_TURN_IDLE_MS` is 30000ms and no idle window elapsed across
   the whole 120000ms. Between the mid-flight stand-down and genuine continuous activity, the turn
   was never silent for thirty seconds.

3. **120000ms is a LOWER bound, not a completion time.** The run did not finish; the instrument
   killed it. No upper bound on a real first turn exists anywhere in this repository, and none can be
   produced without spending a credential. Every constant this plan writes must be justified against
   that fact and must say so in the source.

4. **A derivable upper bound on the mid-flight gap DOES exist.** All ~130 events fit inside 120000ms,
   so no single interval between consecutive events of that turn can have been 120000ms or longer.
   That is a real derivation from the record, not an estimate, and it is what makes a finite
   mid-flight idle bound defensible without a new measurement.

5. **`waitForTurn`'s progress tuple has three members today** — the chunk count, the tool-call count
   and the pending-tool-call count — all returned by `accumulateTurn`. A reasoning event advances
   none of them, so once plan 05-37 models reasoning, a long reasoning stretch with no tool
   outstanding would arm the idle timer and could conclude a turn the model is actively working on.
   That is a new hazard created by the previous plan and must be closed here, in the same round.

6. **`accumulateTurn` has no branch for the reasoning event.** It will simply skip it, exactly as it
   skips every unlisted type today — so nothing is broken by plan 05-37 landing first, and this plan
   is where the branch belongs.
</measured_ground_truth>
