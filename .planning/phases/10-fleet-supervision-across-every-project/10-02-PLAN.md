  <behavior>
    - A child that exits successfully in the same instant its deadline expires is reported with its real exit status and its captured stdout, not as a timeout.
    - A child that exits with a non-zero status at the deadline is reported with that non-zero status, not as a timeout.
    - A child that genuinely never exits is still killed and still reported as a timeout — the fix narrows the misreport, it does not remove the ceiling.
    - The kill path still terminates the whole process group, so the existing no-orphan guarantee is unchanged.
  </behavior>
  <action>
Fix the deadline race at its root: `output_with_timeout` in `packages/core/src/proc.rs`. Per RESEARCH
Finding 12, this function wraps **git and forge subprocesses**, not agent-run terminal status — so the
todo's framing is wider than the defect. Its real reach in this phase is the porcelain read and
`git worktree remove` inside the inventory and reclaim paths, where a spurious timeout refuses a legitimate
reclaim or mislabels a clean worktree.

The fix is one extra non-blocking `try_wait` **before** the kill: when the deadline elapses, check once
whether the child has already exited; if it has, take its real status and its captured output and return
that outcome instead of constructing a timeout. Only when `try_wait` reports the child still running does
the existing kill-the-process-group path run and the timeout outcome stand. Do not change the timeout
constant, do not change the kill mechanics, and do not add a grace sleep — the single `try_wait` is the
whole change, and it must be reached by every caller rather than guarded behind a new parameter, because
the lazy fix here is also the root-cause fix: one check inside the shared function covers every call site
at once.

`packages/core/tests/proc_timeout_boundary.rs` (new). Drive a real child process, in the idiom
`git_retry.rs` already uses for this. Three cases: a child instructed to sleep for just under the deadline
and then exit zero, asserted to report success; the same shape exiting non-zero, asserted to report that
status; and a child that never exits, asserted to still report a timeout and to leave no surviving process.
Keep the deadline in the test small by passing an explicit short timeout rather than waiting on the
production ceiling.
  </action>
  <acceptance_criteria>
    - `output_with_timeout` contains exactly one `try_wait` call, placed before the kill, on the deadline-elapsed path.
    - A child exiting zero at the deadline returns an outcome carrying exit status zero and its stdout; the test asserts on the status, not on the absence of a timeout flag.
    - A child exiting non-zero at the deadline returns that exit status.
    - A child that never exits still returns the timeout outcome and the test observes no surviving child.
    - `cargo test -p core --test proc_timeout_boundary --test git_retry --test lock_contention` passes, so the change is proven not to disturb the retry and contention behaviour built on this function.
  </acceptance_criteria>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| supervisor → child subprocess | `output_with_timeout` interprets what a git or forge child did; a wrong interpretation becomes a wrong refusal or a wrong board fact. |
| agent process → sidecar stream parser | Stream lines are model-produced data; the normaliser decides what reaches the session log and the fleet. |
| scheduler → repository filesystem | A per-tick `git remote get-url origin` spawn runs while the database mutex is held. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-02-01 | Repudiation | `proc::output_with_timeout` | medium | mitigate | One `try_wait` before the kill, so the reported status is the observed one; the three-case regression test pins success, non-zero and genuine-hang |
| T-10-02-02 | Information disclosure | `normaliseStreamEvents` | low | accept | The new events carry the same payloads the single-event path already emitted to the same consumers; no new field and no new sink is introduced, so the existing redaction boundary is unchanged |
| T-10-02-03 | Denial of service | `scheduler::forge_tick_targets` | medium | mitigate | Memoise the failure arm so the spawn count per tick is bounded by project count, not worktree count, and log once per project per tick |
| T-10-02-04 | Tampering | the deadline-race fix's reach | medium | mitigate | The guard lives inside the shared function so every caller is covered at once; `git_retry`, `lock_contention` and `crash_safety` are run as regression gates rather than trusting the local diff |
| T-10-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed in this plan |

**Canon referral:** subprocess argument injection and timeout-based resource exhaustion are canon
constraints owned by this register and by `security_enforcement`; they are not minted as bespoke
prohibitions in `must_haves`.
