<objective>
**As a** developer, **I want to** see that a proposal restates something my board already carries —
or something I already rejected — before I read it as new, **so that** the queue is not where the
same finding arrives for the fourth time in different words.

PROP-04 says duplicates are flagged *before being surfaced*. D-107 makes that literal: the flag is
written in the same transaction that stages the row, so the queue is never in a state where a
proposal is visible and unflagged. D-105 picks FTS5 `bm25` over the indexes Phase 1 already ships,
and D-106 widens the corpus to include the decided rows D-83 keeps forever — a re-proposed rejected
idea being the most irritating duplicate there is.

Purpose: make the duplicate flag a stored, deterministic, testable fact with a measured threshold.
Output: `authoring_proposals_fts`, `query::search::duplicate_candidate_for`, the measured
`DUPLICATE_BM25_THRESHOLD`, and the two columns filled at staging time.
</objective>
