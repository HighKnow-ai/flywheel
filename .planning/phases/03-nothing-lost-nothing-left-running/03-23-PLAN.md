<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| other local accounts -> the permission socket in `/tmp` | The socket answers whether a destructive git or rm command may run; `/tmp` is world-listable, so the filename's randomness no longer restricts who can find it |
| `FLYWHEEL_APP_DATA_DIR` -> the fleet database and runtime directory | An env-supplied value becomes the write target for the store of record, its backups, and every runtime descriptor and kill record |
| resolved orphan -> leftover runtime files | Files written by a run that has been resolved, left readable on disk after the decision that ended it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-23-01 | Elevation of privilege | `mcp-permission-server.ts` socket under `/tmp` | medium | mitigate | Task 1 sets the socket file to owner-only immediately after `listen` succeeds, so a second local account cannot connect to the channel that decides whether a destructive command runs (WR-01) |
| T-03-23-02 | Tampering | `app_data_dir` accepting a relative override | medium | mitigate | Task 2 rejects a non-empty relative value with a named error, so the fleet database cannot be redirected into a working directory the caller did not intend (WR-02) |
| T-03-23-03 | Denial of service | Task 1's hardening throwing out of `startPermissionServer` | high | mitigate | The `chmod` is wrapped so a failure degrades to the previous mode rather than throwing; `startSession` cannot recover from a throw here without refusing a whole session, which would be a worse outcome than the warning being fixed |
| T-03-23-04 | Information disclosure | Lifecycle timeline surviving a resolved run | low | mitigate | Task 3 adds it to `clear_run_runtime_files`, so it is removed by the same orphan-resolution path that already removes the descriptor, kill record and contention log |
| T-03-23-05 | Denial of service | Task 2 newly rejecting a value an existing harness relies on | medium | mitigate | Task 2's action requires grepping every workspace location that sets the variable and confirming each is absolute, and its verify runs the full workspace test suite as the guard |
| T-03-23-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install task exists in this plan — `fs.chmodSync`, `anyhow::ensure!` and `PathBuf::is_absolute` are all already available. If execution finds an install is needed, halt and route through the package-legitimacy gate rather than installing |
</threat_model>
