<objective>
Put the two recovery surfaces in front of the user: the blocking one for a process still spending
money, and the quiet one for a run the app died under (PROC-04, PROC-05, D-46, D-49, D-50).

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

Purpose: success criterion 3 — "User relaunches after a crash and is shown every orphaned process,
every in-flight run ... and decides what happens to each." D-46's framing is the sentence to design
against and it comes from the phase's own title: **Nothing Lost can wait; Nothing Left Running
cannot.** Only the second earns a modal. A run stuck at `running` with no process behind it lands as
a persistent item the user resolves at their own pace, reusing D-37's mechanism rather than
inventing a second one.
Output: `OrphanRecoveryModal`, the `run-abandoned` badge and acknowledgment row, and the
`agent_run_acknowledge` command.
</objective>

properties of that component, and the cleanest way to guarantee this overlay has neither is not to

path).

Focus on mount goes to the first row's Kill button, not to Kill All — a stray Enter should resolve
one process, not all of them, mirroring `DeleteConfirm.tsx`'s own instinct of never auto-focusing the

The panel is 560px wide, centred, `--surface-secondary` background, `--radius-chrome`. Inside:
the heading (`type-heading`), the row list, the Kill All action, and the footer note (`type-micro`,
`--text-muted-rack`). The row list sits in a container with `overflowY: "auto"` and a max height so
the panel cannot grow past the viewport on a machine that somehow accumulated many orphans.
