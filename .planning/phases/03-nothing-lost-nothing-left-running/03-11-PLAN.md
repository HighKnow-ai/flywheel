<objective>
Roll both quiet recovery items up to where the user will actually see them: the board row and the
project rail (D-46, WORK-06, PROC-05).

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

Purpose: D-46 splits recovery into two tiers, and this is the non-blocking one. A missing worktree
and an abandoned run both "land as a persistent 'needs you' item that survives dismissal, reusing
D-37's board-visible-state-plus-project-rail-count mechanism rather than inventing a second one."
Plans 03-09 and 03-10 built the two places a user resolves such an item; without this plan a user
who never opens those panels never learns the items exist.
Output: the `recovery-needed` mark, the row pill, the rail badge, and the core read path behind them.
</objective>

`pub fn recovery_task_ids_for_project(conn: &Connection, project_id: &str) -> anyhow::Result<Vec<String>>`
runs ONE compile-time-literal SQL statement with a single bound parameter — no `format!`, per the
Phase 1 rule. The statement is a `UNION` of two selects over the same project: task ids whose
`worktrees.status = 'missing'`, and task ids whose `agent_runs.status = 'abandoned'` and
`agent_runs.acknowledged_at IS NULL`. `UNION` (not `UNION ALL`) is what makes a task with both
conditions appear exactly once, which is the de-duplication the `<behavior>` list requires — say so
in a comment so a later reader does not "optimise" it to `UNION ALL`.

`pub fn recovery_count_for_project(conn: &Connection, project_id: &str) -> anyhow::Result<i64>`
counts over the same union rather than counting rows in either table, so the count and the set can
never disagree.

Note deliberately: this rollup does NOT require the abandoned run to be the task's *most recent* run.
A task whose latest run completed cleanly but whose earlier run was abandoned and never acknowledged
still has something the user has not seen, and D-46's item is about the user having seen it. State
that reading in a comment, because it is a judgement call a reader could otherwise mistake for a bug.
