<objective>
Make the worktree surfaces keep their own stated guarantees.

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

**User story (MVP framing):** **As a** developer looking at a task whose worktree Flywheel says is
gone, **I want to** be offered only the two decisions that make sense — recreate it, or forget it —
and never a Remove Worktree button for something that is not there, **so that** the screen's
account of reality is one I can act on without checking it myself.

Purpose. Two confirmed defects, both in files this phase changed:

1. `WorktreeRemovalDialog.tsx`'s `handleRemove` guards on `removeState.removing` alone. Three
   separate plans in this phase independently diagnosed this exact React defect and fixed it with a
   `useRef` (`WorktreeSummary.tsx`'s `actingRef`, `RunsSection.tsx`'s `ackActingRef`), each
   recording in STATE.md that a real failing test found it: two synchronous clicks both observe the
   same stale state before the first re-render flushes the `disabled` attribute. This file's only
   `useRef` is a focus ref. The removal itself is safe — `remove_worktree_for_task` re-reads
   `git status --porcelain` on every call and has no force parameter at any layer — but a second
   identical IPC command is still issued.

2. `WorktreeSummary.tsx`'s missing-worktree early return is gated on `summary.status === "missing"
   && isNonEmptyString(summary.path)`. The file's own doc comment says something different and
   stronger: "When `summary.status === 'missing'` this REPLACES the branch/path row and the Remove
   Worktree action entirely… the early return IS the guarantee." With an empty or null `path`,
   execution falls through to the ordinary render and exposes Remove Worktree on a row Flywheel
   believes is missing from disk — the exact affordance the early return exists to make
   unreachable. Nothing is destroyed (there is nothing on disk to remove), but the screen offers a
   decision that contradicts what it just said.

Output: the guard, the corrected early return with honest copy for the pathless case, and tests for
both.
</objective>

## Trust Boundaries

No data loss is possible — `remove_worktree_for_task` re-reads `git status --porcelain` on every call and takes no force parameter at any layer (D-43) — but the duplicate can surface a spurious failure on a removal that succeeded. Task 1's ref removes the duplicate. |
| T-03-18-02 | Spoofing | the missing-worktree early return in `WorktreeSummary.tsx` | medium | mitigate | A row Flywheel has just declared missing from disk simultaneously offers Remove Worktree, contradicting its own statement and inviting an action against a state the screen says does not exist.
