<objective>
Close the gap nothing covers today: the **sidecar itself** dying. Every `claude` session is spawned
`detached: true` as its own process-group leader — deliberately, so `killSession` can signal exactly
one session's subtree — which also means it is in no group the sidecar's death would reach, and
macOS has no `PDEATHSIG`. This plan builds D-47's heartbeat-plus-watchdog, D-48's no-grace kill and
D-50's on-disk kill record.

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

Purpose: success criterion 2 — "User quits the application while a session is running and no agent
process survives — confirmed in the OS process table — including when the supervisor is killed
rather than closed cleanly." `RunEvent::Exit`'s existing `shutdown_all_sessions()`-then-`kill()`
sequence (CR-02) covers a clean quit; a SIGKILL never fires `RunEvent::Exit` at all, and this is the
only net behind it.
Output: `packages/core/src/runtime_protocol.rs`, `packages/sidecar/src/watchdog.ts`, and the
on-disk record `packages/core`'s launch reconciler (plan 03-06) reads at next launch.
</objective>

**Evaluated honestly against the real phase scope:**

1. **The matched signal is a false positive.** "multiple git versions" is a statement about test
   *coverage breadth*, not about a domain noun losing its monopoly. No identity generalises there.
   **Decision: `no-change`.**

2. **A genuine delta exists elsewhere in this phase, and this plan is where it lands.** Phase 2's
   working identity was *"the `claude` child process IS the session's process group leader, and
   `session.child.pid` is the pid every signal targets."* Inserting the watchdog wrapper breaks that
   monopoly: the wrapper becomes the group leader and `claude` becomes one member of the group.
   **Decision: `promote`.** The primary noun becomes **the session's process group, led by its
   watchdog**; `the claude child process` is demoted to *one member of that group* — a detail of one
   variant, not the thing the supervisor tracks. Rationale for promoting rather than adding
   alongside: `interruptSession`/`killSession` already signal `-pid` (the negation of the group
   leader's pid), so the group — not the backend process — was always the real referent; Phase 2
   simply had one member in it. Adding a second concept alongside would leave two competing answers
   to "what does Stop signal?", which is precisely the failure RESEARCH.md's Pitfall 4 names.
   Every task below is written against the promoted noun, and Task 3 asserts it.
</assumption_delta_decision>

Create `packages/sidecar/src/watchdog.ts`, compiled by the sidecar's existing `tsc` build into
`dist/watchdog.js`.

Its `main()` reads `FLYWHEEL_RUNTIME_DIR`, `FLYWHEEL_HEARTBEAT_STALE_MS` and
`FLYWHEEL_HEARTBEAT_POLL_MS` from `process.env`, and the run id from a `FLYWHEEL_RUN_ID` entry the

session is exactly what this phase exists to prevent, so a misconfigured wrapper must never

and **no `detached` flag** — the wrapper was already made a group leader by its own parent's
`detached: true`, and a second `detached` here would fork a second, unreachable group (the exact
failure RESEARCH.md's Pitfall 4 names). Pipe the child's stdout and stderr straight through to the
wrapper's own with `child.stdout.pipe(process.stdout)` and the equivalent for stderr.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| supervisor → watchdog | configuration crosses as environment variables into a process running in the agent's own worktree |
| watchdog → filesystem | the watchdog writes kill records the launch reconciler later trusts |
| watchdog → OS signals | the watchdog can terminate a whole process group |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02-01 | Denial of Service | watchdog staleness threshold | high | mitigate | `HEARTBEAT_STALE_MS` is set to more than seven touch intervals so a momentarily-slow supervisor cannot trigger a kill; the value is one named constant with its tradeoff documented (Task 1) |
| T-03-02-02 | Elevation of Privilege | a session that unsets `FLYWHEEL_RUNTIME_DIR` to escape supervision | high | mitigate | The watchdog fails closed — missing configuration exits non-zero BEFORE spawning the backend, so an unsupervised session cannot be produced by removing a variable (Task 2) |
| T-03-02-03 | Tampering | kill records written into a directory the agent's worktree process can also reach | medium | accept | The runtime directory lives in app-data outside every worktree; an agent that can already write there has the user's full filesystem rights, which is outside this phase's trust model.
