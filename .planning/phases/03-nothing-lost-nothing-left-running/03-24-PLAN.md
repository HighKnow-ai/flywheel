<objective>
Close the destructive-gate bypass class by making the hook's `safe` branch prove what its non-safe
branch has already proved since plan 03-19.

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

**Requirement (quoted verbatim from REQUIREMENTS.md):** **AGNT-07** — "Destructive actions
(force-push, branch deletion, recursive delete) always require explicit confirmation, even when the
session is running in an auto-accept permission mode."

**User story:** **As a** developer running an agent in auto-accept mode, **I want to** know that a
destructive command cannot slip past the gate just because it was wrapped in `sh -c`, **so that**
"always require explicit confirmation" means always — not "always, unless the launcher shifted the
program name one token to the right."

Purpose. `03-DESTRUCTIVE-GATE-BYPASS-CLASS.md` records eight ordinary launcher idioms that all
classify `{"category":"safe"}` against the compiled binary at HEAD, and four prior rounds of fixes
that each taught the classifier one more wrapper token without addressing the shape. The decisive
fact, verified in code rather than inferred: `pretooluse-hook.ts`'s **non-safe** branch already
demands a two-fact proof before it defers — `invokedBareName && shimWillIntercept(program)`. Its
**safe** branch demands nothing and short-circuits to `{}`. That asymmetry is the finding, and
D-59 closes it in that one branch rather than in the classifier's token list.

Output. Three changes, one vertical path:

1. The shim's `--classify-invocation` safe verdict carries the two text facts the hook needs to
   apply D-61 — it already computes one of them and throws it away for safe commands.
2. The hook's safe branch establishes the environment proof (D-59/D-60) and applies the D-61 rule.
3. One end-to-end row set, asserted through the REAL compiled hook against the REAL compiled shim
   binary, proving the path works in both a proven and an unprovable environment.

**This is the tracer slice.** It is production quality, not a prototype: the same `<verify>` and
the same fail-closed discipline as any shipped task, and it is the skeleton plans 03-25 through
03-28 expand from. After it, a real user running an agent in a misconfigured session gets a refusal
instead of a silent bypass — a capability that does not exist today.

**What this plan deliberately does NOT do.** It adds no launcher token to
`resolve_segment_program_index` and does not widen `destructive::classify`'s `git`/`rm` dispatch.
D-59 rejected the first as round 5 of enumerate-and-hope and deferred the second as a product-scope
decision with its own named trigger.
</objective>

    ASCII alphanumeric or underscore. That boundary rule is what keeps `digit`, `legitimate`,
    `format` and `warm` from matching while `sh -c 'git push'`, `.gitignore`, `/usr/bin/git`,
