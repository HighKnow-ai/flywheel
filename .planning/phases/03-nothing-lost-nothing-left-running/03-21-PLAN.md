<objective>
Prove the half of Success Criterion 5 that `03-VERIFICATION.md` left open: that a destructive
permission request stays answerable long enough for a human to actually answer it, and that the
answer is honoured when it arrives.

Purpose: the gap is not "the request is never raised" — that half is verified closed. The gap is
"the session stays blocked until a human answers", which five prior live measurements could not
demonstrate. This plan's acceptance test is the same on both outcomes of plan 03-20's investigation,
which is what makes the plan executable either way: if the terminating behaviour was a condition of
the measurement rather than of the product, the acceptance run passes with no source change and the
gap closes by evidence; if it was a product defect, the acceptance run fails until the branch named
by 03-20's disposition is applied, and then passes.

Output: a repeatable sixty-second-latency acceptance run; whatever source change the recorded
disposition indicates (possibly none, stated explicitly); and a PROC-04 regression guard proving a
pending question never buys an unsupervised agent extra life.
</objective>
