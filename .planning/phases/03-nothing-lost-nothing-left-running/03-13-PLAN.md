<objective>
Make lock contention legible without making it noisy (WORK-04, D-53, D-19).

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

Purpose: D-53's exact split. A collision that resolves in 200ms is noise — writing an event for it
puts clutter in the activity trail the user reads to understand the task. A retry sequence taking
visible wall-clock time IS worth showing, because the agent's own tool-call row is otherwise sitting
apparently idle and a slow commit must not read as a hang. And an exhausted budget is a real failure
that must not be indistinguishable from an ordinary agent error — PITFALLS' warning sign is
"failures correlated with wave width, not task content", and that needs a number you can look at.
Output: the notice relay, the transient feed row, and the one trail entry exhaustion produces.

Neither surface is a new visual component: `03-UI-SPEC.md` is explicit that the retry row reuses the
existing system/transient feed-row kind and the exhaustion entry reuses the existing Activity Trail.
This plan therefore adds no new mark, no new token and no `DESIGN.md` entry.
</objective>
