<objective>
Find out which mechanism ends a real `claude` session roughly 15-16 seconds after a destructive-gate
permission request is raised and left unanswered — by building an instrument that *discriminates*
between the candidate mechanisms, validating that instrument against three deliberately-induced
endings whose cause is already known, and only then pointing it at the unknown.

Purpose: `03-VERIFICATION.md`'s single open gap names two deliverables. This plan is the first: a
dedicated spike, run with Claude Code's configuration isolated from the developer's personal
`~/.claude`, that identifies why the session terminates — or proves it does not reproduce in a
config-isolated, production-shaped run. The plan does not presuppose a fix in any file. Its
deliverable is an attributed timeline and an honest disposition; either outcome is legitimate.

Output: close-provenance instrumentation in the watchdog and the adapter; a validated three-way
discrimination test; a clean-room live harness that measures the scenario twice (supervised and
unsupervised) and writes a durable timeline; and `03-SESSION-LIFECYCLE-FINDINGS.md` recording the
disposition of four named hypotheses against the signals that decided each one.
</objective>

| agent -> Bash tool -> PATH shim -> permission socket | An untrusted model-issued command crosses into a process that can mutate the repository; the socket is what decides whether it runs |
