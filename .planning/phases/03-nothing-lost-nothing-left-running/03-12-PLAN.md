<objective>
Give the destructive-action gate a card a user cannot approve by reflex (AGNT-07, D-55, D-56, D-57,
D-58).

**Phase goal (quoted verbatim from ROADMAP.md):** "Cyril can quit, crash or interrupt Flywheel at
any moment and know that no uncommitted work was destroyed and no agent is still spending his
money."

Purpose: success criterion 5's human half. Plan 03-07 made a destructive command stop and wait; this
plan is what the user sees when it does. The load-bearing decision is the reversed button emphasis:
rather than fighting approve-by-muscle-memory with a delay or a typed confirmation — both considered
and rejected in the UI-SPEC on the same "rigidity is the feature, friction is not" reasoning that
settled D-43 — the reflex is **repurposed**. The filled button, the one a hand goes to without
reading, is Deny.
Output: the `destructive-gate` mark, the card variant, and the read path that carries the category
to it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent-supplied command text → the card's DOM | fully untrusted text is rendered to the user who is deciding about it |
| category value → which layout renders | a database value selects between a strong and a weak treatment |
| renderer → answer command | a decision that can allow a destructive operation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-12-01 | Elevation of Privilege | an unrecognised category falling through to the routine Allow-primary layout | high | mitigate | The consequence lookup falls back to the uncategorized sentence and the variant selection keys off "category is non-null", not off a known-key match; a test with an unknown string asserts the strong treatment renders (Task 2) |
| T-03-12-02 | Elevation of Privilege | a standing grant reachable from the destructive card | high | mitigate | The allow-always button is conditionally absent from the tree, not disabled; a source gate rejects a disabled-attribute implementation and an exhaustive test covers all eight category values (Tasks 2, 3) |
| T-03-12-03 | Spoofing | a command crafted to read as harmless in the card while being destructive | medium | mitigate | The consequence sentence is generated from the CLASSIFIED category, not from the command text, so the sentence cannot be authored by the agent; the raw payload is shown beneath it as corroboration rather than as the primary claim (Task 2) |
| T-03-12-04 | Information Disclosure | agent-supplied text rendered into the DOM | medium | mitigate | Every interpolated value renders as a React text node and the payload keeps the existing `<pre>` treatment; no `dangerouslySetInnerHTML` is introduced anywhere in this plan |
| T-03-12-05 | Repudiation | a card that clears optimistically on a failed answer | medium | mitigate | The existing `RowState` pattern keeps the card mounted and unanswered on a rejection; this variant reuses the same `answer()` function rather than forking it (Task 2) |
