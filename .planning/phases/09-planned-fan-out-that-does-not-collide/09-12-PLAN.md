<objective>
Gap closure for `09-VERIFICATION.md` gap 2 (register **D-REV-37**), its first `missing` item, and the
foundation plan 09-13 needs for the third.

The phase goal says parallelism is "bounded by real file-set disjointness rather than optimism". The
verification's finding is that "bounded" is enforced at ONE choke point — `dispatch::readiness` — which
only the dispatcher consults, and that the launch body both callers share checks nothing. This plan makes
the rule a callable thing instead of a private loop, and proves the window.

## The mechanism choice, made deliberately

The gap's `missing` list offers three mechanisms. They are not equivalent and this plan does not take all
three.

**Rejected: a partial unique index on `agent_runs(task_id)` for running and blocked.** It is the only
option that would be structurally enforced by the schema, and it is the wrong tool twice over. First, it
cannot express the invariant in question: the invariant is disjointness between two DIFFERENT tasks' file
sets, a cross-row predicate over a child table, which no uniqueness constraint can state. The index would
only prevent two live runs of the SAME task — a real but different defect. Second, it would make a known,
explicitly out-of-scope defect permanent: `09-REVIEW.md` WR-03 (register D-REV-39) leaks an abandoned
`running` row, and today that costs one cap slot, while under a unique index it would make that task
permanently unlaunchable with no in-app repair. Buying a narrow guarantee with a one-way door that
sharpens a defect we are not allowed to fix here is a bad trade. The same-task protection is taken instead
as a code guard in plan 09-13, where it is cheap and reversible.

**Taken: one rule, one implementation, called at both the decision and the launch.** The loop inside
`readiness` already is the rule. Extracting it costs almost nothing, leaves the dispatcher's verdicts
identical (32 + 8 existing tests are the proof), and gives plan 09-13 something to call from the shared
launch body — which is the single place all launch callers route through, so one guard there covers the
dispatcher, a user's own launch and any future caller. That is the smaller diff AND the root-cause fix.

Purpose: a re-check is code a fourth caller could bypass, and that is a fair criticism of it. The answer is
not a schema change that cannot state the rule; it is to put the one check where every caller already
passes through, and to say so in the function's own doc comment.

Output: the rule, extracted and called; and the first test of the decide-to-launch window.

**Not in this plan:** the launch-body call site and the manual-launch disposition (plan 09-13), and the
declare path (plan 09-11). Out of scope per the phase's scope fence: D-REV-39, D-REV-41, D-REV-42,
D-REV-32 through D-REV-36.
