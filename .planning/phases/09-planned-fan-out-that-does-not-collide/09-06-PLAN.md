the hook exists to close — it would let one agent's declared set grow underneath a sibling already running
against those files. The re-check is the load-bearing half, and it has to run inside the same transaction
as the write.

Output: `widen_file_set` with the in-flight re-check, the human-only widen command, the board aggregate
command, the feed row with its action, and the task-row badge registered in the legend.

In `packages/core/src/domain/file_set.rs`, add `EVENT_FILE_SET_WIDENED: &str = "task.file_set_widened"` and
`widen_file_set(conn, task_id, raw_entry, actor_id) -> anyhow::Result<WidenOutcome>`.

Order of operations, and the ordering is the whole point:

1. Parse the raw entry through `flywheel_core::file_set::parse_entry`. A refusal returns the named cause
   and stops — the widen path validates exactly as the declare path does, with no second vocabulary.
2. Open the transaction.
3. **Inside that transaction**, read `dispatch::in_flight_declared_sets` for the task's project and run
   `overlaps` of the candidate entry against every entry of every other in-flight armed task. On any
   collision, roll back and return a refusal naming the colliding path and the other task's key. Doing the
   re-check inside the write transaction is what stops two concurrent widens from both succeeding into each
   other; a check before the transaction is a race with a nice comment on it.
4. On no collision, insert the entry row and append the widen event carrying the previous and new entry
   lists in the established payload idiom, then commit.
5. **After** the commit, rewrite the run's scope marker through `write_scope_marker`. The marker is read
   fresh on every tool call, so this is the whole of "takes effect on the next tool call" — no restart, no
   session reconstitution, no signal to the agent process. The atomic write is what keeps the hook from
   ever observing a torn file. A marker-rewrite failure after a committed widen is reported to the caller
   as a partial outcome naming what succeeded, never swallowed: the database says the set is wider and the
   enforcement layer does not yet agree, and the user needs to know which.
