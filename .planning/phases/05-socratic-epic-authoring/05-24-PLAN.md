<objective>
The one authorised live run of this phase (`01M399FP80B184QM2RXTXJDZTK`, 2026-09-24T08:48:54.481Z)
did not fail on CR-01 — it never got that far. Turn 3 of its captured transcript is an Anthropic
API-level safety-classifier refusal on the distillation-instruction turn, and `waitForTurn` captured
it as ordinary agent text (`chars=432 endedBy=result`). The harness then sat waiting 120 seconds for
a proposal that was never going to arrive, and the run died reporting the wrong thing about itself.

That is a **fourth** instrument-failure class, outside the three this phase has already made
self-naming: it is not a starved held request (05-18), not a turn-capture timeout (05-20 — the turn
ended cleanly on `result`, not a deadline rejection), and not a propose-reading misread (05-21 —
`unproven` was the objectively correct reading, because no model turn ever happened). Plan 05-22
deliberately did not patch it; it diagnosed it, recorded it red in `05-VALIDATION.md`'s `05-22-03`
row, and left it for a fresh gap. This is that gap.

Reading the same transcript also surfaced a second, previously unreported defect in the artefact a
human is asked to judge: turns 2 and 3 of that sheet are byte-identical. The live body captures the
first agent turn, then hands `driveChallengeConversation` the SAME seed cursor, so the driver
re-reads that identical turn and records it a second time. The offline arms never caught it because
they assemble their exchange list a different way from the live arm — the classic shape where the
thing under test and the thing being tested are not the same thing.

Purpose: make the next live run fail loudly at the moment of refusal instead of quietly at the
proposal deadline, and make the transcript it leaves behind an honest record of one conversation
rather than a duplicated one.
Output: a named fourth failure class detected by a pure function, proven offline against a scripted
refusal; a fail-fast in both places a refusal can land; and one shared transcript-assembly path.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend error text → the agent-turn stream | The CLI renders an API-level refusal in the same `assistant_text` shape a real model turn uses, and terminates it with a genuine `result` line. The event stream cannot distinguish them; only the text can. |
