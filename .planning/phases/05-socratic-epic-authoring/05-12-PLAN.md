<objective>
**As a** solo developer shaping an epic, **I want to** say what I want to build and answer the
agent's challenges inside the app, **so that** the Socratic conversation this phase exists to
create can actually happen.

Gap **G-05-2**: the shipped app has no human-turn surface. Three independent confirmations, all
measured: `session/SessionSurface.tsx` contains zero text-entry elements; the renderer's whole
authoring command surface (`adapters/tauri.ts` plus the direct calls in `authoring/useAuthoringQuery.ts`)
is start + stage + proposal verbs with nothing carrying text; and `send_authoring_turn`
(`sidecar.rs:460`) has exactly three call sites — `commands/authoring.rs:650`, `:699` and `:745` —
all system-generated relays. The two text channels that do exist, a rejection reason and an
amendment, both require staged proposals, which only appear after the developer has already advanced
out of `challenge`. So the challenge stage — the stage the whole phase is about — has no human
channel at all.

Everything downstream of a turn already works and is covered by passing tests: the stage gate, the
six write tools, the three capped read tools, the tray's four verbs, the distillation relay. The gap
is the one seam between the developer and the conversation. This plan builds that seam, leading with
a tracer that carries one typed line all the way from a keystroke to the live session's stdin before
anything else is widened.

Two constraints shape it. `adapters/tauri.ts`'s single-seam rule — no component reaches the
transport directly — is an existing gate in this phase's own tests, and the composer must respect
it. And the bare-key Advance binding in the `session-surface` region (`state/keyboard.ts:177`) must
not fire while the developer is typing: `resolveBinding` already settles that ambiguity through
`isTypingTarget` (`keyboard.ts:234`), so this plan confirms it with a test rather than reinventing
it.

D-90 survives untouched: only the human advances the stage, and this command cannot. D-88 survives
untouched: a turn is not a proposal, and nothing here reaches a proposal-writing tool.

Purpose: give the developer a voice in a conversation the app already knows how to hold.
Output: one command, one wrapper, one composer, a transcript that records both sides.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → Tauri command surface | The composer's text is renderer-supplied input crossing into the Rust core; it is then written to a live model process's stdin. |
| Rust core → sidecar → `claude` child stdin | A relayed turn becomes model input; it must not be able to carry a capability the stage gate withholds. |
| sidecar stdout → session log path | Event lines carry a `runId` that is joined into a filesystem path. |
