<objective>
Three closures of this phase have now each ended the same way: a finding written into
`scripts/uat/README.md` Item 8 so the next author inherits a rule instead of a fourth instance. This
is the fourth, and it is the most instructive of the four, because every defect it closed was
introduced or missed by a closure that had already learned the lesson one level up.

`G-05-2` established the rule that every property a live script asserts must be provable without a
live run. That rule was followed — and CR-01 still shipped, because the offline arm that "proved"
the propose reading called it at a point in the run where the contamination could not yet exist. The
turn-duplication defect (NF-01, plan 05-24) survived for the same reason: the offline arm assembled
its transcript a different way from the live arm, so it was green about code the live arm does not
run. And WR-04 survived because no fixture in the repository could express a mid-turn pause at all.

So the rule needs sharpening, not replacing: **a property is provable offline only if the offline
arm exercises the same code path, in the same order, with the same inputs the live arm will hit.**
An offline arm that takes a shortcut around the live arm's own assembly, or that asserts a reading
at a point the live arm does not assert it, is not a proof — it is a second implementation that
happens to be green.

Purpose: leave the next author a sharper rule than the one that was not enough, and leave the ledger
and the record telling the truth about what has and has not been measured.
Output: a fourth finding and a sharpened rule in Item 8, a ledger row per task in this closure, and
an honest resolution of the todo that a prior SUMMARY said would be filed.
</objective>
