<objective>
`uat-08`'s live arm is the only instrument that can put a real Socratic challenge transcript in front
of a human, and it dies mid-conversation. The agent authenticates, replies once, makes tool calls,
issues a `board_read_request` — and stops. Not because the product is wrong: the desktop app answers
that request at `commands::authoring::handle_inbound_board_read_request`. Because the UAT harness
stands in for the Rust core on the sidecar's stdio protocol and implements only HALF of that role.
It drains `permission_request`. It has never heard of `board_read_request`. A board read is
DELIBERATELY held open until answered, so an unanswered one starves the session outright.

This plan gives the harness the other half of the role it was already playing, and does it by
generalising the role rather than bolting a second bespoke drain next to the first.

Purpose: make the live instrument able to finish a run, so SHAPE-01's dialogue quality can finally
be judged by a person.
Output: one board-read dispatch in the core called by both the desktop app and the harness bridge, a
generalised inbound-request drain in the harness, and a starvation class that reports itself by name.
</objective>

<assumption_delta_decision>
**The noun that is now primary:** *an inbound request the sidecar holds open until the core answers
it* — of which a permission request is one variant and a board read is another.

**Decision: `promote`.**

`scripts/uat/lib/sidecar-harness.mjs` was written when the harness had exactly ONE inbound role to
play on the core's behalf, so it named that role directly: `drainIncidentalPermissionRequests`. That
singular assumption is now false — `permission_answer` and `authoring_read_answer` are already
siblings on the same socket in `packages/sidecar/src/index.ts`, and the failure mode when either is
unanswered is identical and silent.

So the generalised loop becomes primary: `drainInboundCoreRequests`, dispatching by event type over a
declared `HELD_INBOUND_REQUEST_TYPES` list, with one answering handler per kind.
`drainIncidentalPermissionRequests` is DEMOTED to a thin preset over it — same signature, same
observable behaviour, so `uat-06`, `uat-07` and `uat-08`'s own existing self-test assertions keep
their present meaning and none of them is edited. Adding a second bespoke drain alongside the first
would have left the singular assumption in place and guaranteed a third round of this same gap.

The promote is enforced, not just intended: Task 3 adds an invariant check asserting that the number
of held kinds the harness can answer equals the number of answering ops the sidecar exposes, so a
future third kind cannot silently reintroduce the starvation.
</assumption_delta_decision>
