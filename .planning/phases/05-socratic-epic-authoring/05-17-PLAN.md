<objective>
**As a** developer deciding whether this surface earned its place, **I want to** run one command per
arm and get one file holding both numbers and the verdict, **so that** the phase's founding question
is answered by measurement rather than by recollection.

Two items in `05-VERIFICATION.md` are still `human_needed`, and `workflow.human_verify_mode` is
`end-of-phase`, so they belong here rather than as mid-plan checkpoints.

The first is live challenge quality. `05-16-PLAN.md` made the script able to report a pass and made
it write the two verbatim replies to a fixed path; what remains is one person reading them.

The second is the Product Kill Criterion. Plan 05-13 built the in-app measurement instrument
(`uat_authoring_ops measure-run`) and wrote the protocol into `05-SPIKE-FINDINGS.md`, but the
comparison has never been run, and the protocol as written is a hand-run procedure: find a run id on
a UI surface, hold a stopwatch, hand-time the terminal arm, hand-count what it produced, transcribe
the lot into a document. That is a conversational checklist wearing a protocol's clothes, and it is
why the measurement has never happened.

Almost all of it is instrumentable. The in-app arm's elapsed span is already on the board —
`measure_authoring_run` returns `elapsedMinutes` from the run's own start to its last acceptance,
conversation latency included, which is precisely what the protocol's stopwatch was approximating.
The run id can come from a read-only board query instead of a URL. The terminal arm's clock can be
the instrument's own. The terminal arm's item counts are board rows entered through quick-add, so
they are a before-and-after difference of a count the harness can already take. The verdict is a
two-clause rule the criterion states verbatim.

What is left for a human: performing the terminal arm at human pace, and reading two transcripts.
Both are named precisely below, each with one line saying why no script can do it.

Purpose: turn a hand-run protocol into two commands and one file.
Output: two read-only board instruments, a comparison script with an offline self-test, and a
validation ledger that points at commands instead of procedures.
</objective>

    - `computeKillCriterionVerdict(inApp, terminal)` returning an object carrying the in-app
      amendment rate, the minutes delta, and a verdict that is one of `option-a`, `option-b` or
      `indeterminate`. The rule is the criterion's own, applied literally: `option-b` only when the
      in-app arm's minutes are STRICTLY GREATER than the terminal arm's AND the in-app amendment

      `indeterminate` when the in-app arm accepted fewer than three task proposals (the protocol's
      own validity bar), when it accepted zero criterion proposals (the rate is undefined, and a
      division must not be performed), or when either arm's minutes are missing. An indeterminate
      result must never fall through to `option-a`.

      verdict the function did not compute.
