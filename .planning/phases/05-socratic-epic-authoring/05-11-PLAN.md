<objective>
**As a** solo developer judging whether the challenge stage really is Socratic, **I want to** run
the phase's live acceptance script and read the transcript it prints, **so that** the one judgement
no structural check can make is actually available to make.

Gap **G-05-1**: `scripts/uat/uat-08-socratic-authoring.mjs`'s live arm starves. A real `claude`
session performs its own git housekeeping at startup, outside the agent's visible Bash tool loop;
that housekeeping still resolves through the PATH-shimmed directory and still reaches the shim's
destructive gate, so it raises `permission_request` events nobody answers. Every sibling live script
drains them — `uat-06-permission-block-lifecycle.mjs:193`, `uat-07-launcher-shape-gate.mjs:164`, and
`uat-03-destructive-gate.mjs:98` with its own local copy. uat-08 is the one that does not: its
import block (`:35-42`) pulls six names and `drainIncidentalPermissionRequests` is not among them.
The measured consequence, 2026-09-24: a 120s timeout with eight unanswered `permission_request`
events and zero `assistant_text`.

This is a harness defect, not a production one. The desktop app answers these at the window through
`agent_run_answer_permission` and `session/PermissionRequestCard.tsx`. Nothing under `packages/`
changes in this plan.

The fix is small; the discipline around it is not. The loop must be proven offline — the reason the
defect survived review at all is that `--self-test` was green while the live arm had never run end
to end, and the ledger recorded that green as the task's evidence. So this plan wires the drain,
proves the loop with no child process, and then corrects the ledger to say what the evidence covers.

Purpose: make the live arm capable of completing, and stop the ledger from overstating what ran.
Output: a live arm that answers startup permission requests, an offline proof of the drain loop, a
documented item 8, and a validation row that matches its evidence.
</objective>
