<objective>
Six consecutive gap-closure rounds have found the same defect class — a criterion that cannot
report a genuine result — every time inside `readNoWorkPlanned`'s attempt/answer correlation, and
every time the fix narrowed a positional heuristic by one more shape. This plan stops narrowing it
and deletes it.

The correlation has been reconstructing, by positional inference, a fact the wire already carries
explicitly: the Anthropic stream puts `id` on every `tool_use` block and `tool_use_id` on every
`tool_result` block. `claude-code-adapter.ts` declares its content blocks without either field, so
the adapter cannot read them, so `ToolResultEvent` carries no correlation key at all, so the
harness scans by position — and every positional scheme is ambiguous on some ordinary wire shape.

Purpose: make the correlation EXACT BY CONSTRUCTION, so the defect class becomes unreachable
rather than narrowed a seventh time. The codebase already contains the pattern — `PermissionRequestEvent`
carries an explicit correlation id end to end, for exactly this reason, and says so in its own doc
comment. Tool results never got the same treatment.

Output: the wire's own correlation id carried through the adapter seam onto both tool events; the
positional scan replaced by a map lookup; an explicit, rated decision about what happens when the
id is absent; and the interleaved-read shape from `05-VERIFICATION.md`'s gap proven correct end to
end, offline, through the real sidecar and the real shipped normaliser.
</objective>
