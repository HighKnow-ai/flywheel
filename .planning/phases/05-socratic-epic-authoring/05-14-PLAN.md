<objective>
**As a** developer typing into a live authoring conversation, **I want to** see in the transcript
only the turns that actually reached the agent, **so that** the transcript is a record of the
conversation rather than a record of my keystrokes.

This is the phase's one failed must-have truth (`05-VERIFICATION.md` truth #7, `05-REVIEW.md` CR-01),
independently re-confirmed at HEAD. `SidecarHandle::send_authoring_turn`
(`packages/desktop/src-tauri/src/sidecar.rs:507-523`) calls `record_authoring_turn` — which persists
a `developer_turn` line to the session log and emits it on `agent:event` — unconditionally, before
it ever attempts `send_request`. Both delivery failure modes are reachable: the handle's `child` is
`None`, or the write to the child's stdin fails because the `claude` process has already exited
while `agent_runs.status` has not yet transitioned. When delivery fails the transcript either
permanently shows a message the agent never received, with no marker, or the documented retry path
mints a second row for one logical turn. That falsifies plan 05-12's own declared must-have.

It also carries WR-04, which lives in the same function family: `record_authoring_turn`'s persist
failure reaches only `eprintln!`, while every other persist-failure path in this file routes through
`emit_persistence_failure_notice` so PROC-07's "the live feed never silently drops output" holds.

No test covers any of this today. The only Rust tests touching this code
(`authoring_turn_line_carries_type_run_id_text_and_origin`, `two_builder_calls_...`) exercise the
pure `build_authoring_turn_line`, and `authoring-composer.test.tsx` mocks `sendAuthoringTurn` at the
`adapters/tauri.ts` boundary, so it never reaches Rust at all. The fix therefore needs the ordering
correction and the first-ever failure-path coverage, and the coverage comes first.

Purpose: make the transcript a record of delivered turns, and prove it on the failure path.
Output: a delivery-gated turn seam, a visible persist failure, and four tests that fail before the
fix.
</objective>

**Noun now primary:** the `developer_turn` transcript row.
**Decision:** `promote` — the row is defined as naming a **delivered** turn (one the transport
accepted), not an **attempted** one.
**Rationale:** the two candidate fixes the verification offered encode opposite identities; choosing
"delivered" makes the reorder sufficient and keeps the line format untouched, whereas "attempted"
would require a delivery-status field on the line and a renderer that renders three states.

first phase where an agent writes structured items to the board"): both are historical narrative in
the Phase 5 roadmap prose about work that already shipped. Neither is a singular→plural transition
introduced by this round. **Decision:** `no-change` — no architecture change is manufactured to
satisfy the checkpoint.
