<objective>
**As a** developer who stops or discards a session, **I want to** be certain the session's narrative is on
the board before the run is marked terminal, **so that** throwing away a context never throws away what
that context learned.

Gap #1 from `04-VERIFICATION.md`. The append-only summary guarantee (CTX-01, roadmap Success Criterion 1)
holds on the natural-close path, where `apply_session_closed` owns ONE transaction covering both
`close_agent_run_in_tx` and the presence-checked fallback insert. It does NOT hold on the Stop/Discard
path added by plan 04-13: `stop_agent_run_recording_first` writes the terminal status through
`interrupt_agent_run` — which opens and commits its OWN transaction — and then opens a SECOND,
independent transaction for the fallback summary. A crash, force-quit or SQLite I/O error between the two
commits leaves the run permanently terminal with `exit_summary_id` NULL and no `session_summaries` row.
Because `session_summaries` is append-only and nothing backfills a missing summary for an
already-terminal run, that session's narrative is then silently and permanently absent from every future
context packet for the task — which is the exact failure the phase goal exists to make impossible.

This plan closes it by mirroring the pattern this crate already documents as deliberate: a
`interrupt_agent_run_in_tx` sibling to `close_agent_run_in_tx`, and one transaction around both writes.

Purpose: CTX-01, roadmap Success Criterion 1.
Output: the termination unit becomes atomic, and a regression assertion exists that the pre-fix shape
cannot satisfy.

**Scope discipline.** This plan touches ONLY the Stop/Discard termination path and its assertions. It does
not change `close_agent_run_in_tx`, `apply_session_closed`, `create_summary`, `synthesize_fallback_summary`
or any UI. The warnings `04-VERIFICATION.md` lists as out of scope (unbounded `SUMMARIES_SQL`,
`delete_criterion` orphaning, the sidecar `liveSessions` map, the `abandonedReason` field name) are NOT
addressed here.

**Explicit deliberate exclusion — `mark_abandoned`.** `packages/core/src/domain/agent_run.rs`'s
`mark_abandoned` is a THIRD path to a terminal status (the launch reconciler's verb for runs whose app
died). It also opens its own transaction and writes no summary. `04-VERIFICATION.md` does not name it as a
gap, so this plan does NOT change it and the Task 2 invariant assertion is deliberately scoped to the two
paths the verifier named — natural close and Stop/Discard. Stating this rather than silently widening or
silently omitting: a reconciler writing a terminal status for a process nobody observed dying is a
different question (there may be no session worth summarizing at all), and answering it belongs to a
phase that can reason about it, not to a gap-closure run.
</objective>

<assumption_delta_decision>
The deterministic detector flagged a `pluralization` signal on the term `fallback`. The seam it points at
is real: this codebase now has TWO paths to a terminal `agent_runs` status that must each be composed with
a fallback-summary write — natural close (`apply_session_closed` → `close_agent_run_in_tx`) and interrupt
(`stop_agent_run_recording_first` → `interrupt_agent_run`) — and only the first is atomic.

- **Primary noun:** *terminal transition of an agent run*, of which natural-close and interrupt are two
  variants. `close_agent_run_in_tx` is no longer "the" terminal write; it is one variant of it.
- **Decision:** `add-alongside`. We add `interrupt_agent_run_in_tx` beside `close_agent_run_in_tx` rather
  than promoting both into one `terminate_agent_run_in_tx(tx, run_id, variant, …)`. Rationale: the two
  variants genuinely differ in four dimensions (event type `agent_run.closed` vs `agent_run.interrupted`;
  payload label; whether `cost_usd`/`tokens_in`/`tokens_out` are written; whether an already-terminal
  guard applies), so a promoted function would need a variant parameter carrying an event type, a label
  strategy and a guard flag — a real refactor of `close_agent_run_in_tx`, which is proven, heavily tested
  and explicitly out of this gap's scope.
- **Accepted debt, and what would force a promote:** a THIRD variant. `mark_abandoned` is already that
  third path in shape, though not in the fallback-summary contract (see the objective's deliberate
  exclusion). The moment a phase decides an abandoned run also owes the board a summary, three
  independently-composed terminal writes exist and the generalized `terminate_agent_run_in_tx` becomes
  the correct move. Task 3's structural gate is what makes that moment visible instead of silent.
- **Reversibility:** `costly` — `interrupt_agent_run_in_tx` becomes the shape every future terminal path
  copies, and promoting later means touching both already-tested variants. Not `one-way`: nothing outside
  this workspace consumes it, so no `checkpoint:decision` is inserted.
- **Companion contract test:** adopted, as Task 2's `a_terminal_transition_never_commits_without_a_summary`
  — scoped to the two named variants per the exclusion above.
</assumption_delta_decision>
