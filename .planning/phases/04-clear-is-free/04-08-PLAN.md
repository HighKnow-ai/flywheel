<objective>
**As a** developer reading a briefing before spending tokens on it, **I want to** see exactly which
summaries are being carried word-for-word and exactly where folding begins, **so that** I can tell
whether the next session is still being told what matters.

Plan 04-05 built the fold as a pure function with no caller. This plan gives it one: the packet
computes its own boundary, the rendered prompt splits prior sessions into a folded region and a
verbatim region with the boundary stated between them, and the desktop DTO carries the counts and
ranges so plan 04-09's launch sheet can render the marker without re-deriving anything.

Purpose: turn CTX-05 from a function that exists into a property the agent and the developer both
observe. Output: `ContextPacket.compaction`, the restructured prior-sessions section, and two new DTO
shapes.

**The acceptance test for this plan, in one sentence:** the boundary must be statable as arithmetic —
*summaries 1-4 are folded, 5-9 are verbatim* — not as a heuristic.
</objective>

Wire the fold into the packet and into the prompt.

In `packages/core/src/context_packet.rs`, add `pub compaction: CompactionBoundary` to `ContextPacket`,
placed immediately after `summaries`. Populate it inside `assemble_context_packet` by calling
`crate::compaction::compact_summaries(&summaries)` and taking the returned history's `boundary`. This
is a pure fold over data the function already holds — no query, no I/O — so the file's header contract
is untouched. Keep the full `summaries` list on the packet as well: the drift detectors in plan 04-11
and the accumulated decisions list from plan 04-06 both need every summary, and the fold is a
presentation of that list rather than a replacement for it. Say so in the field's doc comment.

Restructure `render_prompt`'s `## Prior Sessions` section. Call `compact_summaries` once at the top of
the section and branch on whether anything folded:

- **Nothing folded** (five or fewer summaries): emit exactly the flat list the section emits today —
  no subsection headings, no boundary line. This keeps the common early-life case uncluttered and
  keeps the omit-rather-than-emit rule intact.
- **Something folded**: emit `### Earlier sessions (folded)\n\n` followed by one block per folded
  entry rendering **only** its ordinal, its `auto_generated` marker when set, its changed-file paths
  as a comma-separated `Changed:` line, and its decision entries as `- [<id>] <statement>` bullets.
  Nothing else — the narrative fields are not on `CompactedSummary` at all, so there is nothing to
  accidentally include. Then emit the boundary sentence from `CompactionBoundary::boundary_sentence()`
  as its own paragraph. Then emit `### Recent sessions (verbatim)\n\n` followed by the existing full
  blocks for the verbatim entries.

Render folded entries oldest-first and verbatim entries oldest-first, so the whole section still reads
in chronological order across the boundary.

Extend `packages/core/tests/context_packet.rs` with the eight behaviours above as named tests, reusing
the file's own `with_scratch_worktree_root` helper and `common::seeded_git_project` fixture. For the
