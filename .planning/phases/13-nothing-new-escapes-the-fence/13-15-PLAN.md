<objective>
Close criterion 5's second clause — "a board change wakes only the readers it affects, observable as
an event in one project no longer re-fetching an unrelated project's views" (FNC-07) — at all 29
production subscriber sites instead of one.

Purpose: the mechanism is right and well tested. The Rust side emits `{projectId, entity, id}` from
one helper, and `useBoardChangedSubscription` routes on it with eight test cases proving zero
`invalidateQueries` for a foreign project. What is missing is adoption: 28 of 29 subscribers ignore
the payload and refetch on every event, including `useChangeFlags(projectId)` where each refresh
spawns git. The lazy fix here IS the root-cause fix: one shared hook that owns the routing decision,
so 28 hand-edited call sites cannot drift apart from each other or from the central one.
Output: one routing decision, 29 sites routed through it, a gate that keeps it that way, and the
account-wide dispatch regression this phase introduced closed.
