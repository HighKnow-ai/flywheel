## Phase goal

**Goal (ROADMAP, verbatim):** Every structural guarantee the milestone is about to lean on is
closed-world and asserted *before* the first new record type exists — the spine cannot erode, an
unclassified table fails the build, authority is reachable only from a human, the context packet is
bounded, and the fields nobody reads are gone rather than drafted.

> MVP note: the ROADMAP Goal line is not in user-story form and no story was invented. See 13-01.

<objective>
Close the world over the schema. FNC-01 pins the three spine tables' DDL so they cannot erode while
records are added above them, and FNC-02 replaces the no-promotion gate's hardcoded four table names
with a classification list checked against the live `sqlite_master` — so the next table is covered
by default and an unclassified one fails the build (D-22).

Depends on plan 13-03: D-14 fixes that the spine pin is written against the **post-drop** schema, so
the estimate column must be gone before the pin text is captured.

Purpose: the three new record types arriving in phases 14-18 land above a spine that cannot move
underneath them, inside a gate that already covers them.
Output: one const module in core, two new gate tests, a widened no-promotion corpus, and the folded
no-interpolated-table-name convention turned into a real gate.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a new migration -> the gate's coverage | A migration is SQL text; it reaches the database without the compiler seeing it, which is why the classification check reads `sqlite_master` and not an enum |
| an agent-staged proposal -> a canonical table | The no-promotion corpus's subject; widening the proposal vocabulary without widening the gate is the open-world hole FNC-02 closes |
