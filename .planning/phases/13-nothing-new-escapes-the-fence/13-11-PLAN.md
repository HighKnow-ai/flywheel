## Phase goal

**Goal (ROADMAP, verbatim):** Every structural guarantee the milestone is about to lean on is
closed-world and asserted *before* the first new record type exists — the spine cannot erode, an
unclassified table fails the build, authority is reachable only from a human, the context packet is
bounded, and the fields nobody reads are gone rather than drafted.

> MVP note: the ROADMAP Goal line is not in user-story form and no story was invented. See 13-01.

<objective>
F1: the fixed cap of 10 proposals per run was argued for execution runs (D-109) and now applies to
authoring runs by accident, where a legitimate epic decomposition routinely exceeds it — and the
refusal text tells the agent to call `report_summary`, a tool an authoring session does not have.
Fixing it needs a run kind, which is F6's defect: the kind is inferred from column shape in four
independent places.

F6 is fixed without a migration. The duplication is the defect, not the absence of a column: one
Rust classifier for the row-reading site and one SQL predicate const for the three SQL sites gives
the kind exactly one definition. A queryable `kind` column is deliberately not added — nothing in
v0.2.0 groups by kind, and `agent_runs` is referenced by five other tables, so a rebuild to attach a
CHECK constraint would be the most expensive way to satisfy a need no requirement has.

Purpose: criterion 6's first half, and DRFT-09 in full.
Output: one run-kind definition, a per-kind cap and refusal, an executed F1 reproduction, and the
D-109 amendment on record.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| an agent run -> the staged proposal queue | The cap is the back-pressure that stops one run accumulating a queue the developer cannot review |
