## Phase goal

**Goal (ROADMAP, verbatim):** Every structural guarantee the milestone is about to lean on is
closed-world and asserted *before* the first new record type exists — the spine cannot erode, an
unclassified table fails the build, authority is reachable only from a human, the context packet is
bounded, and the fields nobody reads are gone rather than drafted.

> MVP note: the ROADMAP Goal line is not in user-story form and no story was invented. See 13-01.

<objective>
Status stops being nudged and starts being owned. Today the forge writes forward-only on an edge and
hands the column back; `start_agent_run` writes it too, past the Phase 6 gate. After this plan
`tasks.status` has exactly one writer — a deriver reading git and forge state, attached to the
existing scheduler tick plus worktree create and remove (D-08…D-12) — F5's raw write is deleted
(D-13), and `StatusPicker.tsx` is gone so the absence of a human-reachable status write is a
deletion a gate can assert (D-19).

The one non-derivable transition, `backlog -> todo`, rides the acceptance of the task itself, which
plan 13-06 already landed.

Purpose: criterion 3's "a task's status is derived from git and forge state ... and no
agent-writable path to any other status", and DRFT-04 in full.
Output: one deriver module, two trigger points, a deleted raw write, a deleted picker, and a
two-sided gate.
</objective>

and forge facts and writes `max(candidate, current)` over the band order `backlog < todo <
in_progress < in_review < done`. `done` is terminal as a consequence of that floor, not as a
separate rule. The floor binds the deriver only: `request_changes` remains a human-only act that
lowers `in_review` to `in_progress`, and the deriver respects the lowered value afterwards (D-10,
D-11, A-03).
  </decision>

  </options>
  <recommendation>Proceed as decided. The floor is one `max` comparison and it is the only thing standing between a derivation glitch and a card moving backwards under the developer's eyes.</recommendation>
