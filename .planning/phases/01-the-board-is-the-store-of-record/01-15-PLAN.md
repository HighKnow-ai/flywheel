<objective>
Close the last third of G-01-EPIC-ASSIGN: an issue can be filed under an epic or under a task and
shows where it sits, a new task can be nested under an epic at the moment it is created, and
`.planning/REQUIREMENTS.md` can honestly claim BOARD-01 again.

Purpose: plan 01-12 built the commands, plan 01-14 made a task's epic assignable. What remains is the
issue half of the hierarchy — the live database had one issue with both `epic_id` and `task_id` NULL
because `useCreateIssue` dropped both and no reparenting affordance existed — plus the creation-time
path for tasks, which is the second half of the gap's first `missing` item. This plan also settles a
contradiction the UI-SPEC carries: its Quick-add table promises Tab nests "under the nearest epic row
above", but quick-add is pinned to the top of the Backlog band, so there is never a row above it. The
shipped behavior nests under the epic the current selection implies, and the spec is corrected to say
so rather than left describing something unreachable.

Output: the issue parenting path end to end, quick-add nesting, the corrected spec, and the restored
BOARD-01 tick with the tests behind it.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-GC-16 | Tampering | a cross-project parent reaching `issue_set_parent` or `task_create` | high | mitigate | Options are derived from the current project's loaded window only, but the authority is plan 01-12's server-side `assert_parent_in_project`, applied to both the reparenting and the creation paths — the picker and the quick-add row are conveniences, never the boundary |
| T-01-GC-17 | Tampering | an issue holding both an epic and a task parent | medium | mitigate | The renderer sends one `parentKind`/`parentId` pair, and `set_parent` writes both columns from one `IssueParent` variant in a single UPDATE, so a two-parent row is unrepresentable end to end |
| T-01-GC-18 | Elevation of Privilege | the issue parent picker as an unmodelled focus layer | medium | mitigate | It is a `PickerKind` member rather than separate overlay state, so `topLayer`'s `pickerOpen` derivation and plan 01-13's global-binding guard cover it with no further change |
| T-01-GC-19 | Denial of Service | Tab captured inside quick-add breaking region escape | medium | mitigate | Tab is intercepted only when the nesting props are supplied and an indent target exists; the Issues lane's own quick-add supplies none of them and keeps native Tab, and Escape still closes the quick-add layer through the unchanged ladder |
| T-01-GC-20 | Information Disclosure | parent option labels and the quick-add indent chip | low | accept | Every label is the item's own key and title, already rendered on the board beside it |
| T-01-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no package — no line is added to `package.json` or any `Cargo.toml`, so the package-legitimacy gate has nothing to audit |
