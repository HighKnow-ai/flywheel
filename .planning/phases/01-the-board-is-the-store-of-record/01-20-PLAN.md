<design_decision>
## Why the fixture's adequacy is an assertion, not a comment

The number that makes this suite meaningful is emergent from four separate constants that live in three
different files: `ROW_HEIGHT` (40, `BoardRow.tsx:52`), `overscan` (10, `BoardView.tsx:319`), the jsdom
viewport height (800, `test/setup.ts`) and `BAND_ORDER`'s length (5 headers, `BoardView.tsx:72`). A
comment saying "60 is enough" rots the moment any one of them moves — and the failure mode of that rot
is silent: the suite keeps passing while no longer reaching the defect. So `volume.ts` exports both the
fixture size and the estimate of what the harness can mount, and `quick-add-focus.test.tsx` carries a
self-check that fails if the margin between them disappears.

## Why `menu-bridge.test.tsx` and not another synthesized keydown

G-01-1's root cause was precisely that a synthesized webview keydown is not the path macOS takes. On
macOS the native menu owns ⌘N as an accelerator, consumes the keystroke before the webview sees it,
fires `on_menu_event`, and `main.rs` forwards the id over `menu:action`. `menu-bridge.test.tsx` is the
only suite in this repo that drives that real subscription — every other file stubs
`subscribeMenuAction` to a no-op, which is exactly why G-01-1 shipped green. The owner's G-01-4 report
came from pressing the real accelerator, so the fix has to be proven on the forwarded path, not only on
`fireEvent.keyDown(window, …)`.

That file also already renders the full `App`, so its version of the test exercises `useBoardQuery`,
`Board`, `FilterBar`, `BoardView` and the menu-layer sync together — the closest thing this repo has to
an end-to-end harness.

## Why the UI-SPEC gains a mechanism note and not just a checkmark

01-UI-SPEC.md's Keyboard Map already promises "⌘N | New task (opens quick-add, **focused**, in the
current group)". That promise was in the spec the whole time and the implementation still failed it,
because nothing recorded *how* "focused" was supposed to survive virtualization. Writing the mechanism
into the contract is what makes a future refactor of `BoardView`'s virtualization notice that it has a
promise to keep.

## Reversibility

Every change here is `reversible`: two test files, one new test-helper module, and three scoped
documentation amendments. Nothing ships to a user, nothing is persisted, no production source file is
edited by this plan at all.
</design_decision>
