<objective>
Make the board hold the whole fixed hierarchy: epics, tasks and issues created, edited and deleted,
and items moved through the five fixed states by keystroke — with the rigidity enforced by a
database CHECK constraint and one shared constant rather than by convention.

Purpose: the tracer proved one entity on one path. This plan widens it to the three-level hierarchy
`BOARD-01` requires and the fixed workflow `BOARD-04` requires, while keeping every mutation inside
the transactional-outbox shape the tracer established.

Output: a rack a user can actually run their project structure on.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → Tauri command surface | Epic, task and issue titles, descriptions and bodies cross here as untrusted strings |
| renderer's state list → schema CHECK constraint | The renderer proposes a status; the database is what accepts or rejects it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | SQL in `domain/epic.rs`, `domain/issue.rs`, `domain/task.rs` | high | mitigate | Literal statements with `params![]` bindings only; the plan 01-03 grep gate over `packages/core/src` still runs in this plan's test suite |
| T-01-15 | Tampering | status value crossing the IPC boundary | high | mitigate | The status CHECK constraint in migration 0002 is the authority; a renderer that sends an unknown state gets a database error, proved by `invalid_status_is_rejected_by_the_schema` |
| T-01-16 | Denial of Service | `delete_epic` cascade | medium | mitigate | Children are orphaned, never deleted; a grep gate fails the build if `delete_epic` issues a task delete, so an epic deletion cannot destroy unrecoverable work |
| T-01-04 | Repudiation | new command handlers | high | mitigate | Every handler resolves `actor_id` in Rust through `domain::actor`; no handler signature accepts an actor argument |
| T-01-05 | Denial of Service | title, description and body length | medium | mitigate | Each new command caps input length before calling the core |
| T-01-02 | Elevation of Privilege | `capabilities/default.json` | high | mitigate | Each command added here is named explicitly in the manifest; no blanket grant |
</threat_model>
