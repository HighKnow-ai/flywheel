<objective>
Build D-132's missing half: in epic scope the criteria rail shows the epic's own criteria **plus a
roll-up of its tasks**. 08-08 refused to improvise this under a plan that owned neither the query nor
the rail (08-08-SUMMARY Deviation 1), and 08-VERIFICATION ruled it a FAILED plan truth and logged
WINDOWS.md row 28, which blocks `/gsd-ship` while open. The user chose to build it rather than
override it.

**Goal clause this closes** (ROADMAP Phase 8 goal, clause 2): "against the acceptance criteria that
were agreed before it started" — in epic scope the reader currently sees the epic's accumulated diff
and the epic's own criteria, but nothing about where its tasks' criteria stand, which is exactly the
state you need immediately before opening the epic's request (REVW-05).

Purpose: the one surface that serves both scopes (D-132) tells the truth about both.
Output: a read-only core query, one registered Tauri command, an adapter wrapper, a query hook, an
epic-scope rail section, and tests at both layers. No migration — 0018 already carries the anchor
table and the roll-up reads existing tables only.

The renderer supplies an epic id and nothing else (D-118, D-139). The query is read-only. It takes a
connection and spawns no git, so it is safe under the database lock and cannot widen CR-01 (which
plan 08-11 narrows).
</objective>

  <behavior>
    Core query `epic_task_rollup`:
    - An epic with two tasks returns two rows, ordered by rank then task id.
    - A task with 3 current criteria of which 2 are checked, 1 of those checked carrying an anchor,
      returns total 3, checked 2, with_evidence 1, without_evidence 1.
    - A superseded criterion revision is counted in neither total nor checked.
    - An epic with no tasks returns an empty vector, not an error.
    - A task with no criteria returns all four counts as zero.
    - An unknown epic id returns an empty vector, not an error.

    Rail section in epic scope:
    - Two tasks render two rows, each naming the task key, the task title and its checked-of-total
      count; a task with a non-zero without-evidence count also names that count.
    - Task scope renders no section and issues no roll-up read.
  </behavior>
