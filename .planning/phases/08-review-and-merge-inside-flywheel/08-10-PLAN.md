<objective>
Close 08-VERIFICATION gap 2 (CR-03): `useRegionBindings` calls `preventDefault` on Enter and Space
for any non-text target before the handler decides, because `isTypingTarget` excludes only INPUT,
TEXTAREA and contenteditable. The verifier reproduced it — a focused `<button>` receives
`defaultPrevented === true` for both Enter and Space — so in a real WebView the button's activation
is cancelled and a keyboard-only user cannot confirm a merge or open an epic request. No dedicated
keystroke exists for either. Flywheel is keyboard-first (Phase 1 SC3), and a destructive
confirmation with no working Enter path is a real regression.

**Goal clause this closes** (ROADMAP Phase 8 goal, clause 3): "and lands it" — landing works by
mouse and is dead by keyboard.

This is a root-cause fix in one shared hook, not a per-call-site patch: `keyboard.ts` serves six
regions. WR-06 rides it — the surface's Escape handler cascades past sheets and inputs because it
ignores `event.defaultPrevented`.

Purpose: the keyboard path to the merge confirmation and the epic request works.
Output: one guard in `useRegionBindings`, one early return in the surface's Escape handler, and a new
behavioural test file that fails on today's code.

This plan is deliberately independent of plans 08-09, 08-11 and 08-12: it shares no file with them,
and its new test renders the two sheets directly inside a local binding harness rather than through
`ReviewSurface` -> `CriteriaRail`, so it does not couple to 08-09's new adapter symbol.
</objective>
