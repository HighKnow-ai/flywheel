<objective>
The tracer slice for Phase 8: one end-to-end path from a real `git diff` in the Rust core, through
two Tauri commands, to a syntax-highlighted unified diff rendered on a fourth full surface that
the item detail panel pushes into.

**Phase goal (ROADMAP, verbatim):** Cyril reviews an agent's work against the acceptance criteria
that were agreed before it started, and lands it, without dropping back to a terminal.

This plan proves the three mechanisms every other plan in the phase expands out from: the
raw-output git wrapper (because `git_at` converts a non-zero exit into an error and discards
stdout, which merge and merge-tree need), server-side scope resolution (the renderer passes a
scope and an id, never a ref), and the diff render chain (`parseDiff` -> `tokenize` -> `<Diff>`
with the refractor-5 adapter, which is the one wiring in this phase that is documented wrongly
upstream and verified corrected during research).

Purpose: nothing in this workspace renders a diff at all today, and `react-diff-view@3.3.3` does
**not** work with `refractor@5.0.0` the way its own README describes — passing the refractor
object throws. Proving the one-line `.children` adapter on the first commit is cheaper than
discovering it on the eighth. The plan is deliberately at the top of the context budget because
the slice must not be cut across the IPC seam: a tracer that stops at the command boundary
proves an assumption instead of a path.

Output: `review.rs`, three new `git.rs` functions, the `review_files`/`review_file_patch`
commands, `ReviewSurface.tsx`, `FileDiff.tsx`, `highlight.ts`, and three test files.
</objective>

<decisions_resolved>
These close discretion items and research corrections so no later plan rediscovers them.

- **`diff_stat_and_names` is not the file-list source, despite D-134 naming it.** Research and
  `08-PATTERNS.md` agree against CONTEXT here: it bakes in `--no-renames`, returns `--stat` text
  whose long paths are truncated at 80 columns, and `drift.rs` depends on those semantics. The
  file list is a new additive read (`-z --numstat -M` zipped with `-z --name-status -M`). D-134's
  intent — an eager, cheap file list — is honored; only its named source changes.
- **The review base is the LOCAL integration branch, never `origin/<integration>`.** The
  integration branch is cut locally (`domain/epic.rs:767`) and never pushed, so the remote ref
  does not resolve. `git_facts.rs`'s `target_ref` is therefore not reusable here.
- **Both scopes are resolved in the tracer, not later.** D-132 puts one surface over both scopes;
  resolving `ReviewScope::Task` and `ReviewScope::Epic` in the same function from the first commit
  is less code than a second resolution path, and it means plan 08-08's scope toggle is a header
  control rather than a new read path.
- **Diffs run against the project `repo_path`, not a worktree.** Branch refs are all that is
  needed, so review survives worktree removal (Phase 3) and needs no checkout. The only worktree
  read in this phase's diff path is the dirty-file count, which `git_facts.rs` already supplies.
- **Nothing is truncated; long files are chunked.** A file opens collapsed; expanding renders the
  first 40 hunks with a control that appends the next 40, and highlighting is skipped above 5,000
  changed lines while the plain text still renders. Thresholds are two module constants in
  `FileDiff.tsx` so they are tunable without a structural change (research assumption A1).
- **Generated-file tagging is a constant list, not detection.** `package-lock.json`, `Cargo.lock`,
  `pnpm-lock.yaml`, `yarn.lock`, `*.min.js`, `*.map`, `dist/`, `.snap` — tagged and collapsed,
  never hidden and never refused.
- **Whitespace handling is exact.** The patch command takes no whitespace flag in v1.
- **The surface's own keyboard region ships with the tracer** (`review-surface` region and layer,
  `j`/`k` through the file list, `Enter`/`Space` to expand, `Escape` to pop back). The `v` board
  binding and the other three doors are plan 08-08's, which is why that plan touches no file this
  one creates beyond `keyboard.ts`.
</decisions_resolved>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → Tauri command surface | `scope`, `item_id`, `path` and `old_path` arrive from the renderer; none is trusted as a ref or as a filesystem path |
| Rust core → `git` subprocess | branch names derived from the board are interpolated into a diff range, and file paths reach a pathspec |
| patch text → React renderer | arbitrary repository content (including attacker-authored file content) is parsed and rendered as markup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01-01 | Tampering | `commands::review::review_file_patch` → `git::review_patch` | high | mitigate | The command accepts a scope enum, an id and two file paths only. Base and head refs, the repo path and every git flag are derived inside `review.rs` from `projects`/`epics`/`tasks`/`worktrees` rows. Paths are placed after `--` with the literal-pathspec global option set and are refused when empty or containing a NUL byte. No shell is involved — argv only, through the one construction site. |
| T-08-01-02 | Tampering | `review.rs` scope resolution | medium | mitigate | Every statement is a compile-time literal with bound parameters (the crate's no-interpolated-SQL rule); the only renderer value reaching SQL is an id used as a bound parameter. |
| T-08-01-03 | Elevation of Privilege | `review.rs` as a read path | medium | mitigate | Resolution never mutates: the epic module's branch-cutting helper is never called, asserted by a negative grep in Task 1's verify block. A NULL integration branch is a typed outcome, not a trigger to create one. |
| T-08-01-04 | Denial of Service | `review_files` / `review_file_patch` on the main thread | medium | mitigate | Both commands carry the async attribute so git runs off the main thread; the database lock is dropped before git is spawned, so a slow diff cannot block another command handler. The file list is one cheap read and patches are fetched per opened file only. |
| T-08-01-05 | Denial of Service | an 8,000-line patch tokenized synchronously | low | mitigate | Hunks render in bounded chunks and highlighting is skipped above the line cap; the whole output is buffered in memory at roughly 0.4 MB for that size, well inside the subprocess buffer. |
| T-08-01-06 | Information Disclosure | repository paths crossing IPC | low | mitigate | No DTO in this plan carries a repository or worktree path; raw git stderr never crosses the boundary and is mapped to a string the command author wrote. |
| T-08-01-07 | Spoofing | repository file content rendered as markup | medium | mitigate | Patch text is parsed by the library's unidiff parser and rendered as text nodes inside a table; the tokenizer emits class-bearing spans only. No patch content reaches an `href`, a `dangerouslySetInnerHTML` or a URL. |
| T-08-01-SC | Tampering | `npm install react-diff-view refractor` | medium | mitigate | `08-RESEARCH.md` § Package Legitimacy Audit records both packages as `OK` with source repos, ages and download volumes, and no postinstall script; neither is `[ASSUMED]` or `[SUS]`, so no blocking human checkpoint is required. Both are pinned exactly and the lockfile change is committed with them. |
