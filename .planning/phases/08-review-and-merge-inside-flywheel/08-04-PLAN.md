<objective>
Three of D-133's four doors onto the review surface. The item detail panel's Review button shipped
with the tracer; this plan adds the board keystroke, the command palette route, and the offer the
session surface makes when a run finishes.

Purpose: each door is a few lines against a convention the codebase already has — the board list
already opens Start Work from one keystroke, the palette already resolves a git identifier to a
board item, and the session surface already knows when a run has reached a terminal status. What
makes them worth their own plan is that they are the only frontend work in this phase that touches
no file the review surface itself occupies, so they run in parallel with the anchor and merge cores
instead of queueing behind them.

Output: one action id, one binding, three call sites, and two test files.
</objective>

<decisions_resolved>
- **The key is `v`.** Verified free in the board-list region: the region's full key set is `a
  ArrowDown ArrowUp Backspace c e End Enter Home j k l m o p r s w`. `r` is taken, so the first
  letter of "review" was not available.
- **The keystroke opens epic scope on an epic row.** Unlike Start Work, which is task-only,
  review serves both scopes from one surface (D-132), so the action derives its scope from the
  selected row's kind and refuses only issue rows — issues carry no acceptance criteria by
  D-05/D-06/D-07, so a review scope for one would have an empty rail by construction.
- **`open-review` is not added to the review-surface action set.** It is dispatched *from* the
  board, so it must fall through `bindingAllowedInLayer` to the final clause that permits the
  board layer. Adding it to the review set would make the only door that opens the surface
  reachable only from inside it.
- **The palette opens review, it does not replace the detail route.** The resolved-git-identifier
  branch gains a review path alongside the existing detail path rather than changing where a
  resolved identifier lands by default, because a sha may be resolved for reasons other than
  reviewing it.
</decisions_resolved>
