<objective>
Two register items that nothing earlier than an installed build could answer, and which plan 11-08
has now made answerable. Both are marked automatable **given a build** — D-REV-22's note is explicit:
"No human judgement is needed, only a build."

browser-mode test against a configured appearance; whether `prefers-color-scheme` actually tracks the
system setting inside the Tauri shell's WKWebView has never been observed. If it does not, the entire
dark token block is dead code in the shipped application.

Purpose: drain D-REV-20 and D-REV-22.

Write `scripts/release/verify-appearance.mjs`:
1. Record the current `AppleInterfaceStyle` (it is absent in Light mode, which is itself the value to

   system appearance and leaving it changed is a rude test.
2. Parse the dark and light ground token values out of `packages/desktop/src/styles/tokens.css`. The

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the installed bundle → the OS's icon and appearance services | What the OS paints is outside every in-process test's reach. |
| a test script → the developer's system settings | Changing the global appearance affects every running application. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-55 | Tampering | icon substituted or unreferenced in the shipped bundle | low | mitigate | SHA-256 comparison against the source `.icns` plus `Info.plist` key assertions on the installed copy. |
| T-11-56 | Denial of Service | system appearance left changed | low | mitigate | The prior value (including its absence) is recorded and restored in a cleanup that runs on failure, with a verify gate asserting the setting is left valid. |
| T-11-57 | Repudiation | a dark-mode claim resting on browser-mode tests alone | high | mitigate | A pixel sampled from the installed application in system Dark, compared against the token read from the shipped CSS; a negative result is recorded as a finding rather than softened. |
</threat_model>
