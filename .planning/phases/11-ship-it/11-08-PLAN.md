<objective>
**As** Cyril, **I want to** install Flywheel from a release like any other Mac application, **so
that** the thing I have been building is a thing I own a copy of.

This plan flips the repository public, cuts `v0.1.0`, installs it, and publishes `v0.1.1` so the
update path has something real to offer. It depends on nothing in the register drain, by design:
D-195 says the tag goes out first and the register drains against the tagged, installed build —
gating the tag on the register deadlocks, because five register items need an installed signed
bundle that only the tag produces.

Purpose: turn four criteria from "wired" into "observed".
Output: `v0.1.0` and `v0.1.1` releases, an installed application, and one evidence file.
</objective>

## Trust Boundaries

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-11-24 | Information Disclosure | the tracked tree and its history at the moment of publication | critical | mitigate | A pattern sweep over tracked files and a `git ls-files` check for credential-shaped paths run **before** `gh repo edit`, with a hit halting the task; the authorising consent is plan 11-02 Task 1, which asked explicitly. |

| T-11-26 | Spoofing | an empty `signature` in `latest.json` | high | mitigate | Task 3 fails on an empty signature field and independently verifies the tarball against the compiled public key, rather than trusting a green workflow. |
</threat_model>
