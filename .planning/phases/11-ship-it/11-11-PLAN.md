D-REV-41 is the register's loudest process failure: two prior SUMMARYs both said "file this" and
neither did. The behaviour it names is ordinary, not edge — the first failed or conflicting task in
a real fan-out strands the rest of the epic with no in-app recovery, because `is_startable` retries
only four states, `observation_targets` skips three, `wave_is_drained` counts two, and nothing in
`commands/dispatch.rs` sets a task to `skipped` or back to `planned`. D-156 says a conflict "stops
that task and asks the user". The application asks and offers no way to answer.

automatically, because `decide` and `merge_task` never read `task.scope_denied`.

Purpose: drain D-REV-41 and D-REV-42's automatable half.
Output: two human-only commands, their UI, and a needs-attention cause for an observed breach.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent session → the verbs that change what the machine does unattended | A retry or a skip reachable by an agent is an agent grading its own work. |
| observed out-of-scope write → the automatic merge | An unreviewed merge can carry a breach into the integration branch and into wave two. |
