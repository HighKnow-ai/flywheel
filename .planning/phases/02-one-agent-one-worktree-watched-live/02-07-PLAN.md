<objective>
Expansion slice: D-31's full session surface becomes the thing D-32 describes — structured,
skimmable, with the raw stream one keystroke away — and PROC-07's flat memory becomes a property of
the design rather than a ceiling to stay under.

Purpose: ROADMAP success criterion 2 is watching a long-running session live with application memory
staying flat. D-33 chose a windowed read against the persisted log over a generous in-memory cap for
exactly this reason: a long unattended run is what finds a ceiling. This plan builds the bounded
read, the structured rows, and the raw escape hatch that lets a user check a row against its ground
truth without leaving the app.

Output: the windowed JSONL read with a server-side cap, the structured feed rows, the virtualized
list, the raw view, and the cost/token status strip.

Boundary note: per-session cost display beyond a live status strip is AGNT-08, Phase 10. The
`cost_update` data exists from this phase; do not build a cost history surface here.

In `packages/core/src/session_log.rs`, add `LOG_WINDOW_MAX_LIMIT` (100, matching the trail cap
`query/events.rs` already uses), `count_lines(run_id)` and
`read_window(run_id, offset, limit) -> LogWindow`. `read_window` opens the file with a buffered
reader, skips `offset` lines and yields at most `min(limit, LOG_WINDOW_MAX_LIMIT)` lines — it never
reads the file into a single string and never collects the whole file into a vector. That is the
mechanical form of PROC-07: the read is bounded at the source, so no caller can ask for the whole
transcript even by mistake.

`LogWindow` carries the entries, the offset it started from, the effective limit after clamping, and
the total line count. Parse each line at read time into the normalised event shape; a line that
fails to parse becomes an `unknown` entry carrying its verbatim text and its line number. Never skip
a line: the persisted log is the ground truth the raw view exists to show, and an unrenderable line
that disappears from both the feed and the window would be output silently lost. Guard against a
partially written final line by treating a trailing fragment with no newline as not-yet-complete and
excluding it from the window while still counting the file's complete lines.
