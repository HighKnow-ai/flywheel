<objective>
Expansion slice on the tracer: the user can stop a running session and find the worktree intact and
inspectable.

Purpose: this is the second half of ROADMAP success criterion 4 and the requirement (PROC-06) that
makes the whole supervision loop safe to run unattended. It is also where PITFALLS.md pitfall 4's
zombie-process failure mode is either avoided or baked in — killing the direct child instead of its
process group leaves an agent's dev server or build running inside a worktree Flywheel has already
reported as stopped.

Output: `interruptSession`/`killSession` on the adapter, the `agent_run_stop` command, the terminal
run states, a Stop affordance on the session surface, and two real-process tests — one proving the
group teardown, one proving the worktree survives dirty.

Boundary note: crash recovery, orphan reaping at launch, and the refuse-to-destroy-a-dirty-worktree
guard are Phase 3 (WORK-03, PROC-04, PROC-05). This plan must not build them, and must not build
anything Phase 3 would have to tear out.
</objective>

## Flagged assumption carried into this plan

**PROC-06 was `unclassified` by the edge probe.** The assumption executed against: interrupt maps
to SIGINT to the session's process group, force maps to SIGTERM to that same group after a fixed
grace window, and neither ever escalates to SIGKILL in this phase — SIGTERM is what lets Claude
Code tear down its own Bash sub-process tree and run its SessionEnd hooks first
(`code.claude.com/docs/en/headless`, cited in 02-RESEARCH.md). SIGKILL as a last resort belongs with
Phase 3's orphan reaping, not here.

  <action>
Implement D-35 on the adapter. Add `STOP_GRACE_MS` as a single exported constant in
`packages/sidecar/src/claude-code-adapter.ts` — one value, one place, not a per-run parameter and
not read from configuration.

`interruptSession(runId)` looks the session up in the sidecar's map, delivers SIGINT to the
session's **process group** using the negative-pid form (`process.kill(-child.pid, "SIGINT")`),
starts a `STOP_GRACE_MS` timer, and resolves when the child's `exit` event fires. If the timer
expires first, deliver SIGTERM to the same group and resolve when the child exits. Never signal the
bare pid: the session was spawned detached precisely so the group is the signalling target
(RESEARCH.md Pitfall 3 — a Bash tool call the agent had running survives a bare-pid kill). Do not
escalate to SIGKILL; SIGTERM is what lets Claude Code tear down its own sub-process tree first.

`killSession(runId)` is the force step on its own, for the app-exit path: SIGTERM to the group, no
grace window.

Both methods are idempotent and safe on an already-exited session — resolve, do not throw, do not
emit a second terminal event. An unknown `runId` rejects with a typed error naming it. Clear the
timer and remove the session from the map in exactly one place so neither path can leak a timer.

Emit a new `session_closed` event on the `AgentEvent` union in `packages/sidecar/src/adapter.ts`
carrying `runId`, `reason` (`interrupted` | `completed` | `failed`) and, when the backend produced
one, the final result payload. Add `interrupt` and `kill` ops to the stdio request loop in
`src/index.ts`, each acknowledged by id so the Rust core can correlate the response.

Extend `packages/sidecar/test/fake-claude.mjs` with a stubborn mode selected by an argument or
environment flag: it installs a SIGINT handler that deliberately ignores the signal, forks a
long-lived grandchild process that prints its own pid, and only dies on SIGTERM. This fixture is

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → Rust core | An `agent_run_id` supplied by the renderer selects which process gets signalled. |
| Rust core → Node sidecar | The interrupt request crosses the stdio channel; the sidecar performs the actual signalling. |
| Node sidecar → OS process group | A signal delivered to a negated pid reaches every process in that group. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-11 | Denial of Service | `interruptSession` signalling a negated pid | high | mitigate | The signal target is the pid of a child the sidecar itself spawned and still holds in its session map; an unknown `runId` rejects before any signal is sent, so a renderer-supplied id can never be turned into an arbitrary process-group signal. Asserted by the unknown-runId case in `stop.test.mjs`. |
| T-02-12 | Tampering | the stop path touching the user's git history | high | mitigate | No git invocation exists on the stop path; the structural check greps `domain/agent_run.rs` for history-writing subcommand names and requires zero, and `stop_lifecycle.rs` asserts the branch's commit count is unchanged across a run. |
| T-02-13 | Repudiation | a stop recorded without an actor | medium | mitigate | `agent_run_stop` resolves `actor_id` server-side and the terminal event is appended in the same transaction as the status write, so the activity trail cannot diverge from the row. |
| T-02-14 | Denial of Service | a leaked grace timer per interrupted run | low | accept | The timer is cleared in a single teardown path exercised by both the cooperative and stubborn test cases; a residual leak would be bounded by the number of runs in one app session. Accepted at ASVS L1. |
</threat_model>
