<objective>
Close gap G-02-3 (`02-UAT.md`, major, test 1). The user's report was "The design is terrible", with a
screenshot of the session surface rendering every feed row on top of the ones below it — dozens of
superimposed text layers, entirely unreadable.

The cause is a contract implemented on one side only. `SessionSurface`'s virtualizer positions each
row absolutely at `translateY(virtualRow.start)`, where `start` comes from `feedRowEstimateSize` — a
constant per row kind, deliberately never corrected by measurement. That is a sound virtualization
contract and `02-UI-SPEC.md`'s Performance Contract Additions specify it deliberately. But the
absolute row wrapper sets a width and no height and no overflow clamp, and `FeedRow`'s body rows
render with wrapping enabled and no maximum height. The estimate therefore decides where a row
STARTS while nothing makes the row actually OCCUPY that height. The two agree only for short
content — which is all the tests and the fake CLI ever produced.

The clamping pattern this file needs already exists inside it: the tool-call label span at
`FeedRow.tsx:88` clips with hidden overflow, an ellipsis and a no-wrap rule. It was simply never
applied to the body rows.

**Honest scope note, carried from the UAT:** the `--verbose` flag added for G-02-2 made this
dramatically worse but did not cause it. Under `--verbose` the CLI emits `SessionStart` hook events
that `normaliseStreamEvent` maps to `unknown`, carrying the full raw line — 32 of the reported
session's 51 events were of that kind. The overflow defect is independent of that flag and surfaces
on any long assistant message or tool result. This plan fixes the overflow. It does NOT change the
event normalisation: the UAT explicitly records the hook-event rows as cosmetic and not a defect, so
re-classifying them here would be scope the gap does not authorise.

Purpose: the fix has to satisfy two things at once — the render contract must match the position
contract (structural), and the user must still be able to read what an agent actually said
(product). One without the other trades an unreadable overlap for an unreadable truncation.
Output: a clamped row slot, body rows that clip to one line and open in place, and a regression test
that feeds a multi-kilobyte event through the real feed.
</objective>

## UI Considerations carried by this plan

Lifted from `02-UI-SPEC.md` § "E2 — Session feed" and § "Performance Contract Additions". These are
the rows this gap violated, and they are the rows this plan restores:

- **E2 `overflow` (explicit):** "An expanded tool-call payload renders inside a fixed max-height
  sub-block with its own internal scroll, so it never grows its row." Already true for the expanded
  tool call; this plan extends the same containment to every other row kind, and adds the outer
  clamp that makes the claim structurally true rather than incidentally true for short content.
- **E2 `long-text` (explicit):** "Long assistant text and long tool payloads are contained by the
  same fixed max-height, internally scrolling sub-block rather than reflowing the surface." This row
  was asserted in the spec and implemented only for the tool call. Task 2 makes it true for
  assistant text and raw rows.
- **E2 `populated` (explicit):** "The feed is a virtualized windowed read against the persisted
  session log... application memory stays flat as the transcript grows." This plan changes nothing
  about the windowing or the read; it only clamps how a row paints. The flat-RSS observation itself
  stays a human-verification item and nothing here claims to automate it.
- **Performance Contract Additions (explicit):** a fixed `estimateSize` per row kind, never derived
  from content length, never measured. Task 2's expandability predicate is a pure function of the
  row's own data and never changes a COLLAPSED row's height, so the fixed-size rule is preserved.
- **UI-SPEC Open Question 2** ("the exact expanded-tool-call max-height value... left to the
  planner/executor as an implementation density decision") is resolved here by reusing the constant
  already in the file rather than minting a second density value.
