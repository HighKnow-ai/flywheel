<objective>
Turn the pre-push layer's refusal into a question: when a destructive push is detected and the session
has a supervisor to ask, raise a real permission request on the socket the session already has open.

Purpose: plan 12-02 made the measured breach impossible, but by refusing outright. `AGNT-07` requires
explicit confirmation, not prohibition, and round ten's live run already recorded the difference — UAT
6b reported "safety held, the human-in-the-loop half did not" and was scored FAIL. A gate that can only
say no also breaks every legitimate agent push the later git/forge phases depend on.

Output: a `--gate-push` entry point on the shim binary that reuses the existing permission round trip
unchanged, the hook script delegating to it through its baked absolute path, and tests covering all
four outcomes — allow, deny, nothing-to-ask, and the benign push that raises no request at all.

**Why this does not reopen the classifier.** `--gate-push` adds an entry point; it does not touch
`resolve_segment_program_index`, `text_can_shadow_path_resolution`, `text_names_gated_program`, or
`raw_text_names_path_defeating_wrapper`. The string-literal baseline from plan 12-01 is what proves
that: it will fail until the baseline is regenerated, and the regenerated diff must contain only this
entry point's own literals. That deliberate friction is the gate working as designed.
</objective>

  <action>
**In `packages/shim/src/main.rs`** — add one new pre-dispatch mode, in the same position and the same
shape as the two existing classify modes, which is to say checked BEFORE the argv[0]-stem `match`.
This positioning is load-bearing: the hook invokes the shim binary under its own filename, so the stem
`match` would reach the "refusing to run — invoked as …" arm and never see the flag.

The new mode: `--gate-push <category-name> <token>...`. Add `fn run_gate_push(args: &[OsString]) -> ExitCode`:
- Parse the category name with `flywheel_core::destructive::DestructiveCategory::from_str_name`. An
  unrecognised or missing name is a refusal with a named stderr line and a failure exit code — never a
  silent allow and never a defaulted category.
- Require at least one token after the category name. Zero tokens means the caller told the human
  nothing about what they are approving; refuse with a named stderr line.
- Call the EXISTING `request_permission` with `"git"` as the program and the remaining tokens as the
  args, so the request line's `input.command` reads as the git command the push performs and
  `input.destructiveCategory` carries the category name. Do not write a second request-building path
  and do not touch `request_permission` itself: D-55/D-58's fresh-connection, no-deadline contract is
  already implemented there and this mode needs exactly it.
- Map the outcome: `Allow` exits success, `Deny` calls the existing `print_denied` and exits failure,
  `Error(message)` prints the message with the existing `flywheel-shim: ` prefix and exits failure.
  An unobtainable answer is a refusal (D-60), identical to `destructive_gate`'s own handling.
- This mode never resolves `FLYWHEEL_REAL_GIT`, never resolves `FLYWHEEL_REAL_RM`, and never execs
  anything. Say so in its doc comment, next to the same statement the classify modes carry.

Add nothing else to this file. Do not add a token, a match arm, or a literal to any of
`resolve_segment_program_index`, `text_can_shadow_path_resolution`, `text_names_gated_program`, or
`raw_text_names_path_defeating_wrapper`.

**Regenerate `packages/core/tests/fixtures/shim-main-string-literals.baseline.txt`** by re-running plan
12-01's extraction against the modified file. Before committing, diff the baseline against its previous
version and confirm by inspection that every added line belongs to the new entry point — the flag name,
its refusal messages, and nothing resembling a program, launcher, or wrapper token. Record that
confirmation in the commit message. This is the one place in the phase where the fence is deliberately
opened, and it must be opened visibly.

**In `packages/core/src/git_hooks.rs`** — extend `pre_push_hook_script`'s destructive-verdict branch
into two cases, keeping the existing one as the fallback:
- **Ask:** when the permission-socket environment variable the shim reads is set to a non-empty value
  AND the baked shim binary path is executable, run the baked shim binary with the gate-push flag, the
  category name, and tokens describing the push truthfully — the push subcommand name, the remote name
  the hook received as its first argument, and the remote ref from the current stdin line, plus the
  delete flag token for a deletion and the force flag token for a non-fast-forward, since that is what
  the push actually performs. A zero exit means the human allowed it: `continue` to the next stdin line
  rather than exiting, because a later ref in the same push may still be destructive and must get its
  own question. A non-zero exit exits 1 immediately, aborting the whole push.
- **Nothing to ask:** unchanged from plan 12-02 — the named stderr refusal and exit 1. Keep its comment
  and update it to state that the ask branch above is now the primary path and this is the D-60
  fail-closed fallback.

Pass the tokens as separate quoted shell words, not as one pre-joined string: `request_permission`
joins them itself, and pre-joining would double-quote the rendered command text on the board card.

Do not read the socket variable to decide WHETHER the push is Flywheel's business — the territory check
against the baked worktree root already decided that, earlier in the script, and it must stay the only
such decision. The socket variable decides only whether there is anyone to ask.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Generated hook script → the shim binary | Crossed through a baked absolute path, never a `PATH` lookup |
| Shim `--gate-push` → the permission socket | The only channel that can wait indefinitely for a human (D-58) |
| Hook-supplied tokens → the board card's rendered text | Text a human reads before approving a destructive action |

| T-12-16 | Spoofing | the request's rendered command text | high | mitigate | The hook passes the actual remote name and remote ref from git's own stdin protocol; Task 2 asserts the captured request names both, so a human never approves a description that does not match the push |
| T-12-17 | Elevation of privilege | an unobtainable or malformed socket answer | critical | mitigate | `run_gate_push` maps `Error` to a refusal exactly as `destructive_gate` does (D-60); Task 2's no-socket arm asserts the ref survives |
| T-12-18 | Elevation of privilege | a multi-ref push where only the first ref is asked about | high | mitigate | The ask branch `continue`s on allow rather than exiting, so every destructive ref in one push gets its own question; asserted as an acceptance criterion on the rendered script |
