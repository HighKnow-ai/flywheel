<assumption_delta_decision>
**Noun now primary:** *a path that can change a project's `repo_path`* (plural) — no longer *the
registration path* (singular). The detector fired on the ROADMAP's own prose ("not another hardening
round"), which is a false positive, but the underlying scope change is real: Layer 3's install point
goes from one call site to every call site that mutates `repo_path`.

**Decision:** `promote`.

**Rationale:** one private helper, `install_layer3_pre_push_gate`, becomes the single rendering of the
install outcome, both `register_project` and `relocate_project` call it, and a source-level invariant
test in `destructive_gate_layer_coverage.rs` fails the moment a third mutation path appears without it
— promoting the general representation is a strictly shorter diff than duplicating the match block and
is the only shape that makes the third path a compile-or-test failure rather than a silent omission.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer-chosen relocation target → Flywheel's git-config writes | The developer picks an arbitrary directory in the "Project unreachable" recovery UI; Flywheel then writes `core.hooksPath` into that repository's `.git/config` |
| committed `.flywheel/project.json` in a cloned repository → project identity | The marker is tracked content, so it can be hand-edited or arrive from an untrusted clone and still claim a project id |
| installed `pre-push` script → the real `git push` process | The script runs inside git with the developer's privileges on every push from a managed worktree |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-13 | Elevation of Privilege | `relocate_project` (`packages/core/src/domain/project.rs`) | high | mitigate | The gap itself: a relocated project silently runs with Layer 3 absent, so force-push / branch-deletion / history-rewrite fall back to the P1-dependent Layer-2-only posture. Task 1 calls `install_layer3_pre_push_gate` after `tx.commit()`, restoring Layer 3 at the new path; Task 3's invariant test fails if a third mutation path ever skips it. |
| T-12-14 | Tampering | `install_pre_push_hook` Step 1, reached from `relocate_project` | medium | mitigate | A relocation target carrying a foreign `core.hooksPath` (husky, pre-commit) must not have it displaced. Unchanged install logic refuses; Task 2's `a_refusal_never_fails_relocation` asserts the foreign value is byte-identical after the relocation. |
| T-12-15 | Repudiation | the install outcome rendering in `packages/core/src/domain/project.rs` | medium | mitigate | A refusal with no record is the exact silence this phase exists to end. The shared helper logs every non-`Installed` outcome on stderr with its reason at both call sites; Task 3 widens the trust-boundary document's refusal residual row to name relocation as a logging point too. |
