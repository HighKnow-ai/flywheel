<objective>
Ship the one credential-spending measurement this phase needs as a committed, runnable harness, and
measure three things in one session rather than one.

Purpose: the `CLAUDE_ENV_FILE` ordering claim is `[CITED]` and cannot be settled offline — the shell
snapshot's behaviour on this machine's installed binary in headless mode is the open question. Round
ten's lesson is that an environment property must be proved against the process that will actually use
it, so this harness asks the agent's own Bash command shell three questions and asserts on the files
those questions write. Per the project's standing preference the harness is the deliverable; the only
manual part is spending the credentials.

Output: `scripts/uat/uat-11-env-file-ordering.mjs` with a non-credential self-test arm and three live
probes, registered in `scripts/uat/run-all.sh`, plus the measured outcome recorded in
`docs/destructive-gate-trust-boundary.md`'s residual row.

**Deliberate deviation from the research's sketch, recorded.** `12-RESEARCH.md` Open Question 1 proposes
a marker directory containing a stub `git` that writes a file instead of running real git, proving PATH
precedence behaviourally. This harness instead measures the real product wiring: the first `PATH`
segment of the agent's own command shell compared against Flywheel's shim directory for that run. That
answers the same question — is P1 restored — about the thing that actually ships, needs no fake `git`
and no second settings file composed outside `writeHookSettings`, and is strictly cheaper. The stub-git
design remains the fallback if the segment probe turns out not to be observable.
</objective>

and reproduces the D-63 remote-safety statement verbatim even though this item needs no remote at all

**Three probes, one session.** Spawn ONE real headless session through the harness's normal path, so the
settings file comes from the product's own `writeHookSettings` and the `SessionStart` hook under test is
the one that actually ships. Prompt the agent to run three shell commands, each writing its answer into
a distinct file inside the harness scratch directory. Assert on those files' contents and never on the
transcript's narration — a model's claim that it ran something is not evidence it did.

- **Probe 1 — is P1 restored?** A command that writes the FIRST segment of the command shell's own
  `PATH` into a file. Assert the file exists and its trimmed content equals Flywheel's shim directory
  for this run — the harness knows that path because it knows the run id and the runtime directory.
  Report `restored` when they match and `snapshot-won` when they do not, and in the `snapshot-won` case
  also record the observed first segment verbatim in the artifact, because that value is the evidence
  the next round starts from.
- **Probe 2 — is an ordinary command still ordinary?** Prompt the agent to run `git --version`. Assert
  a tool result arrives for it, that its exit was successful, and that NO permission request was raised
  for it. Round ten's live run failed on exactly this probe, timing out for 120 seconds waiting for
  `git --version`'s tool result, so bound the wait and report a timeout as a failure naming that
  precedent. Drain incidental permission requests the way uat-07 does, so Claude Code's own internal
  git housekeeping does not confound the measurement.
- **Probe 3 — does the ask-branch discriminator survive into the command shell?** A command that writes
  whether the permission-socket environment variable is set, into a file, and exits 0 whether or not it
  is set. The command must name no gated program, so it defers through the gate rather than being
  classified. Assert the file exists and report `present` or `absent`. This is the measurement that
  converts plan 12-04's ask branch from an assumption about an invisible process into a fact; an
  `absent` result means the pre-push layer's ask branch can never fire and the trust-boundary document's
  refusal residual becomes the standing behaviour, which must be recorded rather than discovered later.

**The artifact.** Write one JSON file into the harness's artifact directory carrying, per probe, a
`verdict` field with one of the named values above, the raw observed value, and the run id. The result
table's note should name all three verdicts so a reader of the suite output does not have to open the
artifact.

**A non-credential self-test arm, and it is the part that makes a green run mean something.** Support a
`--selftest` flag that spends no credentials and spawns no `claude`: it constructs the same three probe
files by hand — one with a deliberately wrong first `PATH` segment, one absent, one with each socket
verdict — and asserts the harness's own assertion helpers return the expected verdict for each. Then
assert the inverse: with correct inputs the helpers report success. UAT 6a's recorded failure is the
reason this exists — it passed vacuously because the watchdog killed the session before the property was
ever exercised, and nothing in the item could tell the difference. The self-test arm is what tells the
difference. Factor the three verdict decisions into small pure functions so the self-test exercises the
same code the live arm uses, not a parallel copy.

**Register it** in `scripts/uat/run-all.sh` as a new `node scripts/uat/uat-11-env-file-ordering.mjs`
line in the existing item list, in numeric sequence after the uat-10 line, following the surrounding
lines' exact invocation and result-recording shape. Do not reorder or reword any existing item.
