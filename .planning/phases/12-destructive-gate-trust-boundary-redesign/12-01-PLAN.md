<assumption_delta_decision>
**The pluralization event:** the gate goes from ONE interception point (the PATH shim) to SEVERAL
(the PATH shim, git's own `pre-push` hook, and a `SessionStart` PATH-ownership hook).

**The noun that is now primary:** *an interception layer*. "The shim" is demoted to one variant of
it — the variant that depends on winning a `PATH` name lookup, which is precisely the variant whose
premise (P1) is now known to be unachievable.

**Decision: `promote`.**

**Rationale:** the whole reason nine rounds of hardening never found the hole is that the document
described a single chain (Layer 0 → Layer 1 → Layer 2) in which every layer's "cannot see" list
delegated the `PATH` question to the next one, and the last delegate was checking the wrong process.
Adding a git-native layer *alongside* while the document still reads as one chain would reproduce
that exact failure: a reader would keep treating the shim's interception as the thing that must hold.
Promoting "interception layer" to the primary noun makes coverage a question about a SET — which
layers cover which destructive category — and that question has an answer a test can check.

**Invariant encoding the generalized intent** (built in plan 12-02, Task 3): a coverage table mapping
every `DestructiveCategory` variant to the interception layers that cover it, with a test asserting
the table is TOTAL over `DestructiveCategory::all()`. It goes red the instant a new variant is added
without a layer, and it is the artifact that makes `default-branch-push`'s Layer-2-only status a
written, visible fact rather than an unnoticed gap.
</assumption_delta_decision>

(2) **New section `## Layer 3 — git's own pre-push hook` placed after `## Layer 2`.** State:
implementing file `packages/core/src/git_hooks.rs`, installed once per registered project by writing
`core.hooksPath` to an absolute directory under Flywheel's runtime directory (shared by every linked
worktree of the repository by default). Under `### Trusted to prove`: that it fires inside the real,
already-resolved `git` process, after every `PATH` search has already happened, so no shell init and
no `PATH` reorder can prevent it reaching a decision; that it reads git's own stdin protocol
(`<local-ref> <local-object-name> <remote-ref> <remote-object-name>`, one line per ref), so none of
the text-obfuscation shapes rounds five through nine fought (launcher wrapping, `env -S`, brace
expansion, quoting) survive to reach it; that a branch deletion is the all-zeroes local object name
and a force-push / history rewrite is a new local object name that is not a descendant of the remote
object name; and that it resolves the real `git` binary and the shim binary through absolute paths
baked in at install time, never through a `PATH` search. Under `### Explicitly cannot see`: anything
that is not a push (`rm -rf`, `git reset --hard`, `git clean -fdx` — those remain Layer 2's); a push
run with `core.hooksPath` deliberately overridden on the command line; a push from outside Flywheel's

`force-clean`, `recursive-delete` and `default-branch-push`. Record the phase-12 fork resolution: the
