<objective>
Close the measured incident at a layer the developer's login shell cannot reorder: git's own `pre-push`
hook, installed once per registered project via `core.hooksPath`.

Purpose: `git push origin --delete uat-doomed-branch` reached a real remote on 2026-10-01 because
Flywheel's shim lost `PATH[0]` to the developer's shell init. A `pre-push` hook fires inside the real,
already-resolved `git` process — after every `PATH` search has already happened — so the same bypass
cannot reach it. This is the ROADMAP's fork branch 2 ("stop depending on `PATH` precedence"), and
unlike branch 1 it is verifiable entirely offline, which is why it lands first.

Output: `packages/core/src/git_hooks.rs`, the generated hook script, the `core.hooksPath` install wired
into `register_project`, and an offline test that performs real pushes against a throwaway local bare
repository (D-63) proving both arms — destructive refused, ordinary untouched.

**This plan carries the phase's tracer.** Task 1 is the end-to-end slice: one destructive push, wired
through every layer the phase touches (project registration → git config → generated hook script →
git's own hook invocation → refusal), with a runnable end-to-end verify. Tasks 2 and 3 expand out from
it. Task 1 is production-quality, not a prototype: the refusal path it ships is the final behaviour for
the case where there is nothing to ask (D-60's fail-closed obligation). Plan 12-04 adds the
human-in-the-loop branch alongside it — a functionality gap, not an architectural one.
</objective>

Create `packages/core/src/git_hooks.rs` and register it in `packages/core/src/lib.rs` as
`pub mod git_hooks;` in the existing alphabetical position between `git` and `git_retry`.

**Public surface:**
- `pub const PRE_PUSH_MARKER: &str = "flywheel-pre-push-gate"` — the literal written into the generated
  script's own header comment, and the only way `install_pre_push_hook` recognises a script it wrote
  itself versus a developer's own.
- `pub fn hooks_dir_for_repo(project_id: &str) -> anyhow::Result<PathBuf>` — returns
  `runtime_protocol::runtime_dir()?.join("git-hooks").join(project_id)`. Deliberately under Flywheel's
  runtime directory, not inside the user's repository: `core.hooksPath` accepts an absolute path, and
  nothing Flywheel generates belongs in the developer's working tree.
- `pub fn pre_push_hook_script(real_git: &Path, shim_bin: &Path, worktree_root: &Path) -> String` —
  renders the script text with those three absolute paths baked in as single-quoted shell assignments.
  A pure function with no I/O, so the script text is unit-testable without installing anything.
- `pub enum PrePushInstall { Installed { hooks_dir: PathBuf }, RefusedPreexistingHooksPath { existing: String }, RefusedPreexistingPrePush { path: PathBuf } }` — the refusal variants carry the reason so a caller can read WHY the layer is absent. This is the observability contract: an absent layer is a returned value, never a silent skip.
- `pub fn install_pre_push_hook(repo_path: &Path, project_id: &str) -> anyhow::Result<PrePushInstall>`
- `pub fn uninstall_pre_push_hook(repo_path: &Path) -> anyhow::Result<()>` — unsets `core.hooksPath`
  when and only when its current value is a directory containing a script carrying `PRE_PUSH_MARKER`,
  and is a no-op otherwise. This is what makes the install reversible in code rather than in prose.

**`install_pre_push_hook` sequence:**
1. Read the repository's current `core.hooksPath` through `crate::git::git_at(repo_path, &["config", "--get", "core.hooksPath"])`, treating a non-zero exit as "unset" (git exits 1 when the key is absent — use `rev_parse_verify`'s "non-zero means false" policy shape, not `git_at`'s error policy, so an unset key is not an `Err`). If it is set to anything that is not a Flywheel hooks directory carrying `PRE_PUSH_MARKER`, return `RefusedPreexistingHooksPath` without writing anything.
2. Check the repository's default hooks directory for a non-sample executable `pre-push` (an entry named exactly `pre-push`, not `pre-push.sample`). If present, return `RefusedPreexistingPrePush` without writing anything. Rationale to state in a comment: setting `core.hooksPath` REPLACES the repository's default hooks directory outright, so installing over an existing `pre-push` would silently stop the developer's own hook from firing — a harm this layer must never cause. Mark the narrow choice with a `ponytail:` comment naming the upgrade path (chain to the pre-existing hook) and the ceiling (the refusal means no Layer 3 for that repository).
3. Resolve the three baked absolute paths: `crate::shim::resolve_real_git()`, `crate::shim::resolve_shim_binary()`, `crate::git::worktree_root_from_env()`. A failure to resolve any of them is an `Err` — never a script with an empty or relative baked path.
4. `fs::create_dir_all(hooks_dir_for_repo(project_id)?)`, write `pre-push` with the rendered script, and set its mode to `0o755` on Unix (mirror `shim.rs`'s `install_shadow_entry` execute-bit handling).
5. Write the config: `crate::git::git_at(repo_path, &["config", "core.hooksPath", <hooks_dir as str>])`.
6. Verify, before returning `Installed`: the written file exists, is a regular file, is non-empty, carries `PRE_PUSH_MARKER`, and on Unix carries an execute bit; and `core.hooksPath` now reads back as exactly the directory written. Any failure is an `Err` naming which expectation was not met, prefixed `pre-push gate install verification failed` — mirroring `shim.rs`'s Layer-0 verification idiom and D-60's loud-failure obligation.

**HARD CONSTRAINT:** every git invocation in this file goes through `crate::git::git_at`. Do NOT write
`Command::new` with a git program argument anywhere in this module —
`packages/core/tests/supervisor_cwd.rs` asserts there is exactly one such construction site in the
whole workspace, inside `packages/core/src/git.rs`, and a second one fails CI immediately.

**The generated script** (POSIX `sh`, no bashisms, no runtime dependency beyond `sh` and the baked git
binary). In order:
- `#!/bin/sh` then a header comment line carrying `PRE_PUSH_MARKER`, naming what the script is, that it
  is generated by `packages/core/src/git_hooks.rs`, and that hand edits are overwritten on reinstall.
- Three single-quoted assignments of the baked absolute paths: the real git binary, the shim binary,
  the Flywheel worktree root.
- **Territory check, first:** if the current working directory is neither the baked worktree root nor a
  path under it, exit 0 immediately. Git runs `pre-push` with the working directory set to the root of
  the working tree, so this is the pushing worktree's own path. A push from the developer's own
  checkout is not Flywheel's business, and gating it would be the same class of product-breaking
  overreach as round ten. Use a `case`/pattern test against the root followed by a slash, so a
  sibling directory sharing a name prefix does not match.
- **Read git's own stdin protocol:** a `while read` loop over four whitespace-separated fields per
  line — local ref, local object name, remote ref, remote object name.
- **Branch deletion:** the local object name is all zeroes. Test it with a `case` pattern for "contains
  a character other than zero", so the check works for both 40-hex and 64-hex object-name formats
  rather than hardcoding a 40-zero literal. Category `branch-deletion`.
- **New branch:** the REMOTE object name is all zeroes and the local one is not — nothing is being
  overwritten. Not destructive; continue to the next line.
- **Force-push / history rewrite:** run the baked git binary as `merge-base --is-ancestor <remote object name> <local object name>`. A non-zero exit means the new tip does not descend from what the remote holds, so the push would discard remote commits. Category `force-push`. If the baked git binary is not executable, the ancestry question cannot be answered: treat the push as destructive with category `force-push` and say so in the refusal text. Fail closed — an unanswerable question is never an allow (D-60).
- **On a destructive verdict:** write one line to stderr naming Flywheel, the category, the refs
  involved, and that the push was refused because there is no supervisor to ask; then exit 1. Exiting
  non-zero aborts the push before any data reaches the remote. Leave a comment stating that plan 12-04
  adds the human-in-the-loop branch here, and that this refusal remains the behaviour for the case
  where nothing can be asked.
- **Every line non-destructive:** exit 0.
