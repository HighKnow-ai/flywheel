<objective>
**As a** developer who has never seen the planner declare a file-set against a real backend,
**I want to** hand the planning run a real listing of the repository, let it say `undeclared` when
it cannot decide, and have a re-runnable harness that proves whether it worked,
**so that** the hand-typed path field can stop being the path of record on evidence rather than on
hope.

PLAN-01 has been unmet since Phase 9 for one reason: the code path was proven against a fake
backend and never run live. This plan builds the two things that must exist before a credential is
spent — the instrument that makes a live run provable, and the prompt that gives the model something
real to answer. The burn itself is plan 15-04, in the next wave: you cannot run a live measurement
before its harness exists, which is the instrument dependency 15-CONTEXT.md names.

Purpose: close the `--live` gap SUMMARY.md § "Confidence and gaps" records, and make `undeclared`
a first-class answer so the model never invents a set to fill a form.
Output: a guarded live-chain corpus, a planning prompt carrying a real file listing, an `undeclared`
submission field, and `uat-14-planner-file-set.mjs` with its offline arms.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model `submit_plan` call → `store_submitted_plan` | model-authored path strings and the new `undeclared` flag cross into the database here |
| repository working tree → `render_planning_prompt` | `git ls-files` output is untrusted-length text embedded in a prompt |
| harness scratch root → developer's machine | a failed PATH substitution would reach real credentials and real repositories |

## STRIDE Threat Register

| T-15-07 | Denial of service | an unbounded `git ls-files` listing in the prompt | medium | mitigate | The listing is bounded by one declared const with a stated-count notice when it truncates; the bound is a fixed count, never a byte or token ceiling (D-69) |
| T-15-08 | Information disclosure | a listing including gitignored build output or secrets | high | mitigate | `git ls-files` lists tracked files only; `std::fs` recursion is explicitly not used, and the verify greps the Cargo manifests to prove no libgit2 blob walk was added |
