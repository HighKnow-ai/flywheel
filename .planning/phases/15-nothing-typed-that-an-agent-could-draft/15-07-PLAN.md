<objective>
**As a** developer who does not want to adjudicate thirty-six fields for a six-task epic,
**I want to** see an agent's suggested title, body and priority already in the form, marked as
suggestions, and have starting the work confirm them,
**so that** the fields an agent does not execute against stop costing me a decision each.

The two tiers are the whole design. "No form a human fills that an agent could have drafted" does
not mean "every field becomes an approval". The things an agent *executes against* — criteria and
file-sets — are explicit; everything else lands and confirms itself when you start the work. The
chore/assist line in PITFALLS is drawn exactly there.

Purpose: implement D-01 through D-05 and D-07 without a schema change, a second writer or a parallel
UI — and keep the two tiers unblurred, because that separation is what lets the next plan's
no-bulk-accept gate stay narrow and need no exemption.
Output: a derived provisional read, ghosting inside the one item form, and a confirm folded into
Start Work.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staged provisional value → canonical `tasks`/`epics` row | an agent-authored title, body or priority becomes board state here, triggered by a human's Start Work |
| the ghost in the item form → the developer's reading | a ghost that looks like committed state would misrepresent what the board holds |
| `confirm_provisional_values_for_task` → the no-bulk-accept gate | a confirm that reached explicit-tier fields would be a bulk accept wearing another name |
