<objective>
**As a** developer whose board is proof of what a bulk path costs — zero criteria on every task with
a worktree, 15 criteria across 907 tasks —
**I want to** have no control anywhere that accepts a set of drafts wholesale, and a test that fails
the build if one is ever added back,
**so that** the unit of acceptance stays the field for a scalar and the item for a structure, by
construction rather than by discipline.

D-95 of Phase 5 introduced `accept_subtree` as "the ONE bulk path this module offers", reasoning
that a root above the task level is a tray-wide accept-all wearing a different name. A-10 keeps that
reasoning and extends it one level further down: the task level is also a set. So the path is
deleted, not exempted — and `subtree` becomes a forbidden word in the surfaces that named it.

Purpose: close DRFT-07's "no bulk-accept control, label, handler or identifier exists anywhere in
the product — asserted by the source test extended to every new draft surface", and install A-11's
no-backfill gate.
Output: one verb and its whole blast radius removed, and three two-sided source gates in its place.
</objective>
