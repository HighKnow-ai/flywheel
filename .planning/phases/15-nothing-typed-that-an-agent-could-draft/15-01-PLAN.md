<objective>
**As a** developer whose board carries 15 acceptance criteria across 907 tasks,
**I want to** have a criterion drafted for a task I typed by hand months ago, with the slop
filtered out before it reaches me and a hard ceiling on how much drafted work can pile up,
**so that** encoding a task's contract stops being work I do and starts being work I approve.

This is the phase's tracer. It proves the one architectural property every later plan builds on:
the lint and the project cap live INSIDE `create_proposal_in_tx`, before its INSERT, so "a failing
draft is never persisted" and "the cap is real, not advisory" are facts a database read can
establish — for every caller at once. D-23 is rated **costly** for exactly this reason: moving the
lint later means re-proving the no-bypass property across every caller, so it is proven first, on
this agent's best early-context tokens.

Purpose: close F3 (criteria cannot be drafted for an existing hand-made task), install the
deterministic pre-filter PITFALLS prevention 3 asks for, and install the attention budget
prevention 2 asks for — all at one statement site.
Output: a new `criterion_lint` module, three new refusal paths through the existing staging
contract, and three integration tests that read the database rather than a return value.

**Tracer-first note (TRACER_MODE):** Task 1 is the `type="tracer"` slice — ONE path, one entry
point, wired from a drafting call through the lint, through the INSERT, through accept, onto a
pre-existing hand-made task, with a real end-to-end `<automated>` verify. Tasks 2 and 3 expand
outward from that proven slice at the same statement site. Plans 15-02 and 15-03 run in the same
wave but are NOT expansion of this tracer: they touch disjoint files, build measurement
instruments, and prove nothing about this architecture — so they cannot be built on an unproven
slice. That is how TRACER_MODE and the hard ordering constraint ("the live planner measurement and
the deliberate limit burn are scheduled early and in parallel") are satisfied together.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent tool call → `create_proposal_in_tx` | model-authored statement text crosses into the database here |
| sidecar stdout → `apply_proposal_created` | a `proposal_created` event's `runId` and content are as trusted as any other value crossing the process boundary |
| human accept → `materialise_proposal` | the only place staged text becomes a canonical `acceptance_criteria` row |
