**Phase goal (ROADMAP, verbatim):** Cyril can answer "where does this task actually stand in git

ninth.

<decisions_resolved>
Two of RESEARCH.md's three open questions, plus three discretion items, are closed here so no
later plan rediscovers them.

- **Where the fetch age lives — no new column, no new table.** `git` already records it: the mtime
  of the path `git rev-parse --git-path FETCH_HEAD` resolves to. Reading it is D-75/D-128's
  "derive at read time, never cache a verdict" applied literally, it survives an application
  restart for free, and it cannot disagree with git about git. A missing `FETCH_HEAD` reads as
  `None` ("never fetched"), never as "just fetched".
- **Where the scheduler module lives — `packages/desktop/src-tauri`, not `packages/core`.**
  `07-PATTERNS.md` sketches `packages/core/src/scheduler.rs`; `07-RESEARCH.md`'s Architectural
  Responsibility Map says the opposite and is the one that holds, because the job needs both a
  tokio runtime and `app.emit`, and `packages/core` is sync with no `AppHandle`. D-113 fixes the
  *mechanism* (`tokio-cron-scheduler` 0.15, no filesystem watcher) and that mechanism is honored;
  which crate hosts the job is the structure question CONTEXT.md hands to Claude's Discretion.
  The core exposes plain sync functions; the desktop crate schedules them.
- **Interval constants (discretion) — three `pub const`s in `git_facts.rs`, not settings.**
  `HOT_TICK_SECS = 5` (about as long as a person will stare at a card before re-reading it),
  `COLD_TICK_SECS = 60` (D-114's own stated ceiling: "a cold task is permitted to be up to a
  minute stale"), `FETCH_INTERVAL_SECS = 300` (the slowest cadence at which "behind" is still
  useful inside one working session).
- **Three separate scheduler jobs, not one job with internal partitioning (discretion)** — two
  tiers and a fetch read as three registrations of the same primitive; one job carrying a
  partition predicate reads as a scheduler inside a scheduler.
- **The commit window (discretion) — `COMMIT_WINDOW = 20`, rendered with a plain "+N earlier
  commits" count line and no expansion control.** A count line tells the whole truth and is less
  code than paging a list the user can read in full in git.
</decisions_resolved>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → Tauri command surface | `task_id` and the focus task id arrive from the renderer and are never trusted as paths |
| Rust core → `git` subprocess | branch names and ref names are interpolated into a `rev-list` range argument |
| background job → shared SQLite connection | the scheduler locks the same `Mutex<Connection>` every command handler locks |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01-01 | Tampering | `git_facts::git_facts_for_task` → `git::ahead_behind` | medium | mitigate | `target_ref` and `branch` are never renderer-supplied: both are derived inside the core from `branch::epic_integration_branch_name` / `projects.default_branch` / the `worktrees` row. The renderer supplies only `task_id`, which is used solely as a bound SQL parameter. |
| T-07-01-02 | Denial of Service | the hot-tier job vs. the shared `Mutex<Connection>` | medium | mitigate | Each job locks, reads, and drops the lock before any emit (the `handle_inbound_git_lock_exhausted` idiom); no job holds the lock across a subprocess spawn, so a slow `git` call can never block a command handler. |
| T-07-01-03 | Denial of Service | the fetch job against a metered or absent network | low | mitigate | D-116: the fetch runs on its own 300s cadence, skips any project whose `git remote` output is empty, and a failed fetch is an `eprintln!` value that leaves `last_fetch_at` older rather than failing the tick. |
| T-07-01-04 | Information Disclosure | `GitFactsDto.worktreePath` crossing to the renderer | low | accept | The worktree path is already surfaced to the renderer by the shipped `WorktreeSummaryDto`; this plan discloses nothing new. |
| T-07-01-05 | Repudiation | a figure shown without its provenance | medium | mitigate | The ahead/behind figure and its fetch age are rendered by one expression, and a non-resolving target withholds the figure entirely instead of printing a zero. |
| T-07-01-SC | Tampering | `cargo` dependency declaration (`tokio-cron-scheduler`) | low | accept | No new package enters the tree: `Cargo.lock` already pins `tokio-cron-scheduler 0.15.1` via `packages/core`, so this declaration resolves to the already-vendored artifact. `07-RESEARCH.md`'s Package Legitimacy Gate is skipped under its own trigger condition (zero new package-manager dependencies); the acceptance criteria assert the lockfile still resolves exactly one version. |
