<objective>
Close the first `missing:` item of verification Gap 1: **read the work list under the lock, drop the lock, run every forge and fetch subprocess lock-free, then re-acquire a short-lived lock only for the local database write.**

`AppState.db` is one `Mutex<Connection>` that every Tauri command locks as its first statement. `run_forge_tick` (`scheduler.rs:244-308`), `run_fetch_tick` (`scheduler.rs:200-229`), `forge_request_for_task` (`commands/forge.rs:102-145`) and `forge_open_request` (`commands/forge.rs:205-215`) all hold that lock across a `gh`/`glab`/`git fetch` call. Any one of them stalling freezes the whole command surface.

Purpose: make the shape impossible rather than fixing four call sites. The reason all four can hold the lock is that `forge::request_for_branch`, `forge::create_request` and `git_facts::fetch_origin_for_project` each take a `&Connection` *and* spawn a subprocess — so the lock has to be alive while the network call runs. This plan splits resolution from dispatch and removes those three connection-taking forms, so there is no function left that a future caller could hold a lock across.

Output: a connection-free dispatch seam in `forge/mod.rs`, the two scheduler ticks restructured into explicit phases whose network phase takes no connection, and both forge Tauri commands releasing the lock before the subprocess.
</objective>
