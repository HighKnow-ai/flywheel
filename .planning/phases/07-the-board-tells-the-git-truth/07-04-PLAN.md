<decisions_resolved>
- **Storage: two rows in the existing `settings` key/value table, no migration.** Keys
  `open_in_editor_command` and `open_in_terminal_command`. The table already exists and is already
  key/value by design (`0005_credentials.sql` decision 2: "a typed table for two rows would be
  speculative structure"). Defaults are applied on read when the key is absent, exactly as
  `global_credential_mode` already does.
- **The two accessors live in `domain/worktree.rs`, not `domain/settings.rs`.** They read and
  write the shared `settings` table, but the concern is "how a worktree is opened", and
  `domain/settings.rs` is this phase's busiest file (plan 07-03 adds the forge override there in
  the same wave). Keeping these two functions beside `resolve_open_argv` — the only code that
  consumes them — puts the whole open-a-worktree surface in one file and leaves the two Wave-2
  plans with zero file overlap. Their doc comments name `domain/settings.rs`'s
  `global_credential_mode` as the read-with-default idiom they follow.
- **Defaults (D-130): `code {worktree_path}` for the editor, `open -a Terminal
  {worktree_path}` for the terminal.** `code` is confirmed on this machine's `PATH`; `open -a
  Terminal` is the macOS system terminal and this is a macOS-only v1 (phase 11 is the macOS
  build). The template is editable, so the default being wrong on another platform is a settings
  change, not a defect.
- **Substitution token: the literal `{worktree_path}`.** Chosen over a bare `{path}` because the
  substituted value is specifically the worktree's own absolute path and the token appears in a
  user-editable string where a vaguer name invites misreading. A template with no token appends
  the path as a final argv element, so `code` alone still works.
- **Execution: argv, never a shell.** The template is split on ASCII whitespace into argv; the
  first element is the program, the rest are arguments; the token is replaced **within a single
  element**, so a path containing spaces stays one argument. Nothing is ever handed to `sh -c`.
  This is the whole mitigation for T-07-04-01, and the test asserts it by using a path with a
  space and a semicolon in it.
- **Reveal-in-Finder is not built.** It was explicitly rejected in D-130 and its absence
  assertion in the existing test file therefore stays exactly as it is — only the editor and
  terminal assertions invert.
</decisions_resolved>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → `worktree_open` | the renderer supplies a task id and one of two enum surfaces, nothing else |
| stored template → a spawned process | a user-editable string becomes a program name and arguments |
| worktree path → an argv element | a filesystem path, possibly containing spaces or shell metacharacters |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-04-01 | Elevation of Privilege | the stored template reaching a process | high | mitigate | The template is split on whitespace into argv and spawned with `Command::new(argv[0]).args(&argv[1..])`. It is never joined into a command line and never passed to `sh -c`, so no metacharacter in the template or in the worktree path can start a second command. Asserted by a core test using a path containing a space and a semicolon, and by greps in both the core module and the command module. |
| T-07-04-02 | Tampering | the renderer choosing which program runs | high | mitigate | The command's parameters are `task_id: String` and `surface: OpenSurface`. No program name, argument or path crosses the IPC boundary; the argv is resolved entirely inside `packages/core` from a stored setting and the task's own `worktrees` row. |
| T-07-04-03 | Tampering | the worktree path reaching `.current_dir` | medium | mitigate | The path comes from the `worktrees` row this application wrote, never from the renderer, and is passed as a parameter literally named `worktree_path` so `supervisor_cwd.rs`'s absolute-path source gate holds by name as well as in fact. |
| T-07-04-04 | Denial of Service | a spawned editor blocking the supervisor | medium | mitigate | The spawn is detached — the command does not wait on the child — and the database lock is dropped before the spawn, so a slow or hanging editor can neither block a command handler nor hold the connection. |
| T-07-04-05 | Information Disclosure | the spawn error text crossing to the renderer | low | mitigate | A `NotFound` spawn error reports the program name from the user's own template; no other spawn error text includes the resolved worktree path beyond what `WorktreeSummaryDto` already surfaces. |
| T-07-04-06 | Repudiation | a template change with no audit record | low | mitigate | `set_open_command_template` writes `updated_by`/`updated_at` on the `settings` row, which is that row's audit record — the reason `0005_credentials.sql` already records for global-scope settings. |

**Canon referral:** command-injection hardening is canon — owned by `/gsd-secure-phase` — and the
bespoke, product-specific half is minted above as the plan's prohibition plus T-07-04-01.
