  <decision>
Criterion 2 says the cycle table "has no parent". Every other canonical table in this schema carries
`project_id TEXT NOT NULL REFERENCES projects(id)` and `created_by TEXT NOT NULL REFERENCES
actors(id)`. D-05 needs `project_id` as a column regardless, because the one-active-per-project
partial unique index is keyed on it. So the open question is only whether those two columns carry
their `REFERENCES` clauses — and that single choice decides whether criterion 2's assertion can be
written as literally as it is worded.
  </decision>
  <context>
Undo cost: either answer is a table rebuild once rows exist, and migrations here have no
down-migration. The assertion written into `spine_pin.rs` in Task 2 is shaped by this answer and a
later reversal invalidates it.
  </context>
  <options>
    - **A — No REFERENCES clause on the cycle table.** `project_id TEXT NOT NULL` and `created_by TEXT NOT NULL`, both unconstrained. `pragma_foreign_key_list('cycles')` returns zero rows, so criterion 2's "the cycle table has no parent" is asserted exactly as written, and the chain above `epics` provably terminates. Cost: referential integrity to `projects` and `actors` is enforced only by `domain::cycle`'s writers, which is weaker than every sibling table and is the one place this schema would stop being self-describing.
    - **B — The house REFERENCES clauses, and criterion 2 read as a spine statement.** `project_id TEXT NOT NULL REFERENCES projects(id)`, `created_by TEXT NOT NULL REFERENCES actors(id)`. Database-enforced integrity, consistent with every canonical table. Criterion 2 is then asserted as: the cycle table has no parent **in the board spine** (its only parents are `projects` and `actors`, both infrastructure, neither a work-item layer), and no table other than `epics` references it — so nothing sits above a Cycle. Cost: the literal words "has no parent" become a reading rather than a `pragma` result, and that reading must be recorded in the test's doc comment.
    - **C — Split the difference: `project_id` constrained, `created_by` not.** Rejected on sight: a half-constrained table is harder to explain than either whole, and it satisfies neither reading of criterion 2 cleanly.
  </options>
  <recommendation>
**B.** Option A buys a literal `pragma` result by making one table the only unconstrained one in the
schema, which is a worse lie than the reading it avoids — `projects` and `actors` are
`TableClass::Infrastructure`, not layers of work, so "nothing is above a Cycle" is already true with
them present. The decisive half of criterion 2 is "no other table references it", and that half is
identical under either option. If the owner wants A, Task 2's assertion gets simpler, not harder.
  </recommendation>
