  <behavior>
    - An epic whose tasks are all `backlog` derives `backlog`.
    - An epic with at least one `todo` task and no further progress derives `todo`.
    - An epic with at least one `in_progress` task derives `in_progress`, whatever else its other tasks are.
    - An epic whose every task is `in_review` or `done`, with at least one `in_review`, derives `in_review`.
    - An epic whose every task is `done` derives `done`.
    - An epic with NO tasks is left exactly where it is: zero tasks is not "all tasks done", and the deriver must not promote it.
    - An epic already at `done` whose task is then moved back to `in_progress` stays `done`: the floor is one comparison over `BAND_ORDER` and `done` is terminal as a consequence of it.
    - An epic a human deliberately lowered is not raised back by the deriver on the next run unless its tasks' own candidate is now higher — the floor compares against the value the human set.
    - Deriving an epic whose status does not change appends no event and writes no row, so a tick over an unchanged board is silent.
    - Two consecutive derivations over unchanged tasks leave the epic's status equal — the deriver is idempotent, like the task deriver.
