<objective>
Add the dimension that fixes the measured cost this phase opened on: finding the one reviewable task
in a 907-row board took a hand-written SQL join plus a `git merge-tree` sweep, because the UI could
not ask the question.

Implements **D-17** (a sixth filter dimension for items that have an active worktree, as pure SQL
inside the core's single filtering query, because D-03's "no second filtering implementation" holds;
commits-ahead and dirty *cannot* be filter dimensions — they are git facts with no database column —
and stay annotation only).

One structural question comes with it and is gated under **D-03** rather than decided here: epic rows
have no worktree of their own, so the dimension must define them. `08.1-RESEARCH.md` A9 recommends
that an epic matches when any child task has an active worktree, and flags it as the owner's call —
the alternative readings are that epics are hidden when the chip is on, or always shown. Guessing
wrong loses the roster's headers the moment the chip is used, so it is asked.

Probe fallback: skipped — this phase has no REQ-IDs to probe (visible skip). `must_haves` derive
from SC0–SC4, the CONTEXT decisions and `08.1-VALIDATION.md`'s requirement-to-test map.

Purpose: make the board able to answer "which of these has real work behind it" without a SQL client.
Output: one new filter dimension end to end, one recorded amendment, and a test that fails if any
bind site was missed.
</objective>
