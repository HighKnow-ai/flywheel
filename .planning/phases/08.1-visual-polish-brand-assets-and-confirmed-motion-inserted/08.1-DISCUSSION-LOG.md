## Home surface — raised mid-session by the owner

Not an area Claude proposed. The owner interrupted after three list-shaped visual directions were
offered:

> *"I feel like none of the suggestions are showing progress and roadmap, which is kind of the
> right mix I'm looking for. I want the Jira of AI agents, such that it auto-populates, and helps
> feature design automatically challenged by agents… modern but professional… sleek, while having
> impeccable UX standards for retrieving information."*

A reference image was supplied: a dark GitHub/Vercel-style analytics surface with a grouped left
nav, compare rows built as label + muted sub-label + bar + value + delta, colour used only as a
data channel, and a plain-language "What this says" block under the data.

The three rejected visual directions (recorded for the audit trail): **Instrument Panel** — the
reference applied literally, near-black single surface family, colour as data only; **Ledger** —
GitHub proper, light-first, bordered content columns, status as outlined pills; **Console** —
Linear/Vercel, dark with elevation and blur, motion as the signature. All three were lists of
tasks; none showed progress or roadmap, which was the miss.

| Option | Description | Selected |
|--------|-------------|----------|
| Mission Control — epic roster leads | Epics are the roadmap; progress, agent activity, challenges; expand for tasks | ✓ |
| Two-pane — roadmap spine + work rack | Persistent epic roster drives the existing task rack | |
| Needs-You first — the loop leads | Ranked queue of what only the owner can unblock; roadmap second | |

**User's choice:** Mission Control.
**Notes:** Recommended option. Everything it shows is derivable from existing tables — no schema
change. Dates, milestones, Gantt and epic dependencies were explicitly excluded as needing new
data, and recorded as deferred.

| Option | Description | Selected |
|--------|-------------|----------|

| Two bars — work done and work proven | Makes the shipped-vs-proven gap the point | |

**User's choice:** Tasks done/total, criteria as a finer second number.
**Notes:** The database holds four `acceptance_criteria` rows across a 907-task board, so the

## Deferred Ideas

- Agent-written interpretive summary (the slot the computed line creates is the seam).
- Timeline/Gantt roadmap reading — needs dates and epic dependencies the schema lacks.
- Planned-vs-actual and velocity — banned by D-12's "aggregated nowhere" rule for estimates.
- A "Needs You" ranked queue as the home surface — considered, not chosen.
- Sorting or filtering by `ahead`/`dirty` — impossible as SQL without a materialized column.
- Project-rail overflow beyond nine projects (`01-UI-SPEC.md` Open Decision #10).
- Collaborative rich-text editing of descriptions (Yjs/Automerge on single fields).

## Scope creep redirected

Mission Control's roadmap reading was accepted because every signal on it derives from existing
tables. The genuinely new-capability ideas it attracts — dates, milestones, Gantt, epic-to-epic
dependencies, planned-vs-actual — were separated out and deferred rather than absorbed.
