<objective>
Rebuild the rack's row model: four row kinds instead of one, a grouping key instead of a fixed
status grouping, and rows keyed by identity instead of by index.

Implements **D-13** (two fixed row heights — in practice four, by row kind — not measured
virtualization; the size function becomes a lookup and the Performance Contract survives the move to
a nested model, which CONTEXT tells the planner to keep that way) and **D-07** (the status-band rack
becomes a lens, not a second surface: one board, one virtualized rack, one keyboard map, one query,
with a grouping toggle switching the key between epic and status). It builds the row-model half of
**D-05**; the epic row's own content is plan 11.

Both are gated: this plan may only build what amendments A-02 and A-03 approved. Read
`08.1-AMENDMENTS.md` first and build exactly what is recorded there — if either was declined, stop
and report rather than building the proposal.

**Promote, do not add alongside.** The single shared row-height constant becomes a lookup keyed by
row kind, and the board's volume fixture imports it rather than re-declaring it. That fixture
currently mirrors the row height, the overscan, the band-header count and the quick-add row count as
its own literals, and one of its tests is deliberately designed to fail when its margin disappears —
so four heights change every one of those assumptions at once. Importing the lookup is what stops the
next height change from silently invalidating a test that still passes.

**The keying change is deliberate and has a known blast radius.** The virtualizer keys rows by index
today, so collapsing a group leaves each element in place and swaps its content: nothing moves, and
the existing displacement transition never fires. Keying by item id makes a row keep its DOM node, so
rows below a collapse actually slide. It also changes which node holds focus and selection across a
collapse, which is why the keyboard, layer-guard and quick-add-focus tests are re-run here rather
than later.

Probe fallback: skipped — this phase has no REQ-IDs to probe (visible skip). `must_haves` derive
from SC0–SC4, the CONTEXT decisions and `08.1-VALIDATION.md`'s requirement-to-test map.

Purpose: the structural rack the roster, the challenges and the collapse animation all need.
Output: four row kinds, one lookup, one grouping key, stable row keys, and three pre-existing test
files re-proven.
</objective>
