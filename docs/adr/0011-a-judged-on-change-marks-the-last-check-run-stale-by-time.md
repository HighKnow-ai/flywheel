# A judged-on change marks the last Check run stale by time, and keeps the run

Decided in [Judged-on changes: Amend criterion and Amend Epic spec are their own Needs-you items](https://github.com/HighKnow-ai/flywheel/issues/163). Spec §4.4 says an accepted criterion-changing Proposal "marks the last run stale". Before this, a result was stale only when the branch had moved past the commit it ran on, and that was worked out on read. Nothing was stored. Accepting an Amend criterion that keeps its Check now writes `checks.stale_since` (migration 0013) in the deciding transaction (ADR-0007). `CurrentResult::is_stale` is true when the branch has moved, or when the run started before `stale_since`. The run itself is kept, and so is its result. A run that starts after the change is current again, with no flag to clear. An Amend criterion that carries a Check command different from the Check's own replaces the Check through `set_check_in_tx`. As with any edit, that resets the result to not run. A command equal to the Check's own counts as no new command, so the run is marked stale.

We rejected deleting the last run. Runs are the record of what Flywheel ran against which commit, and the review card and the packet still show what the stale run said. We rejected a per-run boolean (`check_runs.stale`). It would need a write on every past run and a rule for when to clear it. One timestamp on the Check orders correctly against every run, past and future. We also rejected touching `checks.updated_at`, which would have read as an edit: the result would show not run and hide what the last run said.

## Consequences

- Everything that asks whether a Check passed at the current head goes through `is_stale`: Merge's "every Check passed" rule, the review card, `criterion_list` and the Context packet. So an accepted change holds Merge until the Checks run again or Cyril merges with the override. That holds even while the Story is In review, which #163 allows. The packet says why the result is stale: the branch moved, or the criterion changed.
- An Amend criterion is refused once its Story is closed (Merged or Dropped). The refusal rolls the decision back, and the Proposal stays pending until Cyril rejects it.
- What counts as judged-on is defined once, as `proposal_apply::is_judged_on` and the `query::judged_on_proposal!` SQL predicate: any amend to a criterion, and an amend to an Epic's spec that a Story session filed. A shaping session's spec change is decided in its Round. The Proposals row (#162) leaves judged-on Proposals out by the same predicate.
